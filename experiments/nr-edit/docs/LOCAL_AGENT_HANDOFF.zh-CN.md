## 本地 Agent 的固定操作

1. 等维护者的 D20 自身工作已有明确、干净的检查点。检查 `git status --short`；不要替维护者提交所有改动，也不要 stash、reset、覆盖或切走正在开发的工作树。可以由维护者指定一个独立集成工作树。
2. 在这个已完成的目标分支，cherry-pick 云端交付的 **单个新增目录提交**。不需要合并云端整条分支，也不要 cherry-pick 旧 #257／#258／#259 的历史实验提交。
3. 从目标仓库根目录执行：

```powershell
.\experiments\nr-edit\Build-Against.ps1
```

它会依次运行目标版本自己的产品生成链、检查式接入、真实 shader 编译、中英文 addon 构建、生命周期测试和 WARP 测试。结果保存在新目录，并打印路径。不会替换原工作树、游戏安装、现用 INI、已发布包或原模型依赖。

另一种更保守的试用方式：直接调用云端独立工作树里的这个脚本，加 `-CoreRoot <D20已完成工作树>`。这样连 cherry-pick 都不必先做，也能生成独立候选。

首次构建沿用原项目的大型 codec 变体，个别 shader 编译较慢。不要因为没有逐行输出就反复终止和重启。`logs/product-build.log` 是本次构建日志；最终以 `validation.json` 为准。可以用 `-CodecCacheRoot <以前的完整build目录>` 加速，但缓存必须通过原项目的源码／编译器／参数核对。

## 遇到错误时只做定位，不自行改算法

| 首个失败 | 应做什么 | 不要做什么 |
|---|---|---|
| 目标工作树 dirty | 回报维护者，改用已提交的独立工作树 | 自动 stash/reset/提交全部文件 |
| source anchor changed／ambiguous | 提交明确函数名、当前函数片段和目标 SHA；现有输出不会被覆盖 | 删检查，强行套 D16 的整文件 |
| 产品原生成链／源码 pin 失败 | 先确认 D20 自身能正常生成；用它原来的生成器 | 把旧 pin 改成任意值骗过检查 |
| shader／C++ 编译失败 | 只提供第一个实际错误及对应日志、目标和实验 SHA | 换假头文件，关闭 Werror 来称已验证 |
| WARP 像素、布局、退休失败 | 停止出玩家包，提供该测试结果 | 把跳过算成功或删掉测试 |
| 游戏 UI 显示 declined／warmup | 由维护者在固定场景做 F6 对照，收一次当前 F8＋实际加载身份 | 强制 source、queue、projection、history 标志 |

Windows SDK、真实 shader 和完整 D19 Core 已验证过；不是要求你重新实现工厂、Hooks、私有 E_R 或提交回调。但未来 D20 的接口变化可能仍需调整，必须定位到实际变化，不能承诺不存在任何冲突。

## 维护者游戏验证

先用一个当前 NRSR／SRNR 已工作的 D3D12 游戏，FG／MFG 关闭，固定 R/O、NR1/NR2 模型和实际工作尺寸。先测默认关闭的回归，再分别开 Deferred B、RR 编辑层。

观察顺序：私有 E_R 成功 → 私有 SR 创建／运行或 RR 编辑准备 → 同帧合成 → 真实提交 → 画面变化。录制计数不等于 GPU 或画面通过；完成计数还需要记录引用可退休。

同条件比较 A、B、完整 C 和相同 N1/N2 的低分 C。记录整帧 P95/P99、显存、移动／遮挡／反射／人物，不只看 NR 计时。重复 F6、模式开关、相机切换、分辨率重建与退出属于游戏验收。前置噪声输入和低分输入不等同于完整后置画面，不承诺完全无画质代价。

RR 的时域开关只是请求。非零／未知采样相位、缺失可靠投影或断裂的运动参考会显示空间编辑层或冷启动。不得用单位相机矩阵冒充真实数据来点亮“历史已启用”。
