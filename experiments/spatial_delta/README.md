# Spatial signed-delta experiment (CPU only)

This directory contains two self-contained Python standard-library scripts. `spatial_delta.py` is the one frozen candidate: signed `Δ=Z−B` and B are area-averaged on the product's floor work grid, then four half-pixel taps weight Δ by the existing `ColourLabGuideWeight(B_output, BN_tap)`. Invalid data returns Z, exact B=Z returns B, the target region and alpha contracts are preserved. There is no new sharpening, temporal path, carrier, or output high-frequency recovery. Every source, area, guide and reconstruction add/subtract/multiply/divide rounds to IEEE binary32 with `ctypes.c_float`; FP16 captured inputs are read exactly. The fixture is generated deterministically, then its B, clean truth and noisy Z inputs are rounded to binary32. **Metric reductions use Python binary64 over the resulting binary32 pixels**, so they are not a GPU storage or instruction-order parity claim.

`stage1_pair.py` is a separate fixed synthetic P/N **CPU sampling-equation** comparison of off bilinear, guided four-tap balanced, guided 16-tap fine, and legacy edge's four-tap pair. It does not run the production compositor, colour/guard policy or GPU; its P/N are not Feature18 outputs. The existing `tests/reconstruction_gpu.cpp` provides production shader WARP tests with controlled P/N for off/balanced/fine, but an exact four-mode same-P/N WARP result and real Feature18 P/N capture have not been produced by these scripts.

From this directory:

```powershell
python .\spatial_delta.py --capture '<private-capture-directory>' --output '<fresh-output-directory>/result.json'
python .\stage1_pair.py --output '<fresh-output-directory>/stage1-pair-result.json'
```

The optional capture is the archived 16-frame Beta 7 real Feature1 input. Frame 0 contains same-source B/Z and captured FP16 carrier + FP32 N-tail. The `carrier_identity_bilinear_decode` branch applies bilinear ordinary recovery, the production support/zero/tail decode contract, and an **approximate** FP16 intermediate round; it is a CPU identity oracle, not a new GPU capture or GPU half-store bit-parity proof. The archived `final` plane is the separate actual Beta 7 Feature1 result. The captured path has no clean truth or real Feature18 P/N, and its MAE against Z is an attribution distance, not a quality score.

The frozen threshold result remains negative. The dark/text/hair clean-truth fixture's guided candidate reduces noisy-Z RGB error RMS by 55.27% and retains 98.45% of true total edit magnitude, but retains only 58.85% of ordinary Z's **NR edit-signal integral on thin-line pixels**; the required gate is 98%. Its edit-specific hair contrast exceeds half of the clean hair-specific edit at 1/47 pixels, longest run 1, versus noisy Z's 39/47, longest run 10. These are signed `output−B` edit metrics, **not final-image visible line brightness or a claim of a one-pixel visible break**. B already has a one-pixel bright hair line. The independent original-pixel visual review at `independent-image-review.md` (private evidence) found the visible arc continuous and candidate background cleaner than noisy Z in the synthetic crop, while real-frame Z and candidate looked similar. Both statements can hold: the displayed PNGs use ×8 exposure and 8-bit quantization, which can hide small edit-amplitude differences over B. The disagreement is retained; no gate or algorithm was changed.

Near-zero is separate: one synthetic pixel has input signed RGB edit `[+1.0430813e−7, −1.0430813e−7, +1.0430813e−7]` and recovered `[+1.4901161e−8, −1.4901161e−8, +1.4901161e−8]`, 14.29% absolute retention; 12,512 exactly zero-edit pixels remain exact. Odd-grid, HDR, invalid fallback, alpha and region exterior checks are in `result.json`. This micro test is a diagnostic, not a separate pass gate.

`result.json` (private evidence) and its original scripts remain the immutable r1 binary64 record. The corrected binary32 result is under `fp32-r2`. All nine r2 PNG crop hashes match the previously reviewed r1 PNG byte-for-byte; the new `carrier-identity` crop has no prior review. The frozen candidate is rejected and must not be added to the product from these results.
