# AMD/NVIDIA optical-flow input for the external Feeder

This experiment is connected to the D3D12 `NRExternalProviderV1` path. The
production shape is the patched official Feeder generated by
`scripts/patch-feeder-external-nr.py`: one Feeder owns the frame, captures the
same Color and Depth snapshot, replaces its normal motion input with optical
flow, and performs one Core submit. `addon.cpp` remains a development host and
must not be installed beside the integrated Feeder.

The ReShade Feeder panel owns the three settings and persists them in
`dlss5-feed.cfg`:

- `of_enabled=0` by default;
- `of_backend=1` for AMD FidelityFX OF, or `2` for NVIDIA Optical Flow;
- `of_scale=100` by default, with explicit `50` as the only other choice.

Changing backend or scale retires the existing session through its declared GPU
fences before creating another. While the selected path is busy, unavailable,
or rejected, the original frame is retained and the normal motion provider is
not submitted as a second owner. Accepted temporal history advances only after
the exact completion fence for a recorded Core writeback.

`backend.cpp/.hpp` call the official FidelityFX or NVOF APIs on a private queue
of the same D3D12 device. The Feeder first executes the immutable Color/Depth
capture on its queue. The OF queue waits for that exact capture fence, generates
source-pixel motion at 100% or 50%, then sends Color, Depth, generated Motion and
the Feeder output through V1. The Feeder queue waits for the returned exact Core
completion before its existing copy-home operation can read the output.

The current built variants define `NR_OF_ENABLE_NVOF=0`. They statically link
official FidelityFX SDK 1.1.4 optical-flow and DX12 backend libraries, so no AMD
runtime DLL is required; the FidelityFX license must accompany distribution.
The NVIDIA backend source is present, but the official
`NvOFInterface/nvOpticalFlowD3D12.h` SDK input was not available without the
NVIDIA Developer Program download. Selecting NVIDIA in an AMD-only binary is
shown as unavailable in the Feeder panel and leaves the frame unchanged. No
mirrored header, fake library, or fallback backend is substituted.

The first integrated format boundary is x64, same-device D3D12, same-size
`R8G8B8A8_UNORM` Color/Output and `R32_FLOAT` Depth. HDR/PQ and the existing
Vulkan/DX9/x86 transports continue through their own routes. Optical-flow
transport for those APIs requires a separate port of this same-owner adapter;
the standalone development addon is not that port.

The sources include explicit odd-size 50% geometry, AMD scene-cut reset input,
NVOF grid conversion, failure quarantine, and 100/50 policy code. This delivery
was compiled with the official AMD SDK. Per the current acceptance instruction,
no new game, GPU, performance, or visual-quality validation was run.
