# Manager 0.4.6-hotfix.4 性能修复

对应本仓库 #180。反馈没有具体版本或现场采样，因此本次证明的是当前源码中
可复现的性能问题和修复效果，不将其视为所有客人卡死问题的唯一根因。

## 组件读取

原 compact payload 检查按“版本 × 显卡族”重复读取共享 Runtime；单次完整检查
读取 1,383,006,264 字节，启动中的两次检查合计约 2.58 GiB。相同文件现在每次
完整检查只读取一次，展示路径复用有界缓存；缓存检查清单和文件大小、修改时间、
变更时间、文件身份，缺失、损坏和失败不缓存。安装与写入前仍完整校验。

同一实际 payload 的集成测量（游戏发现及 GPU 用隔离适配器，不执行游戏）：

| 场景 | 组件内容读取量 |
|---|---:|
| 原启动的两次检查 | 2,766,012,528 字节 |
| 修复后首次启动 | 348,648,364 字节，减少约 87% |
| 文件未变更时再次展示 | 0 字节，仅查询文件元数据 |
| 展示用 FG ReShade 来源查询 | 0 字节，仅查询文件元数据 |
| 新的安装前完整校验 | 348,648,364 字节 |

这里是应用层读取量，并非清空操作系统缓存后的物理磁盘测量；不是整体启动时间
或所有电脑的提速承诺。

## 扫描、界面和反馈

- 游戏发现、PE 解析和手动选择在单个后台工作线程执行，界面主线程不再执行
  同步整文件标记扫描。相同在途扫描合并，文件变更递增 revision，旧结果不能
  覆盖新状态；线程退出后可重建。不通过增加全盘并发来加重磁盘争用。
- 已保存的游戏目录不再因缺少 DLSS 向父目录扩大；选择 EXE 时仅沿已知二进制
  布局和 Unreal Engine 目录证据推断。保留 Engine/Plugins 的 DLSS 布局支持。
- 同次刷新共享 Steam 封面目录索引，使用 Dirent 判断文件，避免每游戏重复 stat。
  40 游戏夹具只枚举一次共用目录，封面条目的 stat 调用为 0。
- 安装、修复、卸载后只刷新一次，界面读取已更新的快照；刷新失败仍能重试。
  折叠卡片不创建隐藏设置表单；搜索保留当前编辑器，不重复读取组件。
- SR/FG 显卡探测改为异步子进程，并合并在途探测；启动展示复用已探测的显卡。
  成功的只读界面操作不写操作日志；失败和修改操作继续记录。采集大运行日志
  只读取末尾最多 256 KiB，不再先读取整个文件再截断。
- 全部勾选框统一尺寸、圆角和颜色；SR/FG 跳转只滚动游戏区域，保留应用顶栏。

回归覆盖缓存失效/篡改、完整校验不走缓存、线程生命周期和响应、目录上界、
Unreal 目录、修改后状态更新、旧扫描结果以及只读日志抑制。游戏兼容性仍需
逐游戏实测；本轮不修改内置 `0.4.6-hotfix.1 · Beta` 核心。
