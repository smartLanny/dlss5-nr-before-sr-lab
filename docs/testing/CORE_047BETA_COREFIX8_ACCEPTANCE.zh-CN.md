# 0.4.7beta-corefix.8 复测说明

本候选针对描述符复制导致格式记录丢失的问题：复制超过观察器的逐项记录上限时，只将复制目标保留为未知，保留未被触及的格式记录。复制执行期间目标记录不能被使用，旧的并发写入也不能在复制结束后恢复成有效记录。是否恢复持续 NR、是否仍有闪烁，需要游戏复测确认。

## 绝区零：一次后置复测

1. 退出游戏并备份当前 Core，通过已确认的管理器外部运行时部署入口换入同语言 Core。保留 INI、HoYoShade、ReShade、NR 运行库和画质设置，同一进程只加载一个 Core。
2. 进入原来的 3D 场景，选择后置（SR→NR），观察开启 NR 后是否持续生效。
3. 保持场景约 30 秒，只按一次 F8。如果再次出现“不支持的 Output 格式”，就在该状态采集。
4. 返回这一份 F8，并说明是否有持续效果、是否仍闪烁。无需重复前置或四阶段测试。

## 包内容与恢复

包内只有所选语言 Core、配套 `nrchain_nvngx.dll`、许可与构建凭据；不包含设置、模型、NVIDIA 运行库或 carrier。优先只更换 Core，沿用已经确认的管理器部署方式，不通过旧快捷方式启动另一套环境。`build-info.json` 记录冻结源码与本地验证边界。

需要恢复时退出游戏，还原备份的 Core。此前候选、设置与反馈均保留。

## 验证边界

本地 CPU 与 WARP 可以验证格式记录、复制期间的拒绝、当前调用检查和实际纹理读回，不能证明 NVIDIA NR、游戏最终画面或性能已经通过。CPU 格式请求仍不作为 GPU 描述符使用证明。

死亡搁浅的无持续效果和偶发闪烁仍未解决，本轮不部署该游戏，也不要求重复四阶段。
