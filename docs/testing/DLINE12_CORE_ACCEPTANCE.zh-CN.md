# 0.5 D12：修正双次 NR 设备归属与区域颜色提示

本次修复延续 D11 的双层、通用控制、精细分区和人脸实验。
双层处理和对照方法见 [D11 说明](DLINE11_CORE_ACCEPTANCE.zh-CN.md)。

## 维护者反馈与修复

- 双次 NR 显示资源不足：反馈实际停在资源分配前，第二层创建、推理与纹理字节均为 0。
  ReShade 的资源 `GetDevice` 返回设备代理，而空间资源模块只比较原生 COM 身份，
  将同一底层设备误判为不同设备。D12 接入 Core 已有的 ReShade 设备身份证明；
  保留原执行设备、资源与跨设备拒绝。设备、管线、资源格式和预算失败分别显示。
  重复失败日志按原因变化或 60 秒间隔记录，避免占满 F8 的有限反馈容量。
- 区域颜色滑块看似无效：所提供帧的 HDR 输入采用非单位预曝光，现有 HDR 策略
  将实际颜色系数设为 0。分区颜色倍率以该系数为基础，因此无法产生颜色变化。
  D12 在区域旁显示实时原因，将已确认无效的颜色滑块置灰，并提供同一个
  “允许实验 HDR 调色”开关。默认及已保存的许可不变；偏色或闪烁时可关闭。
  全局 AI 色彩强度为 0 时也会提示。等待应用和历史记录不冒充当前限制。
- F8 新增分区开关、版本、预览、11 项倍率及其顺序，并附双次状态图例。
  参数来自采集时冻结的配置；颜色是否获准仍以当前颜色策略记录为准。

## 宽范围与细节的原理

它们按 **NR 相对原图的明暗改动范围** 分类，有类似高低频的直觉，但不是对原图
做固定高低通或 FFT。程序在最长边不超过 640 的分析网格上采样近、中、远邻域，
比较同方向的相对亮度变化，再用原图亮度边缘、可用深度和法线限制跨表面混合。
整面墙一起变亮主要归入宽范围，轮廓附近孤立的增亮主要归入细节，两者是连续权重。
亮暗方向、镜面导引与纯颜色改动另外区分；选区在倍率之前确定，调整倍率不重新分类。
缺少引擎镜面导引时不声称识别到了独立反射层。

## 验证范围

新增真实 ReShade 6.8 隐藏宿主复现：WARP 创建的 64×32 FP16 资源经代理返回设备，
旧身份比较拒绝；Core 身份证明允许 100% 与 50% 路径分配。不同硬件设备资源、
1 字节预算仍拒绝，并使用真实队列完成 fence 释放测试资源。此宿主没有游戏或 NGX 调用。
颜色回归执行实际策略、调度常量和 UI 函数，覆盖反馈中的非单位预曝光、显式开启、
零颜色系数和过期状态；反馈回归检查全部分区倍率的实际序列化。

完整生成构建和回归结果以本包 `validation.json` 为准。WARP 与宿主检查不能替代
NVIDIA 双层真实推理、异环画面和整帧性能验收。安装前退出游戏，只替换经核对的
Core 并在游戏目录外备份旧文件；保留当时的 INI、ReShade、桥接、模型和人脸资源。
