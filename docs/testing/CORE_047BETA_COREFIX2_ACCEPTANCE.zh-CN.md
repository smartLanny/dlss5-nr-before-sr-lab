# 0.4.7beta-corefix.2 测试说明

本包接续 corefix.1，包含实验 jitter 的默认关闭与一次迁移、已提交 GPU 工作的事件等待，以及同场景闪烁和耗时对照。游戏视觉修复与性能收益仍须实际比较，构建及软件 GPU 测试不能代替这些结果。

## 更新和配置

游戏退出后只保留一个对应语言 Core，使用包内配套桥接 DLL。保留当前游戏配置、NR 运行库及其他组件；更新前备份原 Core。

没有 `JitterPolicyVersion=1` 的旧配置会在首次加载时关闭实验 jitter；关闭值保存成功后才写迁移标记。新装和恢复默认也关闭。之后仍可在实验设置中手动开启，并跨重启保留。原生 SR 的 jitter 不受此设置修改；POST 已重建颜色网格使用的零坐标合同保持。

如果配置保存失败，以面板中的失败说明为准；不会把失败写入当作完成迁移。此次不统一重置强度、路线、工作比例或预热次数。

## 死亡搁浅与 2077 闪烁对照

1. 保持当前能复现的路线、分辨率、强度和同一场景；等待设置及预热稳定。
2. 在“反馈与诊断 → 闪烁对照”选择“正常采样”，关闭菜单，观察约 30 秒，再按 F8 保存文字反馈。
3. 只将该选项改为“暂停采样”，关闭菜单，在同一场景观察约 30 秒，再按 F8。记录画面是否仍闪、是否持续有增强效果。
4. 死亡搁浅分别关注静止／照片模式和移动；2077 普通 SR 与 RR 的结果分开记录。F8 中请求 RR 不等于真实 RR 正在运行。

此开关仅在当前进程有效，不保存到 INI，不关闭 NR，也不触发模型历史重置。暂停时不再新增自动 GPU 样本，包含恢复探针；已提交的读回仍按原规则完成，其原阶段编号保留。暂停不会禁止显式图像采集，因此本轮两段比较期间不按 F7，避免另一次采集改变负载。F8 仍可使用。

F8 的当前对照阶段与存储样本阶段须相同才可作为同阶段样本；旧阶段读回可以退休，但不能冒充新阶段证据。处理／提交计数或顶部活动文字不代表最终画面已经正确。

## 卡顿和输入响应

在相同配置、同一场景下，比较事件等待与旧轮询各三段 30 秒。每段开始新的计时阶段，关闭菜单观察，结束保存 F8。只切换等待方式，不同时切 jitter、采样、画质、帧生成或限帧设置。

比较帧时间、各 CPU 阶段的尾部耗时、最长等待和 NR 覆盖率。Core 的 CPU 耗时不等于 GPU 推理耗时或完整输入到显示延迟；后者必须同时核对真实操作的画面响应。更高平均 FPS 或少执行 NR 不能单独算优化通过。

F8 的耗时为当前计时段累计 CPU 观察；嵌套阶段不可相加，p95/p99 是直方图区间，最近调用列表有数量上限。混合路线／配置或缺少时钟时会明确标记，不能作为干净的性能对照。源码中的 `scripts/summarize-runtime-timing.py` 可读取每段 F8 文字，输出各阶段区间、最大耗时与数据完整性检查；帧时间与真实操作响应须另外测量。

## 地平线 6 画质反馈

阴影拖影、强化后的车灯溢色当前只有口头报告，未取得原始日志或固定路线。首次复现沿报告人的原设置，记录实际路线、模型参数、工作分辨率及 HDR；jitter 关闭后，同一车灯与阴影边缘重复慢移再静止。

对比额外增强 1.0 与已复现强度；强度未知时 2.0 只作测试起点。需要图像时另做 F7，先区分 Original、Neural 与 Composite 中何处开始出现异常。现有 Neural 导出经过空间恢复，不是原始模型尺寸纹理，也不是精确配对的最终显示图像。未定位前不靠全局降饱和、模糊或削弱所有增强来宣称修复。

## 结果口径

此候选不自动发布稳定版。实际源码、构建哈希、本地验证和各游戏结果分别记录；缺少复现材料的项目继续保留待验证状态。
