# D7：人脸自动对照诊断

这版在“反馈与诊断”中提供独立的“人脸自动对照诊断”。你只需固定画面、
选一次人脸位置并开始；程序会切换参数、等待模型稳定、采集并恢复原设置。
本版没有修改人脸识别或光影算法。

## 使用

1. 保留容易出现人脸问题的设置，让NR正常运行，找到一个可以固定镜头的画面。
2. 打开“反馈与诊断”→“人脸自动对照诊断”，选择“选择人脸区域”。
3. 主面板暂时收起，在人脸处点击或拖动取景框，确认位置。人脸不必位于屏幕中心。
4. 点击开始，保持场景与镜头，等九组完成。程序自动保存每组完整画面，以及
   框内同次模型输入、输出与合成等内部数据，不需手动开关参数或逐次按F8。
5. 完成后原画质参数自动恢复。中途需要停止时重新打开诊断页并取消。
   失败、超时或运行时退出也走恢复流程；报告会说明缺少哪些结果。

通常需要约30–60秒，取决于帧率和模型重新建立所需时间。每组至少等3秒，
并要求当前模型在重置后成功执行64次；内部数据确实完成GPU回读后才请求截图。
若帧率太低或场景不再渲染，30秒单组超时会停止并恢复。

## 自动比较的组合

| 条件 | 保存内容 |
| --- | --- |
| 你的当前模型参数 | 人脸调节关闭、开启且皮肤强度0，各一组 |
| 模型基准：强度1.2、局部明暗1、整体细节1、默认风格、界面保护开 | 人脸关闭、开启0，各一组 |
| 上述基准，局部明暗改为2 | 人脸关闭、开启0，各一组 |
| 上述基准，整体细节改为2 | 人脸关闭、开启0，各一组 |
| 最后回到你的当前模型参数，人脸开启0 | 再采一组，检查场景或模型响应是否漂移 |

所有组都保留光影系数、完整/分层模式、处理路线、工作比例、颜色和光照保护。
原生RR已开启时保留实际后置路线；不替你打开或关闭游戏RR。诊断临时参数不写
个人INI。人脸关闭时实际模型皮肤参数按原有规则使用-1，报告分别记录配置和
真正应用到模型的参数。

当前与基准同时改变了多项模型参数，所以它们只能回答“恢复模型基准是否改善
响应”；局部明暗2和整体细节2两对组合才用于分别检查这两项与人脸控制的关系。

## 全屏与取景框

每组均保存完整PNG。取景框只限制内部五层浮点数据：4K全屏单帧约633MiB，
512×512区域约20MiB。九组原始区域数据约180MiB，另加全屏图和日志。
这不是自动人脸识别，取景框的位置由你选择。

诊断保持现有采集预算，不提高GPU/CPU回读各128MiB或总归档512MiB上限。
128MiB不是整个游戏或ReShade截图的内存上限。开始前根据全屏尺寸做保守预算
检查，写包时仍检查实际文件大小；过大的分辨率会明确拒绝，不会暗中缩小全屏图。
本轮3840×2160在预算内，3840×2400及更高尺寸可能超出当前九组预算。

取景框只在近期NR画面与完整游戏输出/截图的映射可确认时启用；子视图、
未知映射或NR未运行时会提示。采集期间若路线、尺寸、选区或颜色合同变化，
停止并保留部分证据。不同参数组和全屏截图按时间先后取得，并非同一冻结帧；
固定镜头及最后的重复组帮助评估漂移，不能消除角色动画、曝光或场景变化。

## 结果与回退

将生成的结果路径发回本任务即可，不需要手动整理九组图片。内部平面、参数、
组名、位置、完整截图与配对核心报告一起用于分析。缺失证据不会标记为完整。

具体构建/菜单/采集门禁与游戏实测状态见同包来源记录。异常时先退出游戏，
恢复备份D6 Core并保留本次诊断；本包不修改个人INI、游戏运行库或ReShade。
