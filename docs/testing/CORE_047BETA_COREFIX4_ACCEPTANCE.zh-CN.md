# 0.4.7beta-corefix.4：对象识别与当前阶段观察

本候选接续 corefix.3 的实机失败：死亡搁浅后置没有持续效果，正常／仅状态切换偶尔像 NR 增强短暂出现，暂停后不闪但仍无效果；绝区零 NR 仍未执行。新候选修复代理和原生接口之间的观察关联，并补充当前阶段只读边界及近期状态重置原因。是否改善实际效果须由新一轮游戏反馈确认。

包中仅包含所选语言 Core、配套 `nrchain_nvngx.dll`、许可和来源凭据。没有设置、游戏运行库或模型；保留现有 INI、ReShade、NR 运行库及个人画质参数。不要同时加载两个 Core。退出游戏后备份当前 Core，再在实际加载目录替换。已有相同配套桥时按 SHA-256 核对，避免无关替换。死亡搁浅的专用交付脚本只更换 Core，另有原版备份和恢复前置检查。

`build-info.json` 和 `SHA256.json` 记录确切来源及字节身份。本地编译、CPU 和 WARP 通过不等于 NVIDIA NR、游戏最终画面或性能通过。这里没有自动升级稳定版，也没有重新调高增强强度来掩盖问题。

## 死亡搁浅

1. 保持原有画质设置及固定的 **SR → NR（后置）**，进入原先复现的场景。
2. 在反馈页将“自动诊断采样”设为 **暂停采样**，保持面板可见约 30 秒，按 F8。
3. 同时说明画面是否持续有效、是否仍有短暂增强，以及“近期状态”是否还来回跳动。

先提供这一份新的暂停阶段报告即可。该模式仍执行 NR，但不运行自动 GPU 采样；新只读窗口只观察真实调用，不增加状态切换或读回。旧正常阶段样本仍保留原 frame／phase／trace，不会被标成暂停阶段的新像素证据。

## 绝区零

沿用已确认的 HoYoShade 加载位置换入新 Core，进入实际游戏场景约 30 秒后 F8。保留目前的路线和设置，同时说明是否出现持续 NR 效果。不需要猜测 Output 格式或强行切换到某个格式。

## 如何理解状态

“已观察到 NR 处理和提交”只表示最近发生了对应调用和提交。明确的原生视图使用、存储比较、最终显示和画质是不同证据，不能互相替代。报告可能仍显示未知；这比借用旧阶段或不确定对象的记录更准确。

若需恢复，先退出游戏，仅恢复备份 Core，保留当前设置。使用专用脚本前可先运行恢复前置检查；旧候选和原始反馈不会删除。
