# Corefix.3 对照测试说明

本候选接续 Corefix.2 的真实失败反馈，用于区分采样相关闪烁、后置最终画面无效与资源解释拒绝。加载、NR 调用、提交和诊断通过都不等于画面修复。

## 更新

退出游戏后，使用相同注入方式选择一个对应语言的 Core，并保留现有设置、NR 运行库和其他组件。包内包含配套桥接 DLL，不含配置或模型。不要同时保留多个活动 Core。

Corefix.2 已完成的 jitter 迁移不会重复覆盖之后的手动选择；新装、旧版本首次升级和恢复默认仍关闭实验 jitter。此次不统一重置其他个人画质设置。

## 死亡搁浅：固定 SR→NR

在“反馈与诊断 → 闪烁对照”按以下顺序比较，每段约 30 秒，关闭菜单后观察，再保存一份 F8 文字。

1. 正常采样。
2. 暂停采样。
3. 仅切换输出状态。
4. 返回正常采样。

保持相同路线、分辨率、参数、视角和场景。若人物或镜头自动转动，先重新固定视角，再重复相关段；记录确实发生的移动，不能把不同画面当成严格同场景对照。比较期间不按 F7。

每段分别记录“是否闪烁”和“增强是否持续可见”。仅切换模式继续执行 NR，在原诊断采样时点仅保留那组额外输出状态切换，不新增自动采样 shader、clear 或 readback，也不创造恢复存储证明。已有读回仍可按原阶段退休；对照不落 INI、不重置模型历史。

若仅切换也闪，说明这组输出状态切换可能参与；若只有正常采样闪，继续检查其余诊断工作。后者仍包含其他 GPU 命令、描述符切换及收集调度，不能直接把读取 shader 当成唯一根因。F8 的实际模式、阶段、状态切换记录与 NR／提交覆盖率用于核对对照有没有真正发生。

## 绝区零

沿原米哈游启动器与 HoYoShade 路线，进入实际游戏场景，保留复现设置并保存 F8。报告会区分前置回退尝试、后置准入失败与真正的兼容路线锁。

新增的缓存描述符、显式原生 UAV 使用及 RTV 目标／范围记录是观察证据，不会自动把未知 typeless 资源猜成 UNORM。当前 Output 类型仍未确认时，NR 会继续受保护地拒绝；不要把同一份报告中的 DLL 加载成功或“尝试后置”看成效果已生效。

## 兼容路线

真实 RR 的强制 RR→NR 保持。普通 SR 只有在前置失败与同一证据范围内的后置验证都充分时，才保持兼容后置路线；配置、Feature、资源解释变化或实际失败会使旧证据失效。个人保存的模式偏好保持，顶部会说明当前原因并提示 F8。路线锁只表示执行合同满足，画面仍需玩家确认。

## 耗时与反馈

F8 修正了部分长计时数字被误脱敏的问题。事件等待／旧轮询对照仍须独立各三段 30 秒，每段开始新计时段，不混改采样和画质。CPU 百分位为有界直方图区间，不是 GPU 推理耗时、游戏帧时间或输入到显示延迟。

这是测试候选，不自动发布稳定版。来源、验证和文件哈希见包内 build-info.json 与 SHA256.json；游戏画面和性能验收独立记录。
