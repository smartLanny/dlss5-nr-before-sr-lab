# 2077 本机测试：beta0.5-dev4

这是一套人工游戏验收步骤，不是已通过的游戏测试结果。dev3 吸收 0.4.5 候选修复，保留 dev2 单次 NR 分层 shader；没有多次 NR、Lanczos2、Catmull 或 Mode1B。强度上限 4，不需要按早期研究报告测试 8。

## 1. 安装与固定条件

完全退出游戏，备份旧 addon、自有 nrchain_nvngx.dll、nr_before_sr.ini。安装本包一个语言的 addon 和同包自有 bridge；中文与英文 addon 二选一，新旧 NR addon 不要同时加载。保留已有能工作的 NVIDIA 运行库与驱动，不为本次测试随意替换它们。不要把自有 bridge 改名成游戏 DLL。

首轮只保留一个 NR 执行者。通用 renodx-dlss5/ShortFuse NR 与本插件不能同时争用链路；游戏专用 HDR-only RenoDX 不是同一回事，不要不分用途删除。记录所有保留的 MOD。

游戏内保持同一输出分辨率、同一 DLSS SR 档位（例如质量）、固定画质、关闭动态分辨率。首轮关闭光线重建 RR 与帧生成 FG/MFG；先用普通非路径追踪场景。HDR/SDR 固定一种，不能在一组 A/B 中切换。不要同时调模型风格、人脸遮罩、模型内部强度或颜色跟随。

找一个可反复读档的脸部近景，另留一个能看到霓虹/栏杆/头发的镜头。自然停留或对话镜头即可，不要求另装暂停 MOD。照片模式可能改变渲染路径，只能作为单独测试；不能拿照片模式截图对比普通游戏性能。

进入插件画面页，点击“恢复推荐画质设置”，再检查：前置 Mode2、最终强度 1.2、NR 画质档位保持同一档、高强度保护打开、分层关闭。该按钮保持总开关；若原来关闭，另用 F6 开启。按钮也恢复模型/HDR画质偏好，因此先备份自己的参数。

## 2. 先证明真正生效

在正常游戏画面用 F6 关闭，再开启，观察当前链路状态以及“NR 成功/提交”计数是否继续增加。历史累计非零不代表此刻有效：要看同一场景前后是否增加。存在 SR 调用也不代表 NR 已执行。

完全没变化或状态持续旁路时，先按 F8 收集核心报告，不要为了强行生效拉满参数、关闭安全检查或改 ExperimentalNullPsoCarrier。核心报告能在 NR 为零时完成。遇到崩溃/设备丢失/持续闪白，停止这一轮，保留报告和既有崩溃记录后回退；F6 不是重新加载损坏运行库或清除资源隔离的按钮。

F6-off 是“插件加载但旁路”对照。若怀疑插件本身导致启动/崩溃，另做一次完全退出游戏、移走本 addon 后的原生对照，不与热切换等同。

## 3. 四组足够开始，不要一次改很多项

每组固定同一个存档、镜头、时间/天气和其他参数。切换后等 5–10 秒，让画面和曝光稳定，再截屏/录屏；回到原组复查一次，以识别 NPC 动作/照明变化。

| 组 | 设置 | 看什么 |
|---|---|---|
| A | F6 关闭 | 原生 SR 的脸、噪点和高光基准 |
| B | F6 开启，Mode2，强度1.2，分层关闭 | 原有单次 NR 效果是否正常 |
| C | 在 B 上仅开启分层，四项都为1 | 应无稳定可见的额外修改；活游戏不是冻结输入，不要求跨帧逐位相同 |
| D | 在 C 上仅把“提亮贡献”改为0.75 | 额头/鼻梁/脸颊反光、肤色、金属感是否改善，细节是否损失 |

顺序建议 B→C→B，再 C→D→C。D只是定位实验，不是预设推荐或保证更真实。仍太重时，另起一组只把局部结构贡献改为0.75；不要同时改提亮和结构，否则不好定位。

主强度保持1.2做完上面几组，才单独试2和4。4只做短暂压力测试：出现爆白、明显色偏、黑边或闪烁就回到1.2。最后故意把分层调成非中性，再点击“恢复推荐画质设置”，应看到分层关闭、四项1、高强度保护开，而总开关不被悄悄打开。

截图可用主键盘“-”；文件名没有完整记录所有分层参数，需和设置截图/F8报告一起保存。相同设置的截图不要在聊天中再次压缩后当作像素证据。

## 4. 运动、性能和稳定性分开测

静态画质确认后，按同一路线缓慢左右转头、快速转身、经过暗室到霓虹/室外、打开关闭地图、读回存档和切出切回窗口。观察是否出现持续黑边、重影、曝光抽动、旁路后不恢复。首轮每个动作只做几次，不要同时切 HDR、DLSS、NR 尺寸和 FG。

性能用 B/C/D 同一个静止镜头或可重复路线，各记录30–60秒，至少重复3次。开始前预热，关闭限帧/VSync或确认没有撞到同一个帧率上限；记录平均帧率及基础帧时间的P95/P99（手头工具支持才记）。不要把FG插帧后的显示FPS当基础渲染性能。测量期间关闭插件Overlay，不按F7、不截图、不生成反馈包；先测完，再收报告。用帧时间看增量，不承诺分层零成本。

完成后再单独打开FG做相同动作，保持RR关闭。RR另列“安全旁路”测试：本候选不会把RR当SR强行注入NR；RR打开后NR停止且原生游戏正常，可以是预期旁路，并非新兼容失败。关闭RR仍有旧handle时，重启游戏再验证。

后置Mode1单独测：先关闭分层，切完整后置，比较开关与状态，测试后切回前置。它处理完整输出，成本不能与前置同档位简单等同；若后置拒绝，提供F8，不启用宽松状态回放。

## 5. 给开发者什么

反馈页“采集核心反馈包（F8，推荐）”只采CPU核心诊断，不自动改画质、不采GPU图像。生成后可复制“完整报告（群文档）”，或发同目录feedback-report.txt；ZIP也保留。F7是额外画面/阶段证据，会先生成配套核心记录，按当前UI选择范围和模式，完成后再进行性能测量。两者都没有自动上传。

最小反馈：填写2077-RESULTS.txt，附设置截图、B/C/D同镜头图和至少一份问题当时的F8 TXT/ZIP；运动问题加10–20秒原始录屏。记录版本、GPU/驱动、输出分辨率、DLSS档、NR档、RR/FG/HDR和MOD。无需玩家自行解析shader或日志。

F8新增字段是“采集时请求设置”，不是已执行证明。请结合start/end.nrSuccess、transferSubmitted和旁路原因；F7逐帧codecFlags和高强度/分层标志才描述该帧提交的合成配置。报告标记partial/snapshot-busy时不要当成完整证据。
