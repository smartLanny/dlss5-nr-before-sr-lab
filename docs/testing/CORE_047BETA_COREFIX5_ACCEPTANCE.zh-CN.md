# 0.4.7beta-corefix.5 验收说明

本候选接续 corefix.4 的实机失败，修复不同绘制线程导致的近期状态回退，以及描述符记录在仍有空位时被覆盖的问题；为复用既有视图的原生调用补充明确格式来源，并完善 UNORM 实际写回的逐点比较。实际游戏效果仍以本候选的新反馈为准。

包中只有所选语言 Core、配套 `nrchain_nvngx.dll`、许可和来源凭据。退出游戏后备份当前 Core，再在实际加载目录替换；同一进程只加载一个 Core。保留现有 INI、ReShade、NR 运行库及个人画质设置。已有相同配套桥时按 SHA-256 核对。`build-info.json` 与 `SHA256.json` 记录冻结源及实际字节身份。

## 死亡搁浅

保持原来的 **SR → NR（后置）** 和同一场景，将反馈页“自动诊断采样”设为 **正常采样**，保持面板可见约 30 秒后按 F8。说明 NR 是否持续可见、是否仍短暂闪现，以及近期状态是否仍跳回检查。一份正常采样报告即可检查新的实际写回比较。

暂停采样仍执行 NR，但不产生新的自动 GPU 存储样本；迟到的旧样本会保留原阶段。所有 UI 真正停止读取超过两秒后，再显示检查状态仍属预期行为。

## 绝区零

沿用此前确认的 HoYoShade 加载目录换入新 Core，按原先能复现问题的步骤进入实际场景，约 30 秒后 F8。保持路线及设置，并说明是否还有 unsupported format、NR 能否持续显示。不需要手动指定 Output 格式。

## 结果与恢复

近期处理、原生格式请求、实际存储和最终显示是分别验证的事实。完整的稀疏写回匹配也不能代替最终画面确认；本地 CPU、WARP 和菜单通过不等于真实 NVIDIA 或游戏通过。

需要恢复时先退出游戏，仅还原备份 Core。专用交付目录保留旧 Core、安装记录和恢复前置检查；此前候选与反馈不会被覆盖。
