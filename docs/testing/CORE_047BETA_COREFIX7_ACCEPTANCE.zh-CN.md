# 0.4.7beta-corefix.7 复测说明

本候选修复一处槽位选择问题：当 Color/Output 不变而运动矢量（MV）纹理轮换时，旧代码可能一直选中忙碌槽位并跳过 NR。现在优先复用正确绑定，再使用可安全修改的槽位；仍不改写 GPU 正在使用的描述符。是否消除游戏闪烁仍需本次复测确认。

## 绝区零：当前 POST 原场景一次复测

1. 退出游戏，备份当前 Core。在此前确认的 HoYoShade 实际加载目录换入本包同语言 Core，同一进程只保留一个 Core。
2. 保持原有路线、INI、ReShade、NR 运行库和画质设置，进入当前 POST 原场景，观察 NR 开启时是否持续生效。
3. 可在游戏内关闭 NR，再开启一次；保持面板可见约 30 秒后只按一次 F8。若出现“不支持的 Output 格式”，在该状态下采集；不重复测试 PRE。
4. 只返回这一份 F8，并说明 NR 是否可见、是否仍闪烁、是否再次出现格式不支持。

## 包内容与恢复

包内包含所选语言 Core、配套 `nrchain_nvngx.dll`、许可与来源凭据，不包含 INI、模型、NVIDIA 运行库或 carrier。沿用已确认的 HoYoShade 部署方式，优先只更换 Core；已有配套桥可按 `SHA256.json` 核对，不新增另一套加载器。`build-info.json` 记录冻结源码与本地验证边界。

需要恢复时退出游戏，仅还原备份 Core。之前的候选与反馈继续保留。

## 尚未解决的范围

死亡搁浅仍无持续可见效果且偶有闪烁。本轮不替换该游戏的 Core，不要求重复四阶段，也不据此宣称画面问题已修复。

CPU 格式请求、GPU 描述符使用、实际存储和最终画面分别验证。本地 CPU/WARP 不能替代真实 NVIDIA、游戏效果或性能验收。
