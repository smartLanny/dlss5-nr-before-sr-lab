# 0.5 D15 测试版安装与使用

这是用于现有 DX12 安装环境的 Core 更新包，版本为 `beta0.5-dline15`。
本包提供一种语言的 Core 和配套 `nrchain_nvngx.dll`；个人 INI、ReShade、
NVIDIA 模型及游戏文件沿用现有安装。验证身份和文件哈希见包内 `build-info.json`
及 `SHA256.json`。本地测试结果与实际游戏兼容、最终显示和整帧性能分别记录。

## 更新与恢复

1. 完全退出游戏，将现有 Core 和 `nrchain_nvngx.dll` 备份到游戏目录之外。
2. 把本包 Core 和 `nrchain_nvngx.dll` 放到原有 Core 所在目录。移走旧版本 Core，
   目录内只保留一份所选语言的 Core，避免同时加载多个版本。
3. 保留个人 INI、ReShade 和游戏原有 NVIDIA DLL。进入游戏后确认菜单版本为 D15。
4. 要恢复旧版本，退出游戏，移走本包的两个模块，再还原成对备份。

此包适合已经正常加载本插件的 DX12 环境。新安装仍需完整的原安装环境。
配套 D15 桥接模块已包含官方 SDK 加载器，可在游戏从未初始化 DLSS 时初始化 NGX。
请成对更新 Core 和桥接模块；NVIDIA 驱动及另行提供的签名 NR 运行库仍然需要。
嵌入 SDK 的许可条款见 `LICENSES.txt`。

## 选择起点

三个按钮分别指定优先尝试前置、后置或 Present 兼容处理。
前置未能开始处理时可顺延到后置，再顺延到 Present；选择后置只尝试后置及 Present。
菜单分别显示保存的选择和实际运行位置。自动顺延会在本次会话中保留；
再次点击起点按钮或重启可重新尝试。普通画面设置和分辨率修改不会自动改回前置。

Present 优先使用同一源帧可确认的原生导引；缺少导引时自动使用纯颜色模式，
并按源帧重置历史，应与有导引模式分别比较。FG 开启时是否能在帧生成前处理，
取决于本次来源与消费位置的实际确认。状态中的“已记录”或“GPU 完成”不能替代最终画面验证。

## 完整 2–4 层对照

“完整同尺寸对照”默认关闭。开启后选择 2、3 或 4 层，各层均使用第一层的处理尺寸，
各有独立模型状态，最后统一合成。请求层数与实际采用层数会分别记录。
原有低分辨率二次 AI 比例会保留，关闭完整对照后恢复；已有合法的旧比例不会被重置。

## 最小回测顺序

1. 在固定场景先用 F6 关闭增强，保存游戏原生画面基线，再开启单层处理。
2. 分别尝试三个起点；保持其余设置不变，记录菜单实际运行位置和画面变化。
3. 比较单层、完整 2/3/4 层和原有低分辨率第二层。分别记录画面与整帧性能。
4. 游戏支持时，分别回测原生 SR、RR、无 DLSS、FG 开关，以及 SDR/HDR。
5. 出现画面异常、持续等待或结果与状态不符时按 F8，保存报告及确切切换顺序。
   同时说明游戏版本、图形 API、分辨率、SR/RR/FG/HDR 设置和复现位置。

F8 仍用于状态和日志。兼容路径下，F7 捕获当前处理路径的完整各层数据，
按实际路径导出到系统文档中的 `DLSS5-Present-Capture` 或 `DLSS5-FG-Capture`。
界面分别显示待完成、正在导出、失败或已导出；这些文件不是原生阶段矩阵或最终屏幕截图。

格式 #253/#202/#248 与曝光 #228 使用已有共享机制继续验收；报告应来自同一候选版本。
旧版 #247 和早期 #68 仅作历史对照，不能据其结果扩大 D15 的兼容结论。
详细场景与公平对照填写[集中游戏验收表](DLINE15_GAME_ACCEPTANCE.zh-CN.md)。
