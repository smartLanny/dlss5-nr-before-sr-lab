# D13：双层连续处理与常用菜单

本批处理 D12 中第二层在“暖机”和“等待安全资源”间反复切换的问题，并整理常用画质菜单。
版本为 `beta0.5-dline13`，PE 版本为 `0.5.1.13`；仍是独立的 0.5 测试候选。

## 变更

- 第二层和引擎分区使用有界、不可原地改写的描述符表。同一有序队列、相同资源与视图可以继续录制；绑定变化时使用已退休的另一份表。最多每个上下文 8 份，不增加纹理池上限，也不等待 GPU。
- 所有表及直接传入第二层的引擎导引都保持引用，沿用 Core 的录制、提交和确切 fence 退休机制。未知队列、不同设备、容量不足、未确认的创建完成及不透明调用失败仍按原有规则拒绝或保留依赖。
- 第二层的合成表在推理前准备完毕，包含本帧可用的分区与独立脸区。运行第二层后不再重新写入已使用的表。
- 引擎分区每帧重新读取导引并生成本帧区域；补充 `R32G8X24_TYPELESS` / `D32_FLOAT_S8X24_UINT` 的深度读取视图。缺少有效镜面和命中距离导引时，不开放镜面倍率。
- 第二层仍默认关闭。新配置、缺失比例或恢复默认使用 50%，用户可调到 100%；升级保留合法旧比例。
- 常用顺序为画面风格、处理顺序、第一层精度、二次 AI 与比例、模型强度、额外增强、AI 色彩和模型人脸调节。二次开启后立即显示比例；诊断移到反馈页，较长说明移入悬浮提示。
- 保留“全部亮暗变化”和“仅细小变化”两种光影范围。引擎分区、通用分层仍标记为实验；独立人脸保护单独列为实验，文字与界面保护放入开发者选项。
- 模型人脸参数由两层各自的上下文绑定。F8 分别记录第二层实际成功推理后的参数与是否仍处于暖机，不能据此推断模型一定识别了某张脸。
- 第二层摘要按短时间窗口统计主层、第二层成功推理、暖机丢弃和最终选用；旧配置及旧路线的状态不作为当前生效证据。
- F8 记录实际 Reset 来源、绑定拒绝原因、分区导引标志和各自的配置代次，用于区分模型历史变化、资源占用及未验证的队列。

## 游戏对照

1. 固定场景、镜头、第一层精度、风格、模型强度和 HDR 调色许可，先启用第二层 50%。等两层准备完成后，确认摘要持续生效，并保存 F8。
2. 在“先增强，后放大”和“先放大，后增强”间切换，再交替调整第二层比例、模型强度、人脸开关和光影方式。切换后的准备可以短暂出现；持续无法选用应显示“暂未生效”，需保存当时 F8。
3. 对引擎分区比较 0、1、4 倍。两条路线必须使用相同颜色强度和 HDR 许可；AI 色彩为 0 或当前 HDR 策略拒绝颜色时，不把颜色不变认作分区失败。
4. 开启模型人脸调节，先设人脸细节为 0，再改变整体细节，分别对照一层和两层。独立人脸保护保持单独实验，不自动介入此项核验。
5. 性能比较分别记录第二层新增开销和同 NR 设置下整帧 GPU 中位数/P95。暖机、采集帧、旧配置样本以及链路计时不能充当整帧性能结果。
