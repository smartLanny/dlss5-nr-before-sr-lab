# 0.4.7beta-corefix.6 复测说明

本候选针对 corefix.5 绝区零反馈中已确认的一处格式观察缺口：原生 Clear 的 CPU 视图格式仍明确，但 GPU 描述符记录被淘汰时，独立 CPU 格式请求也被错误丢弃。现在保留符合条件的 CPU 请求，仍须在当前原生调用成功后再次核验。已知冲突和未知 CPU 格式继续拒绝；不需要手动指定 Output 格式。游戏效果尚未验收。

## 绝区零：一次切换复测

1. 退出游戏，备份当前 Core。在此前确认的 HoYoShade 实际加载目录换入本包同语言 Core，同一进程只保留一个 Core。
2. 保持原有路线、INI、ReShade、NR 运行库和画质设置。进入原先能复现的场景，先观察 NR 开启时是否持续生效。
3. 在游戏内关闭 NR，再开启一次。保持面板可见约 30 秒后按 F8；若又出现“不支持的 Output 格式”，在该状态下采集即可。
4. 返回这一份 F8，并说明切换前后 NR 是否可见、是否闪烁、是否再次出现格式不支持。

## 包内容与恢复

包内包含所选语言 Core、配套 `nrchain_nvngx.dll`、许可与来源凭据，不包含 INI、模型、NVIDIA 运行库或 carrier。沿用已确认的 HoYoShade 部署方式，优先只更换 Core；已有配套桥可按 `SHA256.json` 核对，不新增另一套加载器。`build-info.json` 记录冻结源码与本地验证边界。

需要恢复时退出游戏，仅还原备份 Core。之前的候选与反馈继续保留。

## 尚未解决的范围

死亡搁浅 corefix.5 仍无持续可见效果、偶尔闪烁。本轮没有确认其最终显示根因，也未据此替换该游戏的 Core 或要求重复四阶段测试。

CPU 格式请求、GPU 描述符使用、实际存储和最终画面分别验证。本地 CPU、WARP 与菜单检查不能替代真实 NVIDIA、游戏效果或性能验收。
