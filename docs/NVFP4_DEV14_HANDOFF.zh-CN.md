# NVFP4 dev14 研究交接

维护者于2026-09-09恢复 GPU 验证。真实 ReShade Core 的 mode2 NR→原生 SR 已接通，
三次／两次调用融合均已有局部 GPU 验证。完整 NR 降低10%、运动／游戏画质和 Auto
仍未通过验收；默认仍是原 FP8，Auto 合格策略表为空，没有部署、合并或发布。

本页先记录当前证据范围，再保留最初预览包的准确身份。当前工作源码尚不能与下方旧包
混为同一构建；新包的文件名和哈希须由最终实际包装收据产生。技术细节见 `NVFP4_DEV14.md`。

## 当前已确认的范围

- 提前安装被动 NVAPI 观察器后，新启动的真实渲染器已取得 FFN 身份并完成每帧8对替换。
  CUDA／设备准备仍在后续阶段进行，默认精度仍为 Off／原 FP8。
- 静态同输入比较使用 NR 2560×1440、M960、原生 SR 输出3840×2160；192帧历史周期，
  其中128帧预热、64帧计时，捕获第184–191帧。S 为关闭 Core 的纯 SR，F 为原 FP8 NR→SR，
  另两组为锁定上游 FFN 和自建普通收缩。上游比较采用同一安全后端载入锁定内核／权重，
  不代表整个上游插件的测试。F 为零替换，另两组各8对、32次调用、40个 UAV 依赖。
- 修正渲染器按进程地址排序导致的输入变化后，两次纯 SR 的完整周期元数据一致，捕获的8帧
  输入和 SR 输出逐字节一致；S／F／上游／自建四组的完整周期元数据及8帧输入 SHA256 也一致。
  未捕获全部192帧原始像素；旧 r4 不同输入结果仍保留，但不用于同输入画质结论。

以输出网格 RGB 上的 `rF=F-S`、`rC=C-S` 定义
`effect_gain=sum(rC*rF)/sum(rF*rF)`、
`residual_nrmse=sqrt(sum((C-F)^2)/sum(rF*rF))`，跨8帧汇总能量后计算：

| 候选 | effect_gain | residual_nrmse | 增强残差 RMS／FP8 残差 RMS |
| --- | ---: | ---: | ---: |
| 锁定上游 FFN | 0.98630334 | 0.07535483 | 0.98908292 |
| 自建普通收缩 | 0.98632293 | 0.07269010 | 0.98890329 |

FP8 增强残差 RMS 为0.0034353073。以上是明确写出的本地指标定义，未声称复用了外部报告
的原定义。上游和自建输出也不逐字节相等：8帧 SR RGB RMSE 为0.00007220–0.00007776。
静态同输入结果不构成运动、遮挡显露或游戏画质验收，FP8 也不是画质真值。
私有证据 ID：`resume-20260909/chain-fixed-pure-sr-repeat-r1.json`、
`chain-fixed-reference-enhancement-r1.json`、`chain-fixed-optimized-enhancement-r1.json`、
`chain-fixed-upstream-vs-optimized-r1.json`。原始捕获与 NVIDIA 资产留在私有证据目录。

三次调用融合收缩已有独立 GPU 与真实签名 Feature18 宿主验证；两次调用版本已实现
CTA 内 pack＋expansion＋gate，再接融合收缩，M640 实际记录8对／16次调用，
完整 Feature18 输出与三次调用版本逐字节一致，但更慢。补齐共享内存布局后的独立样本中，
最快融合 expansion 在 M640 为0.06932 ms，对照 pack＋expansion 为0.01857 ms；
M960 分别为0.11392和0.03385 ms。减少调用数本身不是性能资格。
修正 epilogue 后的66组形状／零值／有符号输入和96组真实权重 GPU 用例通过；最初失败结果保留。

M640 是自建实现新增覆盖，1920×1080 NR 对应内部20×32；上游完整 hybrid 替换模板不支持
该尺寸。M640 的独立数学与宿主证据不能写成上游完整 hybrid 对照；共同支持尺寸的真实
NR→SR 上游比较使用 M960。对应证据为 `expansion-shapes-r3.json`、
`expansion-models-r3.json`、`expansion-timings-r3.json` 和 `vector-two-smoke-m640-r1`。

## 唯一允许的 HLSL 改动与未完成项

源码只落地已验证的 `CombineV2` 诊断门控：诊断源转换与最终相对差值只在诊断开启且
x、y 坐标均为32的倍数时计算。输出运算、增强强度、保护、资源绑定和生命周期未改。
导出脚本只放行两组精确 HLSL 基线／候选哈希，保存完整差异；未知或新增 HLSL 及 NRChain
桥改动仍被拒绝。原生成 HLSL 的 `7cf7fe7e…` 哈希是历史基线，当前候选为
`eb10b9548d0b8c49d2b048f5c93c4a135004a976ff7162e89cbe611e302adc55`。

诊断门控与原上游内核配置相比，8帧共24份输入／SR／显示捕获逐字节相同，两个完整颜色诊断块
也相同。实际 O3 编译的生成着色器与私有已测 DXBC 一致。两组短程反序比较的合成阶段
分别节省0.04029和0.04125 ms；完整 NR 时间受到 Feature18 漂移影响，不能据此声称达到10%。
证据：`chain-fixed-reference-diag-equivalence-r1.json`、`diagnostic-gate-short-decision-r1.json`、
`diagnostic-gate-source-integration-r1`。

当前还需在冻结候选上完成五轮长程交错 A/B、带深度／运动矢量的运动和遮挡显露比较、
游戏及 HDR／DRS 验收。Auto、游戏和完整 NR 性能资格仍为 false，旁置 JSON 不能绕过 Auto。
未来合格策略需记录真实 NVIDIA 驱动构建身份，不能用 CUDA driver API 版本代替驱动610.62。
