DLSS 5 AI 渲染完美链路 beta0.4.3 社区测试版——轻量更新说明
作者：@野生的装机宅 Bilibili
官方发布地址：https://space.bilibili.com/941799

适用范围

本包用于已经装好兼容运行库的 beta0.4.x 用户。完全退出游戏后，备份旧 addon 到游戏目录外，只替换 addon，并把 Collect-Feedback / Collect-Crash-Feedback 两组 CMD + PowerShell 工具放在 addon 旁边。保留现有 nrchain_nvngx.dll、nvngx_dlssnr.dll 和 nr_before_sr.ini。不要同时加载旧版、新版、中英文两个 addon、HD2 实验版或 renodx-dlss5.addon64。

0.4.3 主要变化

1. 合入 0.4.2 bug sweep：收窄光照保护的黑边/反向残差风险，修正遮罩相关参数与面板隔离，并为原生 NGX Hook 增加保守重试路径。空 PSO 与高风险扩展图形状态路径仍默认安全旁路。
2. F8 改为独立的小型核心反馈包。核心 ZIP 有 8 MiB 硬上限，只收集已知日志与运行状态，不读取纹理、不自动上传，也不会为了采集而改画质参数。
3. F7 图像反馈会先生成与本次会话关联的核心包，再进入原有图像采集；核心包与图像包可核对 session、源码提交、实际 addon SHA256 等身份，但“配对成功”不等于同一帧。
4. 反馈解析器加强完整性校验：必需日志必须明确声明，取消、扫描不完整、缺失输入等情况不能再被误判为完整；不同 addon 二进制产生的 core/image 也不能只凭相同源码提交就被误判成一对。
5. 热键与状态管理收紧：F8 自定义键不会与 F6/F7 冲突，新采集会清掉过期结果路径，忙碌时拒绝重复请求而不破坏正在进行的采集。
6. 新安装仍以 Mode 2 为默认链路：较低工作分辨率运行 NR，再把匹配残差送回游戏渲染分辨率，最后交给游戏原生 DLSS SR。NR 画质档位只改变 Feature 18 工作分辨率，不改变游戏自己的 DLSS 档位。

画面默认值

新安装最终效果强度为 1.2，滑条就是实际请求值，可在 0 到 8 之间调整。颜色跟随新装默认 0.75；未知 HDR 合同仍只传递明暗。已有配置中的明确数值会保留。低 NR 工作分辨率配合很高强度可能放大颗粒，遇到噪点应先提高 NR 画质档位再判断。

兼容性与安全边界

本版本仍是 D3D12 原生 DLSS Feature 1 路线。DX11 不在本次 0.4.3 beta 中，DX11 研究分支独立维护。遇到不确认的资源、格式、子区域、命令状态、RR 所有权或 HDR 合同时，优先旁路并保留游戏原生 SR 结果。

鸣潮、燕云、地平线、黑神话及其他曾出现间歇失效或崩溃反馈的游戏仍需要当前 beta0.4.3 实机复测。自动回归、D3D12 WARP、Shader 编译和源码构建通过，不等于 NVIDIA 模型与真实游戏运行时已经验收。

怎么更新

完全退出游戏，备份旧 addon 到游戏目录外，再替换为本包 addon。保留原来的两个 DLL 和现有配置。进游戏后在 ReShade 插件页确认版本为 beta0.4.3，用 F6 做开关对比，并观察诊断中的 NR 成功提交计数是否持续增加。

怎么反馈

普通问题优先按 F8 生成核心反馈包；它体积小，不需要等待成功 NR 帧，也不会截图。需要画面对比时再使用 F7 图像反馈，并保持固定机位、一个设置一包。解析结果如果显示 partial / unpaired，请保留原包，不要手工修改 manifest。

闪退后运行 Collect-Crash-Feedback.cmd。它只收集已有 Windows 事件、WER 与转储证据，不会开启转储、改注册表、启动游戏或自动上传。转储可能包含进程内存和本机路径，发送前请自行决定是否分享。

如果只是进不了游戏但没有崩溃证据，运行 Collect-Feedback.cmd。两个 CMD 都必须与各自的 PowerShell 脚本放在一起。
