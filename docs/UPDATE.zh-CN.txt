DLSS 5 AI 渲染完美链路 beta0.4.2 社区测试版——轻量更新说明
作者：@野生的装机宅 Bilibili
官方发布地址：https://space.bilibili.com/941799

本包给已经装好运行库的玩家使用。保留原来的 nrchain_nvngx.dll、nvngx_dlssnr.dll 和 nr_before_sr.ini，只替换 addon，并把两组反馈工具放在 addon 旁边。不要同时保留旧版、新版或中英文两个 addon。

默认画面参数

新安装的最终效果强度是 1.2，滑条显示的就是实际请求值，可在 0 到 8 之间调整，没有隐藏倍率和 1.2 快捷预设。颜色跟随新装请求值提高到 0.75；未知 HDR 合同仍只传递明暗。已有配置中的明确数值（包括 0）会保留。

0.4.2 的 NR 画质档位只改变 Feature 18 的工作分辨率，不改变游戏自己的 DLSS 档位，也不改变 NR 与 SR 的前后顺序。低工作分辨率配合高强度可能放大颗粒；先提高 NR 画质档位，再判断是否是 jitter 问题。

本次稳定性修正

r3 在设备初始化时看到内存开关为关闭，便延后命令签名观察。鸣潮四份精确 r3 反馈包已确认：即使安装的 INI 写着 Enabled=1，启动观察数仍为 0；这个瞬时关闭状态的具体来源目前没有证据，不能武断归因于 INI 载入顺序。人物、UI、地图和雨天随后复用了无法追溯的 ExecuteIndirect 签名，插件便在 NR 帧与原生旁路帧间切换；最后的雨天采集中，1507 次原生 SR 调用没有产生一次新 NR 提交。beta0.4.2 在设备创建时始终安装这一个轻量观察 Hook，不再依赖开关快照；空 PSO 准入和扩展图形状态 Hook 仍默认关闭。自动 WARP 回归已验证 NR 激活前观察到的签名以后仍可恢复。鸣潮、燕云和其他游戏仍需 beta0.4.2 实机复测。

默认顺序没有改变：Mode 2 是“前置 NR → 游戏原生 SR”。只有手动选择 Mode 1，或旧配置原本保存 Mode=1，才会运行“游戏 SR → 后置 NR”。界面的 NR 画质档位 / WorkMode 只决定 Feature 18 的工作分辨率。

孤岛危机 3 重制版的新包确认当前呈现 API 是 DX11，因此没有原生 D3D12 Feature 1 可供本插件接入。beta0.4.2 会在面板直接提示“DX11 不支持，需要 D3D12”，不再让玩家把等待 Feature 1 误看成强度或 HDR 问题。这个提示只看当前呈现窗口，不会被 D3D12 游戏里的辅助 DX11 设备永久误触发。

中文界面不再强行使用缺少中文字形的 ReShade 字体。若当前字体只能显示拉丁字符，插件名称保持可读英文，面板自动回退到英文并说明怎样在 ReShade 的“Overlay & Styling”里选择 zh-CN／系统默认字体或微软雅黑；换好字体并重启后会恢复中文。这能消除方块、问号等乱码，但不会替其他 ReShade 插件翻译文字。

RDR2 的新反馈确认同一目录同时装了本插件和 renodx-dlss5.addon64。r3 会识别并安全停用本插件，同时显示准确删除和重启提示。两套 NR 插件不能共存；更新前请完全退出游戏，移走 renodx-dlss5.addon64、旧版、HD2 实验版和另一语言版本。

黑神话的新日志显示，低地址加载的 nvngx_dlssd.dll 让旧版 MinHook 中继分配返回状态 9，导致三个生命周期 Hook 全部缺失。r3 扩大了安全中继搜索范围，并在首个 SR 创建前立即预扫已加载模块；本地程序已复现旧错误并验证修复。黑神话实机仍待玩家复测。

地平线反馈没有崩溃转储，因此 beta0.4.2 仍保留空 PSO 安全旁路与扩展图形状态 Hook 默认关闭；这条风险收窄和本次命令签名修复都仍需地平线实机确认。

本机已复现并修正《赛博朋克 2077》在默认 NR 画质档位下不提交 NR 的问题：游戏使用四通道半精度浮点运动向量，旧版只接受两通道格式而安全旁路。现在只为这种明确的有类型格式建立视图，并读取其中的 XY 运动信息；其他未知格式仍会旁路。自动 GPU 测试已核对三种允许格式，本机短时运行累计 6546 次实际提交且没有队列状态不匹配。这只证明处理链路在运行，不代表画质已经验收。

针对《极限竞速：地平线》从 0.3.3.5 开始出现的闪退反馈，默认恢复为空 PSO 命令状态直接旁路，也不发布只为这条高风险恢复路径服务的扩展图形状态 Hook。反馈包没有转储，所以这是按精确版本回归面做的保守修复，实机仍待验证。普通玩家保持 ExperimentalNullPsoCarrier=0；只有做单变量兼容实验时才改为 1，并完全重启游戏。

DLSSNR.UICorrection 旧版写错了参数类型。现在改成运行库实际读取的无符号值；新装默认开启“HUD / 文字保护（模型）”，已有明确的 0/1 不覆盖。它只有在游戏提供独立 UI 层时才可能生效，不能自动识别已经混入 SceneColor 的字幕或 HUD。

怎么更新

完全退出游戏，备份旧 addon 到游戏目录外，再替换为本包 addon。保留原来的两个 DLL 和配置。进游戏后在 ReShade 插件面板确认版本为 beta0.4.2，用 F6 比较插件开关，并观察诊断里的 NR 成功提交计数是否持续增加。

怎么反馈

画面问题：停在固定机位，按 F8 或点“一键采集反馈包”，保持画面约 30 秒直到完成。每个设置单独采一包，不要把不同机位当成强度对比。包内会区分显示截图与 GPU 阶段，不会把它们冒充同一帧最终 SR。

闪退问题：闪退后双击 Collect-Crash-Feedback.cmd。它从最新 ReShade.log 确认唯一的游戏 EXE 完整路径，只收集最近 72 小时符合身份规则的已有 Windows 1000/1001 摘要、WER 与转储；带 AppPath 的记录必须与当前游戏路径一致。独立 CrashDumps 不含来源路径，只能按精确 EXE 文件名和时间筛选，包内会标明这个限制。工具不会开启转储、改注册表、启动游戏或上传。转储可能包含进程内存和本机路径，发送前请自行决定是否分享。

如果只是进不了游戏但没有崩溃证据，运行 Collect-Feedback.cmd。两个 CMD 都必须与各自的 PowerShell 脚本放在一起。
