DLSS 5 AI渲染超分版 beta0.3.8 轻量更新说明
作者：@野生的装机宅 Bilibili
官方发布地址：https://space.bilibili.com/941799

这是什么更新

本次 beta0.3.8 首先修复 r3 的间接命令观察回归，同时保留界面、描述符、字体、生命周期和配置迁移修复。新装默认效果强度 1.2、颜色跟随请求 0.75；已有设置（包括 0）按原来所用模式保留。滑条显示的就是请求值，范围为 0 到 2。前置模式仍为默认，未知 HDR 颜色跟随实际仍为 0。

本包面向已经装好 0.3.5 维护线的玩家。核心更新文件是 addon、说明.txt、Collect-Feedback.cmd 和 collect-feedback.ps1，另附校验与来源清单。沿用原来的两个 DLL 和 nr_before_sr.ini，不需要重新下载大运行库。

beta0.4.2 是另一条实验线，请分开保留安装和配置。不要直接混合覆盖，再把结果当作同版画质对比。如果要从实验线切回，请先恢复维护线的安装和配置，再使用本更新包。

怎么更新

完全退出游戏，把原来的本插件 addon 备份到游戏目录外，再用本包 addon 替换。只留一份正在加载的本插件，不要把新旧版或中英文版同时放进去。

原来的 nrchain_nvngx.dll、nvngx_dlssnr.dll 和 nr_before_sr.ini 保留。把 Collect-Feedback.cmd 与 collect-feedback.ps1 一起放在 addon 旁边。不要把不同显卡完整包里的运行库互换。

进游戏后，在插件面板确认版本为 beta0.3.8。第一次安装或缺少运行文件的玩家，需要使用对应显卡的完整包。

这次修了什么

RDR2 的新反馈确认同一目录同时装了本插件和 renodx-dlss5.addon64。r3 会在句柄判断前识别这个准确模块，保留游戏原生画面并提示删除后重启。两套 NR 插件不能共存；普通 RenoDX HDR 文件不受这个准确文件名规则影响。

黑神话的新日志显示，低地址加载的 nvngx_dlssd.dll 让旧版三个生命周期 Hook 全部返回 MinHook 状态 9（内存分配失败）。r3 扩大安全中继搜索范围、验证 RIP 相对指令仍在可达范围并记录可读错误名，还会在首个 SR Create 之前立即预扫已加载模块。本地程序已复现旧错误、验证近距离 RIP 相对重定位，并确认不可达重定位会安全拒绝；黑神话实机仍待玩家复测。

r3 原本在设备初始化时看到内存开关为关闭，便延后命令签名观察。鸣潮 r3 的四份反馈包已确认：即使安装的 INI 写着 Enabled=1，启动观察数仍为 0；这个瞬时关闭状态的具体来源目前没有证据，不能武断归因于 INI 载入顺序。人物、UI、地图和雨天随后复用了无法追溯的 ExecuteIndirect 签名，插件便在 NR 帧与原生旁路帧间切换；雨天最后 1507 次原生 SR 中 NR 提交增长为 0。beta0.3.8 在设备创建时始终安装这一个轻量观察 Hook，不再依赖开关快照；空 PSO 与扩展图形状态 Hook 仍默认关闭。自动 WARP 回归已验证 NR 激活前观察到的签名以后仍可安全恢复。鸣潮、燕云和 0.3.7-r3 闪烁仍需玩家用 beta0.3.8 实机复测。

默认处理顺序没有改变：Mode 2 是“前置 NR → 游戏原生 SR”。只有手动选择 Mode 1，或旧配置本来保存 Mode=1，才会使用“游戏 SR → 后置 NR”。0.4.2 里的 NR 画质档位 / WorkMode 只决定 Feature 18 的工作分辨率，不会改变前后顺序。

孤岛危机 3 重制版的新包确认当前呈现 API 是 DX11，因此没有原生 D3D12 Feature 1 可供本插件接入。beta0.3.8 会在面板直接提示“DX11 不支持，需要 D3D12”，不再让玩家把等待 Feature 1 误看成强度或 HDR 问题。这个提示只看当前呈现窗口，不会被 D3D12 游戏里的辅助 DX11 设备永久误触发。

中文界面不再强行使用缺少中文字形的 ReShade 字体。若当前字体只能显示拉丁字符，插件名称保持可读英文，面板自动回退到英文并说明怎样在 ReShade 的“Overlay & Styling”里选择 zh-CN／系统默认字体或微软雅黑；换好字体并重启后会恢复中文。这能消除方块、问号等乱码，但不会替其他 ReShade 插件翻译文字。

针对《极限竞速：地平线》新反馈，稳定版恢复为不在空 PSO 命令状态中插入 NR，也不发布只为这条高风险恢复路径服务的扩展状态 Hook。反馈包没有崩溃转储，因此这是按版本回归面做的保守修复，仍需玩家实测确认。需要旧兼容实验的人可在配置中手动开启 ExperimentalNullPsoCarrier=1，并完全重启游戏；普通玩家请保持 0。

修正 DLSSNR.UICorrection 参数类型：运行库读取无符号值，旧版却写入有符号槽。新装默认开启“HUD / 文字保护（模型）”，已有明确的 0/1 设置不覆盖。它只有在游戏提供独立 UI 层时才可能保护界面，不能自动识别已经混入场景颜色的字幕和 HUD。

后置模式会保留游戏原始输出，再复制到自己的中间画面。修正了这一步的资源描述符建立方式，避免从不允许作为复制来源的描述符堆取数据。已通过模拟 GPU 检查，仍需要各游戏实测。

修正了旧配置强度被另一个模式的较大数值覆盖的问题；原来设成 0 的值会保留。状态提示也只在对应配置的实际调用后显示，不会把待应用或已经过期的记录当成当前状态。

游戏的光线重构（RR）正在接管画面时，F8 会收集截图、设置和日志，并说明为什么没有 NR 阶段图，不再为等不到的 NR 阶段图空等。

如果 F8 超时，仍未开始的阶段采集请求可以取消，让下次 F8 能重新尝试。此项不会强行中断已经开始的采集，不能把所有超时都当成已取消。

当前处于旁路时，面板优先显示旁路，不再被“设置待应用”盖住。你保存的设置不会因此丢失。

两项实验开关的说明更明确：光照匹配调整局部明暗，高光细节调整送入 NR 前的高光映射，都不负责解锁颜色跟随。颜色是否生效请看颜色跟随旁边的实际值和原因。

异环没效果的玩家先看这里

这次收到的异环日志明确显示：游戏启用光线重构后，由 RR 接管，本插件随即停止 NR。这是当前的安全旁路，不能据此判断 RTX 40 系列不支持，也不能说所有“没效果”都已修好。

要测试本插件 NR，请先关闭游戏里的光线重构（RR）。如果面板仍显示 RR 旁路，再完全退出并重启游戏后测试。这次没有更改这条规则。

怎么发反馈

停在能看清问题的位置，按 F8，或点“一键采集反馈包”。保持机位，等待提示完成。采集最多等待约 30 秒，之后还需后台打包；磁盘慢时保存会更久。

feedback.zip 通常在系统“文档”的 DLSS5-Feedback 里。文档目录无法写入时会尝试系统临时目录，以面板显示的路径为准，可直接复制路径。提示“部分未采到”的包也可以发。

包内有三张当前画面截图、能采到的 NR 阶段画面、画面信息、设置和日志。三张截图不是自动开关对比，程序不会替你切设置或自动上传。对比时固定机位，自己用 F6 开关 NR，每种设置各采一包，注明版本和开关状态。

发 ZIP 时请写清：游戏名、显卡型号、HDR 还是 SDR、遇到什么问题。效果偏弱、蜘蛛侠和鸣潮的画质、龙之信条 2 的崩溃仍需要新反馈，不要只凭“已应用”判断画面一定变强。

如果游戏无法启动，双击 addon 旁的 Collect-Feedback.cmd，collect-feedback.ps1 必须在同目录。把提示路径中的 feedback-offline.zip 发来。离线包只能收集已有信息，不能补回没保存的画面。
