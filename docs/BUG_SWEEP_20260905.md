### Lighting protection contract

The old `logRatio - localMean` can cross zero at a boundary because sparse
neighbouring ratios need not resemble the current pixel. The new target is
`clamp(logRatio - localMean, min(logRatio, 0), max(logRatio, 0))`, blended with
the original residual by LightingLock. This is attenuation, not a new sharpen
or tone-mapping pass. The four existing neighbour taps and colour/gamut/finite
and luminance-ratio guards are retained. The `neural == proxy`, zero strength
and invalid-input early exits are unchanged. Only the Mode-2 V2 composition
uses this correction; full post-SR composition is not modified.

### Face-control persistence

INI keys remain `AutoMask`, `SkinStructureStrength` and `UICorrection`.
Normalization is in memory; ordinary settings commits persist the normalized
preference through the existing writer. Mask off does not replace a saved
positive skin preference with the effective `-1` sentinel. The actual create
signature contains the effective value, so inactive preference changes do not
change that signature. Mask toggles still change the signature and use the
existing exact-fence feature-retirement path. Parameter slots remain float for
skin, signed integer for AutoMask and unsigned integer for UI correction.

### Hook publication contract

A successful `MH_CreateHook` owns a disabled trampoline. A subsequent failed
`MH_EnableHook` must not lose that identity and attempt duplicate creation.
Owned slot count and enabled state are now separate, under the existing per-
family publication locks. Only a successfully created local target is eligible
for retry. Failed enables back off for one second per target because MinHook
may suspend game threads; ready hooks do not republish or query the clock.
Recovery is logged once, without per-frame failure spam. No unknown
`MH_ERROR_ALREADY_CREATED` target is adopted. No native commands are recorded
until the existing state/admission rules allow them.

## Tests

Run on a host with Python 3 and a C++20 compiler:

```sh
python3 scripts/validate-bug-sweep.py --compiler c++
python3 scripts/validate-beta04-structure.py
python3 scripts/validate-beta04-result-resize.py
python3 scripts/test-beta04-math.py
```

The new suite extracts production normalization, feature-create signatures,
the bilingual face-control block, the scalar HLSL lighting block and the native
hook-publication functions. It does not substitute a separately reimplemented
policy. ImGui, scalar HLSL intrinsics and MinHook failure responses are host
adapters, not a GPU or driver oracle. Overlay registration is a structural
check, not a claim that its window has been visually tested.

Initial red runs reproduced the existing skin-state/UI failures, lighting
sign reversal and native enable-retry failure. After the changes, six test
methods pass, including 30,170 C++ checks. Most of these are deterministic
parameter sweeps, not distinct game scenarios. Existing structural, DRS result
surface and multiplicative HDR/guide math validators also pass locally.

The beta0.4.2 workflow now runs on pull requests targeting that branch. It adds
Linux and Windows execution of the new suite while retaining shader compilation,
Win32/native command-state, D3D12 WARP positive/negative controls, codec GPU,
static analysis and English/Chinese build checks. Consult the actual PR checks
for Windows results; this document does not predeclare them successful.
