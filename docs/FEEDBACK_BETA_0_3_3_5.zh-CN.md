# beta0.3.3.5 测试与一键反馈

遇到画质问题时，把镜头停在能看清问题的位置，按 **F8**，或在插件面板点击 **一键采集反馈包**。保持机位，等待采集和打包完成。面板会显示 ZIP 路径，并提供复制路径按钮。

F8 反馈包名为 `feedback.zip`，通常位于系统“文档”文件夹内的 `DLSS5-Feedback`，每次采集使用独立目录。如果无法在“文档”中创建目录，会尝试系统临时目录下的 `DLSS5-Feedback`；以面板显示的实际路径为准。采集最多等待画面和 GPU 阶段数据约 30 秒，之后后台打包；磁盘较慢时保存还需要一些时间。提示“部分未采到”仍可提交，包内会说明缺失原因。

游戏无法启动时，双击安装目录里的 **Collect-Feedback.cmd**。它与 `collect-feedback.ps1` 要放在一起，不需要管理员权限。离线收集器会在“文档”中的 `DLSS5-Feedback` 独立目录生成 `feedback-offline.zip`，包含可找到的日志、设置、系统信息和文件版本／校验值；缺少日志也会生成部分包。它无法补回崩溃前未采集的画面，不复制运行库文件或自动抓取转储。

提交 ZIP 时，再写一句：游戏名、问题出现条件、期望效果。若是开关对比，请分别在开、关状态按 F8，各提交一个包，并保持相同机位。HDR/SDR、前置/后置、自然/电影风格也分别采集，便于判断哪个变量引起变化。

## 包内有什么

- 当前设置下间隔约两秒的三张显示截图，使用 ReShade 已配置的图片格式；截图失败会记录原因。它们不是自动 A/B，采集器不会切换开关、模式或风格。
- 一次 NR 原图、代理图、网络输出、合成结果的同帧浮点数据。PFM 便于读取 RGB；RGBA 原始文件保留透明度与非有限数值。
- 该阶段采样时 GPU 实际读取及归一化的曝光值；输入输出格式、尺寸、jitter、运动向量比例和 Reset 的有界时间记录。
- 请求设置与最近实际合成的有效参数及限制原因、旁路原因、NR 成功和实际提交计数。没有当前有效记录时会标明未知或历史记录，不把滑条请求值当成已生效。
- 当前及前次 NR 日志、可定位到的 ReShade 日志与配置、加载插件和运行库的文件 SHA-256。
- `manifest.json` 与 `capture-info.txt`：每项是否取得、大小、校验值、缺失和截断原因。

文件只保存在本机，由玩家自行提交。不会自动上传、切换模式、改画质参数、收集其他目录截图或生成整个进程转储。日志和截图可能包含安装路径、游戏画面及叠加层内容。

## 数据应如何解释

四张 NR 阶段图来自同一次合成，可相互进行同帧分析；三张显示截图与它们有不同的帧身份，不能当作严格同帧对照。NR→SR 阶段图止于原生 SR 之前；只有后置模式的原图代表 SR 之后的输入。原始阶段处于不同颜色域，请按元数据解码，不要直接比较 PFM 数值大小。

阶段采集会创建新的 NR 历史，等待 64 次成功评估，再按真实 GPU fence 导出；这是采样等待期，不代表已经证明网络收敛。采集完成后历史会再创建。原始深度和运动向量纹理没有额外读回，包内会标明这一限制；资源格式、比例和 jitter 仍会记录。

本版修复了 ExposureTexture 无效值为 NaN 时未正确回退到单位曝光的问题。包含该路径、有效纹理／标量曝光和边界值的 54 个 D3D12 WARP GPU 用例已通过，并验证了阶段采集开关不会改变这些用例的合成输出。这证明了该曝光处理合同和测试覆盖路径，不等于所有动态曝光问题或蜘蛛侠人脸效果都已修复。

本版还包含异环空初始管线状态的兼容修复、参数实际生效提示和诊断采集。鸣潮／蜘蛛侠的颜色与细节、龙之信条 2 的崩溃仍需要相应游戏的新包复测；不以“NR 执行成功”代替画质结论。未知 HDR 合同仍保留颜色跟随限制。HD2 的特殊桥接继续延期。
