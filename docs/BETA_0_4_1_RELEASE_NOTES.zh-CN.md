# beta0.4.1 社区测试版说明

作者：@野生的装机宅 Bilibili · [官方发布](https://space.bilibili.com/941799)

本版从 `fee08f0` 的本地合并版继续开发，并完整合入 `973d22d` 的 0.3.6 维护修复。正式名称统一为 **beta0.4.1**。编译和自动回归验证的是代码行为；游戏观感仍需同场景验收。

## 不懂参数也可以这样用

1. 新安装默认使用“性能优先：NR → SR”、最终效果强度 1.2、颜色跟随请求 0.75 和默认 NR 画质档位。滑条显示的就是实际请求值，没有隐藏倍率。
2. 想减轻或加强效果，直接调“最终效果强度”；允许在 0 到 8 之间实验。已有配置中的明确数值（包括 0）会保留。
3. 想对比传统后置插件的观感，直接把处理模式切到“画质优先：SR → NR”。后置在完整输出分辨率运行，通常更费性能，效果不保证与其他插件相同。
4. 颗粒明显时，先提高游戏渲染采样或 NR 画质档位，再比较“细节稳定保护”关闭与开启。不要同时改很多设置。
5. 按 F6 关闭插件，得到游戏原来的 SR 画面。插件不会强制 DLAA，也不会改变游戏内的 DLSS 或 HDR 设置。

## 这次改了什么

- 首页保留启用、模式、最终效果强度、风格、反馈入口及 NR 画质档位。其余参数放进高级画质、HDR、兼容性和诊断折叠区。
- 新安装默认最终效果强度为 1.2，最高 8；新安装颜色跟随请求为 0.75。数值超过 1 会放大 NR 的变化，也可能放大低采样噪点。社区“本插件 1.2 接近某插件 1.0”的反馈只是对比线索，不是通用换算公式。未知 HDR 合同仍会把颜色实际值限制为 0。
- 新增默认关闭的细节稳定保护：将模型对明暗比例的修改分成较平缓和细碎的部分，降低局部不一致的细碎变化。原始游戏画面不做模糊处理。只在前置乘算链路使用；后置模式会明确显示不可用。
- 沿用曝光有效性、RR 接管时的反馈处理和旁路显示修复。模型 HUD／文字保护参数改用运行库实际读取的无符号类型；只有游戏提供独立 UI 层时才可能生效，无法自动识别已经混入 SceneColor 的字幕。
- 针对《极限竞速：地平线》从 0.3.3.5 开始出现的闪退反馈，默认不再尝试从空 PSO 状态插入 NR，也不发布只为这条恢复路径服务的扩展图形状态 Hook。反馈包没有转储，因此这是缩小精确回归面的保守修复，实机仍待验证。`ExperimentalNullPsoCarrier=1` 只供单变量兼容实验，修改后需完全重启游戏。
- 向安装助手提供本次进程的运行快照。只有同一配置、同一链路观察窗口内 NR 评估和实际提交增长，才报告运行生效。文件部署成功与运行生效分开显示。

## 保护和 jitter 的边界

细节保护目前只依据空间一致性、工作采样比例、近黑和极端亮度比例判断。没有可靠的逐像素深度历史时，运动保护显示不可用，不猜测人物移动或新露出区域。皮肤和界面修正使用现有模型参数，不代表有独立的人脸或 HUD 识别。

0.4 继续使用换算到 NR 工作网格的游戏像素 jitter；开发者可与“不传递”做对照。游戏原生 SR 的 jitter 不变。写入参数不证明运行库一定采用它，也不证明所有闪烁已经解决。

“超分之后缩小副本再做 NR”放在 `codex/post-sr-lowres-experiment` 单独研究，本版普通界面没有第三条链路。

## 新反馈的处理

- 新增独立的 `Collect-Crash-Feedback.cmd`。普通离线收集器继续不读取转储；崩溃模式从最新 ReShade 日志确认唯一游戏 EXE，只收集最近 72 小时精确匹配的已有 Windows 1000/1001 摘要、WER 和转储，并在清单中写出缺失和上限。它不会开启转储、修改注册表或上传。

`归档 2.zip` 中，《最后生还者 2》旧 0.4 r4 多次报告 `pipeline-unbound`，NR 提交计数为零。这类问题不同于画面效果偏弱。空 PSO 恢复现在默认关闭并安全旁路；仍需新版本游戏日志确认游戏是否能在有完整命令状态的帧持续提交 NR。

《鬼武者》附件内部标识比文件名所称版本更早。ReShade 退出时“仍有插件加载”的警告不能单独证明崩溃原因，不为消除这一行而拆除仍可能被调用的永久 hook。新版本仍无法启动时，请运行包内 `Collect-Feedback.cmd`，保留崩溃错误或 dump。

测试时分别观察：效果强弱、静态颗粒、周期闪烁、运动拖影、人脸与细线保留、帧率及显存。只改变一个条件，保留效果不佳的样本比口头描述“强了一点”更有帮助。
