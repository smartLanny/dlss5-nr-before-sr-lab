DLSS 5 AI 超分管理器 0.4.8-beta.1

先将完整 ZIP 解压到普通目录，再打开管理器 EXE。不要只复制 EXE。
安装版、便携版和完整解压版使用同一配套；界面默认普通权限与沙箱。

1. 在游戏库中点击“查看详情”。概览显示 API 对照与本次运行的四项验收。
2. 在“增强设置”选择 API、Core、运行目录和启动方式。NR / SR / FG 修改只暂存。
3. 点击“预览并应用”，核对文件与设置。组件准备包含在同一次应用中。
4. 游戏内 DLSS / FG 开关无法读取时，需要先开启游戏内选项、退出游戏并确认。
   确认只表明用户已开启；不表示驱动或增强实际生效。
5. Steam 游戏默认通过 Steam。管理器继续等待所选游戏进程；超时不会偷偷改用直接启动。

外置运行
DX11 / DX12 原生 DLSS 路线可选择每游戏外置目录，活动配置、Core、依赖和日志一起迁移。
外置助手使用本项目受限加载程序，参考 HoYoShade 的外置与就绪流程。
它只针对绑定的普通权限游戏程序和受管 ReShade，不结束游戏、不自动删冲突文件、不修改系统保护。
游戏保护可能拒绝加载；助手成功也不等于 NR 成功。Vulkan / Feeder 保留各自固定配套。

卸载与恢复
每次选择“干净移除”或“恢复安装前”，先看具体文件清单，再应用。
干净移除不会把旧代理放回游戏目录；原件与历史备份仍保留。
恢复安装前只使用有记录且摘要匹配的原件，未知 .bak 不会被当作原件。
清理剩余文件先做备份隔离；可从同一维护页撤销。
清理预览不改动文件或驱动；HDR、其他模组与来源不明 Add-on 默认保留，可逐项明确选择。
卸载和设置恢复完成后，可在维护页单独移出游戏库。
中途失败时先恢复未完成事务。已完成的阶段会明确保留，不能当作全部回滚成功。

权限与启动排障
若需要写入受保护目录，在变更预览中选择“以管理员权限应用本次操作”。
普通界面保持打开；只为该次已预览操作请求 Windows UAC。失败不会自动重试。
默认不要使用兼容启动；打不开时先运行“启动诊断.cmd”。“兼容启动.cmd”只用于临时排障。

当前实机边界
助手就绪 / Core 加载 / NR 成功并持续提交 / 同场景画面变化分别验收。
“记录本次画面对照”保存同场景开关观察及 F8 / ColorDiag 材料名称；来源标为用户观察。
TYPELESS 格式修复由独立 Add-on 线推进，本管理器不把加载成功当作格式兼容已修复。
BG3 DX11 提供 beta0.4.7 + Bridge 1.4.11 固定对照配套，来源为 issue #224 用户材料。
它保持 Core / nrchain / ReShade 不变，仅换桥；群友报告可进入游戏，仍需用户实机核对 NR 与画面。
默认配套仍保留原桥，管理器没有宣称 BG3 回归、米哈游 NR 或 RTX40 MFG 实机验收已通过。

反馈可在游戏详情维护页保存，包含分开的 API、启动会话与四层验收记录。
