# Manager 0.4.5-hotfix.1

本次只修复安装器。内置条目仍为 `0.4.5-DX11-兼容增强`，核心源码仍为
`dccb5b398ccc540723f84a6ef789dd70dbda5cd3`，不据此宣称 2K27 已通过实机验收。
安装器界面及文件名显示 `0.4.5-hotfix.1`，Windows 文件版本为 `0.4.5.1`。

## 用户反馈与证据

- 旧版截图报 `ERR_GAME_RUNNING`，手动游戏目录为 `D:\po`；截图没有被拦截进程清单，不能判断当时游戏是否真的仍在运行。
- 新版截图同时禁用了多个游戏的安装按钮，提示“安装组件未准备”，且没有列出缺失文件。
- 用实际发布载荷复现：保存的旧 DX11 条目 `0.4.2-dx11-native-bridge-exp1-r1` 已移除，后端正确回退到默认 `0.3.3.5` 并报告组件完整；旧前端仍优先读取失效设置，将 `ready` 改为 false。这与第二张截图表现一致，但尚无该玩家设置文件来确认其具体触发原因。
- 进程夹具证明旧守卫把游戏目录里的便携启动器及安装器自身子进程视作游戏。旧错误规范化又丢掉原始进程名，无法区分误报和真实运行中的游戏。

## 修复行为

- 已移除的保存版本回退到后端确认的实际条目，并显示回退提示。有效选择及游戏版本锁保持原有语义。
- 组件检查继续采用当前显卡族的实际校验结果。真正缺失、哈希错误或无法匹配显卡时仍阻止安装。
- 组件提示随版本切换刷新，不再要求玩家生成开发用 `bundle.json`。
- 进程判断通过 PID 关系和精确可执行路径识别安装器自身；仍拦截真实游戏、其他同目录程序和无法读路径但名称匹配的游戏/helper。
- `ERR_GAME_RUNNING` 显示检测到的进程名，反馈保留 PID/名称，以便下一次反馈有可核对证据。

## 玩家临时处理

旧安装包可先在“插件版本”中重新选择现有版本；需要新组件时选
`0.4.5-DX11-兼容增强`。便携管理器移到游戏目录之外运行，并关闭游戏。
若热修包仍报运行中，请提供报错中的进程名或“修复”页反馈日志。
不要通过反复确认反作弊提示来处理上述两类错误。

## 验证范围

Windows Node 回归测试覆盖旧版本迁移、显卡匹配、真实缺失/损坏、进程误报与保守阻断、反作弊确认、安装/修复/卸载夹具及 UI 契约。
发布前校验实际归档源码、组件哈希、安装器版本及 EXE 文件版本。
本次未在该网友电脑或 2K27 实机复现；照片所示问题仍需玩家使用热修版回测。
