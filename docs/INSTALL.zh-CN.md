# beta0.3.8-hd2-exp1 实验反馈版快速安装

按 **F8** 或在插件面板点击“一键采集反馈包”，保持机位等待完成。`feedback.zip` 通常保存在系统“文档”的 `DLSS5-Feedback` 中；创建目录失败时会尝试系统临时目录，以面板可复制的实际路径为准。部分数据未采到仍会打包并说明原因。游戏无法启动时，双击同目录的 `Collect-Feedback.cmd`；它需要 `collect-feedback.ps1` 配套，会在“文档”中生成 `feedback-offline.zip`，不需要管理员权限。

这是独立的 HD2 Feature 11 生命周期实验版，尚未通过 HD2 实机兼容验收。完整安装的核心载荷共 **7 个文件**；正式签名压缩包还会加入清单中列出的验证文件。请以面板、日志和文件属性中的 `beta0.3.8-hd2-exp1` 及 SHA-256 确认版本。采集只保存到本机，不自动上传或修改设置。

本版保留 ExposureTexture 非有限值回退、描述符、强度迁移和界面修复，并新增重复 NR 插件识别、低地址 NGX Hook 中继分配修复及首个 SR Create 前的模块预扫。地平线反馈没有崩溃转储，因此只确认启动风险面收窄；各游戏仍需实测。

插件名称：**DLSS 5 AI渲染超分版 beta0.3.8-hd2-exp1［Feature11 实验，兼容性待验证］**

作者：**@野生的装机宅 Bilibili**

唯一官方发布地址：[野生的装机宅 Bilibili 主页](https://space.bilibili.com/941799)。插件界面和二进制内均保留作者与官方地址。

## 适用范围

- 64 位 D3D12 游戏；
- 游戏本身必须调用原生 DLSS Super Resolution（NGX Feature 1）；
- 已安装允许加载 `.addon64` 的 ReShade / RHI；
- 仅限离线、无反作弊的环境。

DX11、Vulkan、没有原生 DLSS SR，或被 OptiScaler 等转换层完全接管的
游戏不属于此插件的直接适配范围。

## 安装

1. 完全退出游戏。
2. 打开 ReShade/RHI 当前实际使用的 **Addon 搜索目录**。如果没有单独
   配置，一般就是游戏真正的 64 位可执行文件和 ReShade DLL 所在目录。
3. 删除旧版 `nr-before-sr*.addon64` 和旧语言版。若存在准确文件名
   `renodx-dlss5.addon64`，也要移到游戏目录外；它是另一套 NR 插件，
   不能与本插件共存。普通 RenoDX HDR 文件不受这个准确文件名规则影响。
4. 把压缩包中的下列文件放在 **同一个目录**，不要把 DLL 与 addon
   分开：
   - `DLSS5-AI渲染超分版-beta0.3.8-hd2-exp1-@野生的装机宅-Bilibili.addon64`
   - `nrchain_nvngx.dll`
   - `nr_before_sr.ini`
   - 当前显卡完整包内的 `nvngx_dlssnr.dll`
   - `Collect-Feedback.cmd`
   - `collect-feedback.ps1`
5. 启动游戏，在 ReShade 的“插件”页确认界面顶部显示 `beta0.3.8-hd2-exp1`、实验性质、作者名和官方地址。

插件会从自身目录读取配置、桥接 DLL 和 NR runtime。因此，仅让 ReShade
看见 `.addon64`，但把其余文件放到另一个目录，会出现界面能打开、所有
功能却不生效的情况。

## 快速使用

- `F6`：总开关。关闭时应为纯游戏原生 SR，Feature 18 调用应为 0。
- `F8`：收集当前设置的三张显示截图、一次同帧 NR 阶段数据、有效参数及
  日志。三张截图间隔约两秒，**不是自动 A/B**；对比开关、链路或风格时，
  请自行切换后在同一机位分别采集。显示截图与阶段图不是严格同帧。
- 主键盘 `-`（小键盘减号也可）：直接截图。短文件名记录版本、链路、
  运行/旁路状态和请求配置号，以及 `I/S/B/C/HP`（NR 强度、风格、混合、
  颜色跟随、高光肩部实验）。完整分辨率、格式和参数写入同时间的日志，
  避免长游戏目录下截图因路径过长而失败。文件名描述请求设置；精确的
  NR 实例、应用配置和帧号以日志或阶段图元数据为准。
- 默认开启“使用渲染分辨率 NR → SR”：按游戏当前 DLSS 挡位的真实渲染
  分辨率先运行 NR，再交给游戏原生 SR。
- 关闭该链路开关：切换为 `SR → NR`，用于全输出分辨率高画质/性能对比。
- RR/光线重构活跃时，正式版会显示“RR 安全旁路”，不会叠加第二次 NR。
- 修改 NR 强度、风格、自动遮罩、皮肤或局部参数后，插件会在准确 GPU
  fence 后重建 Feature 18；短暂的预热/旁路帧属于正常安全切换。
- NR 强度建议先设为 1。当前原版 310.8 运行库在本插件使用的无外部遮罩
  路径上，1 → 2 不会继续放大模型效果；这与设置是否成功应用是两件事。
  本轮没有用额外暗化或对比度增益替代这个参数。
- `场景纸白缩放` 只调节 HDR 图像送进 NR 前的归一化；大于 1 会让模型
  输入更暗。格式 24 的 HDR 输入会先按 PQ 解码，再使用这一纸白尺度，输出
  时对称编码回 PQ。它不是最终画面亮度，也不是 NR 强度，建议先保持默认值 1。
- 高级选项中的高光肩部实验默认关闭，仅用于已识别 HDR 输入的对照采集；
  尚未证明能改善蜘蛛侠的人脸或 NR→SR 画质，正常测试请保持关闭。

## 报错时请提供

优先提交 F8 反馈 ZIP，并说明游戏、问题出现条件和期望效果。游戏无法启动时
提交离线收集包；缺少画面或日志的部分包也有助于定位问题。无法打包时，请提供
插件界面里的版本、当前状态/旁路原因，以及同目录下
`nr-before-sr.log` 中匹配问题前后的最小片段。beta0.3.3 会记录状态机、
延迟模块观察、颜色阶段归因、前几次诊断和稀疏性能摘要，不会逐帧刷屏。分享前请删除用户名、
绝对路径、账号、进程地址和运行库文件。

若 HDR 画面整体偏亮或偏暗，请在同一固定机位依次记录 F6 关闭、默认
`NR -> SR`、以及开启“实验性光照匹配”的 `NR -> SR`，每组停留约 15 秒。
不要同时改风格、强度或曝光；这样日志才能区分代理合同、NR 模型偏差和
最终合成偏差。

RTX 30/40 ShortFuse 完整包已经包含匹配的 `310.8.SF-v2` runtime，解压后
直接整体覆盖即可；不要再同时开启另一个 ShortFuse/RHI NR addon。

## 分发包内容

为方便直接覆盖安装，完整安装的核心载荷包含 **7 个文件**：插件、桥接 DLL、配置、
对应显卡的 NR runtime、本说明，以及离线收集器 `Collect-Feedback.cmd` 和
`collect-feedback.ps1`。正式签名压缩包另外附一套来源记录、签名清单、公钥和离线校验脚本，
用于确认载荷来自同一冻结提交；签名清单才是压缩包的准确文件清单。
发布页同时给出 ZIP 的 SHA-256。

## 参数与阶段诊断

面板区分请求设置、最近已应用的 NR 强度／风格和预热状态；颜色跟随及光照匹配
会显示当前有效值与限制原因，没有当前有效合同记录时标为未知。受限制的请求值
会保留，切回允许的模式后可恢复使用；未知 HDR 合同仍不会直接开放颜色跟随。
自然／电影或强度 1／2 的可见差异仍需按场景验证。

可选“采集一次 NR 各阶段”会在日志旁的 `nr-stage-captures` 输出四张原始浮点 PFM
和元数据，默认不运行。NR→SR 的采集不包含后续原生 SR；按 `-` 可另存显示截图，
按 `F7` 独立请求阶段图（同时只允许一个未完成请求）。
四张阶段图来自同一次合成，彼此同帧，但与显示截图不是同一帧证明。
阶段采集会重新创建 NR 历史，等待 64 次成功评估，按真实 GPU fence 导出后再重建；
这段等待不代表已经证明网络收敛。F8 会尝试将阶段数据一并收入反馈包。
请在固定镜头下每次只改一个参数，按包内元数据区分请求值、有效值和颜色域。
