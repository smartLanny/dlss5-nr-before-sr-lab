# Manager #180 · 普通 Content 目录候选扫描

本项与界面 #179 分开验收，接入同一个现用 Manager 候选。检查基点 `00f25dd` 已包含 `b4d1d44` 的共享载荷哈希去重/展示缓存、持久 worker、在途合并与 revision 防旧结果、Steam 封面目录索引、只读成功 IPC 静默。已检查本地所有可见引用，没有发现尚未整合的更新 Manager 性能提交。

## 本次修复

`createLibraryService.collectCandidates()` 曾无条件向 walker 传入 `includeContent: true`。普通游戏手动选择目录时，即使首次扫描已经找到运行程序，候选收集仍深入 `Content` 素材树。

改为沿用 GDK/Xbox 布局识别：只在根目录或直接 `Content` 目录发现 `MicrosoftGame.config` 时开放该树。探测只读这两层，不递归找配置；其他普通游戏按原 walker 规则跳过 Content。已提供的候选和用户明确选择的 EXE 仍然保留，未更改 worker 数量、并发量、轮询或缓存策略。

## 应用层计数与边界

隔离合成目录包含一个根 EXE、120 个素材子目录和 9,600 个素材文件；使用真实目录 walker，游戏/PE 扫描由隔离适配器提供，只测候选收集这一阶段。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 文件回调 | 9,601 | 1 |
| 目录读取 | 123 | 3（1 次 walker + 2 次固定 GDK 探测） |

没有将回调减少等同于物理磁盘读写字节减少。后续仍会做两层配置探测，并非完全不读取 Content。热缓存单次时间约 20.6ms→2.0ms，仅是该合成目录观察值，不用于承诺整机提速。

相关回归 **25/25** 通过，覆盖普通素材树、明确选择 Content 内 EXE、根目录配置标记、Content 配置标记、Unreal Engine/Plugins 寻根、保存根不向外扩大、worker 与刷新行为。完整候选回归及成品核对见维护交接。

## 本机进程观察与尚缺证据

在安装此补丁前的 dev.5，读取本机现用 Manager 的完整 4 进程树累计计数，12.2988 秒内合计 CPU 时间 140.625ms、逻辑读 182,776B、逻辑写 19,690B，主进程逻辑读写均为 0。原始记录在本地 `build/manager-dev5-process-sample.json`。采样没有强制空闲、控制用户交互或清理 OS 缓存；逻辑 I/O 包含缓冲和其他系统活动，不能当物理硬盘吞吐。

这次本机短样本没有出现持续占满一个核心，但不是原客人的故障现场，也不是补丁前后整机对照。仍缺原反馈版本、空闲/扫库阶段及 CPU/Procmon 采样；#180 保持开放，未判定历史卡死的唯一根因。
