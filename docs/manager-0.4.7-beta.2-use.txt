DLSS 5 AI 超分管理器 0.4.7-beta.2

开始使用
退出旧版管理器，再打开本目录的“DLSS 5 AI 超分管理器.exe”。保留整个目录及 resources 配套。
选择实际游戏 EXE；能够识别的 API 自动采用检测结果。例如 Steam 博德之门 3 的 bg3_dx11.exe 对应 DX11，bg3.exe 对应 Vulkan。下拉框的“DX11 桥接（自动）”就是已选用 DX11，无需再选一次。手工保存过的 API 仍会保留，可选自动恢复跟随检测。
点击一键安装后无需再点第二个“一键准备”。NR 参数在画面增强中；API 和核心版本收在安装配置中。超分补帧设置与适用组件的准备绑定，改变选项后自动处理。
绿色对号表示文件或配置检查通过；游戏是否实际采用、画质和帧率是否变化，仍需在游戏内确认。

维护、卸载与清理
游戏卡片和侧栏都使用同一个“维护与恢复”入口。
1. 修复当前安装：补齐并校验管理器组件，保留参数。
2. 恢复安装前状态：撤销管理器安装。安装前已有的 ReShade 或旧 Add-on 可能被保留或从备份恢复，因此不等于游戏原版。完成后会重新列出同目录仍存在的图形代理和 Add-on。
3. 尝试恢复干净环境：先撤销管理器安装，再列出所选 EXE 同目录的图形代理和 Add-on。确认名单后，先复制并校验备份，再隔离所选文件。
   历史 DLSS 5 / NR Add-on 会明确标出；来源未确认的代理 DLL 不会默认选中；识别到的 Microsoft 运行组件不能选择。
   第一步完成后关闭窗口，管理器配套也已经卸载；第二步确认前不会隔离外部组件。
   不处理 EXE、原生 DLSS、游戏数据、存档或着色器目录；这个有限范围检查不能保证游戏已恢复纯净原版。
隔离文件保存在游戏安装根目录的 _DLSS5_Backup/environment-cleanup 下，窗口显示实际位置。使用“撤销环境清理”可恢复原文件；备份仍保留，不自动清空历史备份。
如果清理中断，用同一入口恢复未完成环境操作。文件被其他程序改动、备份摘要不匹配或游戏仍运行时，会停止并保留文件与记录。
复制先写到专用暂存目录，校验完成后一次提交；中途退出不会把半个 DLL 放进游戏目录。异常退出遗留的 .part 仅是未提交暂存文件，不作为可恢复的完整备份。

埃尔登法环与 Feeder
无原生 DLSS 的 Feeder 试验配套提供成品帧 NR；不会给游戏新增原生 DLSS 超分或补帧，因此不显示不可用的调节项。
当前固定 Feeder 面向 RTX50、x64 DX12、SDR sRGB RGBA8。当前不支持 HDR、BGRA、x86、DX9/10 和 OpenGL Feeder。
这个 Feeder 固定使用 DXGI 加载入口；普通原生路线适用的 DXGI → D3D12 开关并不适用于它。
反作弊可能拒绝原有或新装的图形代理。卸载到安装前状态仍可能保留旧 dxgi.dll。环境清理用于排查外部组件，不会修改或绕过反作弊，也不保证解决 0xc000007b 等启动错误。

超分补帧
需要游戏本身具有对应原生功能，并在游戏内开启。RTX40 的 MFG Unlock 还需要 x64 DX12、已有 Streamline FG、符合配套要求的 DLSS-G 与 ReShade Add-on 支持。
改变超分补帧选项会自动准备适用配套，设置后需重启游戏。旧补帧套装需要通过已有迁移入口处理。

打不开或操作失败
优先在维护窗口保存反馈；未完成安装或迁移仍保留专用恢复入口。
默认普通权限与 Chromium 沙箱。需要写入受保护目录时，在“设置 → 启动与权限”选择“以管理员身份重启”。
“启动诊断.cmd”可在界面打不开时导出日志。“兼容启动.cmd”只用于临时排查已知沙箱启动问题；阅读提示后使用，平时直接打开原 EXE。
此版本的清理功能通过临时目录和模拟中断验证，未自动修改你的真实游戏文件。目标电脑启动、EAC 兼容和实际游戏效果仍需手测。
