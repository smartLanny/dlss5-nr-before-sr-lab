# Manager 候选的一次发布前审查

审查固定比较点 `b8785be..8fa5b3d`，覆盖新增运行库检查、现用 UI 与 Content 扫描；按用户 #191 升级要求读取 installer/manifest/OTA 及直接调用路径。此前外部 payload 摘要绑定与回滚审查不重复展开。本次按 runtime safety / functional contracts 两轴各执行一次，修复后只复查受影响代码和定向回归。

## P1：安装记录与新扫描 EXE 混用

复现：同根 A/GameA.exe 已安装后，扫描改选 B/GameB.exe。旧 repair 返回 complete 并向 B 追加组件，收据仍绑定 A；D3D12 模式下卸载按 B 重算 A 的 ReShade 目标，返回 removed 并移除收据，却留下 A/d3d12.dll。

修复采用共享的 manifest EXE 解析与一致性门禁。安装/修复/OTA/路由操作及直接 NR、默认设置、快捷键读写不能静默改绑。错误给出原相对程序路径；卸载根据原收据和逐条文件记录恢复，NR 文件恢复不依赖原 EXE 仍存在。独立 SR/FG 恢复记录继续执行其原有 EXE/所有权门禁。

为避免恢复逻辑重新引入猜测：新 D3D12 路由对借用的原代理也保留摘要和备份；旧版只有路由标志而没有来源证明时拒绝移动未知 DLL；两处入口同时存在则保留文件和收据，提示歧义；直接记录 d3d12.dll 的旧行不会误判为两个位置。历史 A/B 双部署的可验证文件按各自记录恢复。

## P2：旧保存回调抢先显示已保存

复现：1.2 保存尚在途，又排队了 1.8；第一个回调返回后显示已保存，实际 1.8 仍在 debounce 队列。修复用每游戏保存序号限制状态更新，旧失败仍给可读提示，最新成功清除错误样式。确定性回归覆盖旧成功、旧失败、不同字段、乱序完成和跨游戏独立性。

## P2：Core-only 包错误类型误导

实际读取支线 dev10 D3D12 Core-only ZIP，旧解析器因 build-info/SHA256 文件名相同，误报 unsupported DX11 OTA metadata。现在给出专门中文包类型说明并拒绝导入，错误码穿过 app-service 到 UI；没有把 Core-only 验收包升级为受信任的 Manager OTA，也没有加入新的 carrier profile。

## 读取失败的界面处理

新增 EXE 门禁可能使 NR/快捷键读取失败；原 Promise.all 会同时隐藏可用的安装诊断。当前一次 allSettled 独立处理三项结果，保留过期结果守卫。失败编辑器禁用并显示原因，成功重读恢复能力；诊断仍可见，快捷键失败不伪造已读取 Home。未增加重复磁盘诊断。

## 验证及限制

P1 和相关路径定向 96/96、0 skip；OTA 与 NR 保存专项 36/36；隐藏 Electron 隔离 IPC 交互覆盖 124 条断言。完整候选回归、包内源码和安装身份最终结果见维护发布交接。修复前失败与修复后通过分别保留为本地证据。

这些检查不替代真实游戏/驱动/新 carrier 验收。Vulkan 仍未接入；任意无收据旧 DLL/bak 的自动迁移不在已完成范围。按照用户选择，公开发布继续等待关联核心任务的正式交付，并先核对实际新包是否具备 Manager 更新合同。
