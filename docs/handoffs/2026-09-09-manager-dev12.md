# Manager dev.12：Vulkan 选择状态修正

Manager `0.4.6-hotfix.7-dev.12` / Windows `0.4.6.12`，接续 dev.11 的 `9b28c82`。

用户在自动检测为 mixed 的终末地卡片中选择 Vulkan 后，Core 正确显示 beta0.4.7，
但状态仍提示“当前游戏路线不是已确认的 Vulkan”，同时允许点击“应用并安装”。
原因是 API 选择保存在尚未应用的草稿中，配套提示却读取已保存路线的 `available`。

## 修正

Vulkan 服务分别报告配套可选择状态 `selectionAvailable/selectionReason`，
以及当前已保存路线的 `available/reason`。配套选择不依赖先保存 Vulkan，
仍遵守资产、显卡、位数、路径和恢复状态限制。正式安装继续要求明确的 Vulkan 路线。

选择区域、应用按钮与折叠的一键安装按同一配套状态判断。
未应用的 Vulkan 选择可显示“可准备”；缺少资产或设备不匹配仍显示具体原因并禁用提交。
API 与 Core 仍一次应用，选择时不提前写偏好或安装文件，已有不同路线仍须先卸载。
未安装的待确认说明改为“等待应用 API 与核心”，避免下方继续要求重新确认已有选择。

## 验证边界

- Vulkan 服务和联合应用业务测试 26/26 通过，覆盖 unknown/mixed/DX12 的未应用选择与真实硬限制。
- 本次 UI 单元测试 19/19、Electron 联合应用交互 37/37 通过：mixed/unknown 的选择前、尚未应用与安装成功状态一致；真实硬限制即时禁用按钮且不发送应用请求。卡片主体和选择时的零 IPC 行为保留。
- 原卡片操作 14/14 通过；最终说明文案调整后，37 项联合交互再次通过，并检查了尚未应用的实际渲染截图。
- 本机终末地 EXE 与已安装 047 资源只读核对：旧路线为 mixed 时配套可选择，模拟选择 Vulkan 后当前路线就绪；无游戏启动、配置修改或注册表写入。
- Core、Feeder、运行库及其配套清单与 dev.11 完全相同；沿用该二进制组合已有的 600 帧受控验收，不重复启动 NVIDIA 测试。
- 本修正不证明终末地支持 Vulkan，也不自动修改该游戏的实际渲染 API；真实游戏验收仍以用户实际运行反馈为准。

完整 dev.11 配套来源与既有验证见 [dev.11 交接](2026-09-09-manager-dev11.md)。
