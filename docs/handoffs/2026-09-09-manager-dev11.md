# Manager dev.11 修复交付

Manager `0.4.6-hotfix.7-dev.11` / Windows `0.4.6.11`。
普通 DX12 / DX11 默认 Core 使用 `0.4.7beta`，显示为 `beta0.4.7`。
普通列表由它取代 0.4.6，保留实际 PE 版本为 `0.3.3.4` 的稳定兼容项及历史内部 ID。

## 修复行为

- 生化危机安魂曲：在 Steam 应用身份和根目录 `re9.exe` 匹配时，根据官方 DX12 要求识别 API。大于 512 MiB 的真实 EXE 使用有界 PE 头读取，不被大小阈值排除。REFramework 的 `dinput8.dll` 不作为游戏渲染 API 证据。
- RE 引擎：读取 `re_chunk_000.pak` 的 KPKA 文件头等独立本地证据。发行商、游戏标题、Steam ID 或 EXE 名称单独出现不作为引擎证明。识别到未知 RE 游戏时说明检测结果；只有已实现的精确配套才自动准备 REFramework。
- 精确配套覆盖鬼武者、安魂曲、龙之信条 2、怪物猎人荒野与街头霸王 6 的受支持入口。SF6 使用根配置和加载器；不会创建、读取或接管无关 `_storage_` 配置与 Core 镜像。其他指定配套按固定官方版本的缓存规则处理。
- 游戏卡片标题区显示实际 EXE 路径。D3D12 与 RE 兼容操作在同一行并列，适用说明默认折叠。保存 API 后恢复同一卡片位置和按钮焦点，异步配置加载不会把视图推走。
- BG3 手动添加 `bin/bg3_dx11.exe` 时，用其在已发现 Steam 安装中的精确完整路径保留入口身份，添加窗口与保存后的刷新均自动识别 DX11。`bin/bg3.exe` 保持 Vulkan，两者独立，API 选择不切换 EXE，也不改写用户已显式保存的 API。
- API 与 Core 在同一区域选择，一次应用。所选 Core 显式随请求传给安装/修复，不再因单独保存 API 刷新而丢失。原有 native/Vulkan 安装跨路线时仍须先卸载，不能覆盖另一配套。
- RDR2 在精确 Steam 身份下读取 Windows 当前文档目录的 `system.xml`，提供自动、DX12、Vulkan。主进程将真实文档目录传入扫描工作线程，支持目录重定向。用户显式选择时同步单个 API 设置；自动跟随游戏当前保存值。
- RDR2 同步要求游戏关闭，先保存原配置字节，再原子替换 API 文本。其他 XML 内容、编码和 BOM 保留；插件应用或偏好保存失败时回滚。回滚发现外部修改会保留外部版本并报告失败。配置不可读时明确保留原有手动路线，不宣称同步成功。

## beta0.4.7 与桥接器

普通 beta0.4.7 Core `b7bef0c7…` 与既有 `4656d9…` DX11 carrier 都使用 `NRNativeBridge_QueryV1`。
双方 ABI 头逐字节相同（SHA256 `fe5dd176…`），ABI 为 `0x00010000`、WINAPI 签名、24 字节状态结构。
因此此前“仅原生 DX12”的界面限制已移除，047 目录纳入原 carrier；DX12 不部署该 carrier。
真实资源的临时安装/诊断/卸载验证：DX11 Core/carrier/nrchain 摘要相符，DX12 使用同一 Core/nrchain 且不安装 carrier，两路原有 INI 字节保留。

原始 047 二进制没有 Vulkan Feeder 所需的四个 `NRExternalProvider_*V1` 导出。
独立 Vulkan Core 从真实 047 源线构建，新增外部提供器接口和 canonical IUnknown 设备身份校验，保留 047 算法、菜单与默认配置。
构建来源 `4ecc6d02ca6058cb1ebb0faae5aa49b34b0614ad`；中文 Core SHA256 为
`93011d9283615ea9dc8e92955f5ca6aeff01435925f63e941dc1eea1128a372c`。
Manager 的 Vulkan 配套编号为 `nr-vulkan-047-20260909`，真实 Core 版本 `0.4.7beta`，界面显示 `beta0.4.7 · Vulkan 桥接`。
原生与 Vulkan 的 Core 二进制不同，由管理器按路线选择；桥接器仍要求匹配的 ABI，不能推论可配任意 addon。

该中文 Core 使用既有已固定摘要的 Feeder 与 nrchain，在 RTX 5090 Laptop 的独立 Vulkan 场景完成 600 帧。
生产打包门禁核实 NR 实际处理、同帧完成、输出变化、正常退出（OS exit 0）及 HKCU/HKLM 注册项前后相同。
生产配置仅关闭验证 trace，并使用通用深度默认值；这些与前向深度受控场景的差异逐项记入 recipe。
本轮新验收独立于旧 R5，仍标记 `scope=controlled-renderer`、`realGameVerified=false`。

## Vulkan 启动崩溃

用户 BG3 两次启动的转储确认同一 `c0000409` / fast-fail 参数 5。
固定 Core 在 DllMain 日志轮转中调用 `wcscat_s`：实际模块路径受 Windows 应用目录映射影响达到 292 字符，
日志目录含尾斜杠 235 字符，追加 `nr-before-sr.previous.log` 与结尾 NUL 后需要 261 个 WCHAR，超过 260 元素的缓冲区。

运行目录缩短为 EXE 摘要前 16 位 / 配套指纹前 16 位，完整身份仍保存在收据和绑定中。
完整摘要不一致或前缀碰撞会拒绝覆盖。准备和启动前检查请求路径及真实 Windows 路径，涵盖所有固定资产和轮转日志。
旧目录格式继续支持检查、日志取证和归档恢复；超长旧配套只允许恢复，并提示点击“卸载插件”后重新安装。
短路径修复与 Core 版本独立；原有 R5 的历史验收声明保持原样。
