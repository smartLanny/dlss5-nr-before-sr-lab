# Manager 0.4.8-beta.2：展开设置与实测入口

基于 `e9517524d6d1f8751b9a6ab709d02613e32e6967`，在 `codex/manager-048-beta2-20260910` 实施。Manager 版本为 `0.4.8-beta.2`，Windows buildVersion 为 `0.4.8.2`；Electron 保持 `44.3.0`，既有 Core、Bridge 和其他固定组件版本不变。最终构建由主流程统一输出至 `dist-beta0482`。

## 本批行为

- 游戏卡片向下展开，分为“安装与画面”“超分与补帧”“高级与维护”。先看 API 和兼容性，再安装；复杂诊断与桥版本对照放在高级区域。API 未确定时明确要求手动选择，并阻止错误应用。
- 新游戏显式预选本机推荐模型：RTX20/30 → K，RTX40/50 → M；默认 `quality:preserve`，只改模型，不附带改 DLSS 档位、输入比例或 FG。未知或混合显卡保留游戏控制。已有保存请求、已应用请求及明确的旧模型选择优先。
- 不新增持久化请求枚举，继续提交 K/M/L；已有 `preset:auto` 保留按 DLSS 档位解析的语义，避免正在使用 beta.1 的用户遇到共享配置读取失败。高级手选保留；模型短标签为“K · 老版兼容”“M · 平衡选择”“L · 4K 优化”。
- 确认状态只在真正等待游戏开关确认时提供入口。与当前 EXE 内容和功能域匹配的确认持久化后，不再反复显示确认提示；EXE 改变或读到关闭状态时失效。
- DX11/DX12 支持从原 ReShade 的默认或自定义 Add-on 目录直接建立外置配套，按游戏维护活动配置、组件、依赖、日志与恢复记录。首次安装使用代理，安装后可切换助手；Vulkan/Feeder 保持固定布局和所有权。原自定义配置位置在迁移前核对，不覆盖未知文件；自定义目录的直接外置安装可独立卸载恢复，迁到尚未适配的普通目录会在预览时阻断。
- 改动先暂存，统一预览并应用。打开、刷新和启动前检查不自动覆盖驱动设置；中断恢复、两类卸载及外部修改保护继续保留。

按显卡默认是本工具的初始选择。NVIDIA 的 Recommended 按档位选择 M/L/K：M 优化 Performance，L 主要优化 4K Ultra Performance；20/30 系使用 M/L 有更高开销，K 是第一代 Transformer。没有采用“L 在所有情况下画质最好”的表述。[NVIDIA 官方说明](https://www.nvidia.com/en-us/geforce/news/dlss-4-5-dynamic-multi-frame-gen-6x-2nd-gen-transformer-super-res/)

最终发行身份和打包验收以交付目录中的 `release-manifest.json`、`SHA256SUMS.txt` 与 `验收记录.txt` 为准，分别记录源提交、最终 Electron 界面断言、普通与兼容启动、便携启动、安装/便携/完整 ZIP 的内容一致性和文件摘要。完整回归针对冻结候选；上述两个 UI 修复由后续实际 Electron 回归覆盖。没有复用 beta.1 的验收结果。

版本准备仅更新包版本、buildVersion、说明入口和构建目录忽略项。`product.json` 没有 Manager 版本字段。现有 `verify-manager-release.js` 从可信源 `package.json` 比较版本，接受目标目录参数；归档核验脚本同样使用参数，未发现 beta.1 版本或 `dist-beta048` 路径硬编码需要修改。

本批自动验证使用隔离目录、测试进程和受控驱动适配器；不修改真实游戏、驱动或用户配置。真实受保护目录 UAC、安装版实装和原故障电脑启动仍需独立验收。

## 用户实测与后续范围

1. 本机 RTX5090 Laptop 可先测 2077：固定同一 Core、画质和场景，外置图形代理 → 完全退出 → 外置助手。逐项记录 Ready、当前 Core 加载、NR 成功/提交增长和同场景画面对照。
2. BG3 使用 `bg3_dx11.exe`，先固定 `0.4.7beta + Bridge 1.4.11` 配套，再比较代理和助手；桥版本对照单独一组。进入游戏不等于 NR 或画面验收通过。
3. RTX40 MFG 由另一台 40 系机器验证：已有原生 Streamline FG 的 x64 DX12 游戏，完整 Add-on ReShade 和可验证的现代 DLSS-G。普通 2× 基线后请求 3×，分别测试 NR 关闭/开启，并收集 MFG 面板和实际呈现遥测。

米哈游 TYPELESS 修复由独立 Add-on 线推进，HDR 成功和助手 Ready 均不替代 NR 证据。DX9/DX10/OpenGL 桥接仍属于后续实现与实机矩阵，本批不宣称完成。RTX40/RTX50 补帧与 NR 共存、BG3 和米哈游的实际结果均待各自记录确认。

测试结束后先退出游戏，恢复未完成事务，再按预览撤销 SR/FG 覆盖或选择干净移除/恢复安装前。失败反馈需绑定同一游戏会话、EXE、Core、活动路径和日志。
