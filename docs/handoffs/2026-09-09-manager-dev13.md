# Manager dev.13：Vulkan 启动权限预检与失败恢复

Manager `0.4.6-hotfix.7-dev.13` / Windows `0.4.6.13`，接续 dev.12 的 `12f56d3`。

## 已确认的原因

Endfield 的 EXE 清单为 `requireAdministrator`。Vulkan 普通权限 broker 在首次安装时
返回 `GAME_LAUNCH_REQUIRES_ELEVATION`，测试尚未进入 ReShade 或 NR 运行阶段。

旧调用顺序先发布外部运行目录并保存 `phase=prepared` 的绑定，再调用加载层部署的启动预检。
因此预检拒绝后留下未完成绑定；后续应用返回 `VULKAN_RECOVERY_FIRST`。
API 偏好已经按失败事务恢复为 DX11，而反馈又把尚未激活的绑定写成“已部署 API：vulkan”，造成误导。

## 修正

- 选择阶段读取 EXE 权限清单，要求管理员权限的程序明确显示当前 Vulkan 路线不支持。
- 安装前完整执行 broker 预检，成功后才发布运行目录和保存绑定。加载层部署仍在自己的写入边界再次核对启动环境。
- 预检失败不会留下 profile、绑定、加载层或激活状态；真实写入中断继续保留可恢复记录。
- 即使 API 偏好已回滚到 DX11，未完成 Vulkan 绑定也优先显示恢复入口，不显示可启动状态。
- 反馈将未完成的 Vulkan 配套写为“Vulkan 准备未完成”；完整就绪才报告已部署。

## 验证与本机恢复

Vulkan 服务、启动 broker 与部署测试 50/50 通过；UI 与反馈测试 23/23 通过。
额外应用服务 Vulkan/路由组合 30/30 通过。预检回归覆盖强制管理员、普通权限 token 无法确认、零写入，
以及环境修正后的直接重试；旧长目录恢复仍通过。

本机仅通过既有恢复流程归档 Endfield 的 prepared profile 并清除绑定。
确认没有加载层收据、部署 pending 或游戏 ReShade.ini；恢复前后 HKCU/HKLM Vulkan 注册项逐项相同，
游戏 EXE 与管理器设置摘要相同，用户选择的 DX11 保留。没有启动游戏，没有修改游戏权限清单。

本版不增加管理员 Vulkan 路线，不写入机器范围的新加载层。
Core、Feeder 和运行配套与 dev.12 相同，不追加 NVIDIA/真实游戏验收。

既有配套来源见 [dev.11](2026-09-09-manager-dev11.md)，选择状态修正见 [dev.12](2026-09-09-manager-dev12.md)。
