# Manager 0.4.7-beta.2 手测反馈修订

本候选收敛一键安装后的重复按钮，把修复、恢复安装前状态、备份隔离外部组件放进同一个“维护与恢复”窗口。超分补帧选项负责适用组件的准备；无原生能力的游戏只显示能力说明，并保留已有设置和事务的恢复入口。

恢复安装前状态可能把历史核心重新放回游戏目录。现在卸载结果返回恢复的原文件清单，主进程重新检查所选 EXE 同目录的图形代理和 Add-on，窗口列出残留。测试覆盖用户指定的 DLSS5-AI渲染超分版-beta0.4.6-hotfix.1-@野生的装机宅-Bilibili.addon64：安装冲突隔离、卸载恢复、环境清理隔离、撤销后原字节一致。

环境清理先恢复管理器受管组件，再展示具体文件确认名单。只在所选 EXE 同目录操作有限代理名称和 Add-on 扩展；已识别 Microsoft 运行组件不可选，未知代理不默认勾选。文件先复制并校验 SHA-256，随后隔离；环境备份与恢复记录保存在安装根目录的 _DLSS5_Backup。事务绑定目标 EXE、PID、允许路径和前后摘要；遇到外部修改、备份损坏或其他归属事务时保留文件和记录。撤销后保留历史备份。本功能不声称校验了完整游戏或清除了所有模组。

独立检查发现“复制未完成即进程退出”的恢复阻断，最终版本已修正。所有复制（含环境事务回滚）先写 environment-staging/UUID.part、校验并同步，再通过 Windows File.Move 原子提交到不存在的目标；只有经过验证的管理器 JSON 恢复使用 File.Replace。未提交的半文件不出现在活动 DLL 或已确认备份路径。环境恢复由自身事务归属逻辑处理，不再调用会直接覆盖复制的通用恢复。

实际 Elden Ring 反馈确认了另一语义问题：原有 dxgi.dll 被 Feeder 复用，卸载本次安装仍保留原加载器，EAC 仍可能拒绝它。现明确提示。没有修改 EAC、游戏 EXE 或进行绕过，也没有把 0xc000007b 宣称为已修复。

BG3 检查：本机真实 bg3_dx11.exe 的选择预览和库刷新均自动解析为 DX11；bg3.exe 解析为 Vulkan。所运行 beta.1 的 api-evidence.js / library-service.js 与本树原有代码字节相同。仅在内存中去除手工 API 覆盖后复测自动结果，没有修改用户设置或真实游戏。用户最初看到的具体界面状态尚未确认，不能宣称复现并修复了该报告。

验证记录位于 build/beta2-*：
- 最终整套测试 831 项：828 通过，3 跳过，无失败；其中环境测试 24 项，包含半复制、反复恢复中断与最终删除事务记录失败。
- 三个隔离 Electron 界面检查通过：游戏卡片、超分补帧、维护窗口。包含双击抑制、隔离前确认、未知 DLL 不默认选择、撤销失败保留入口、残留历史 Add-on 显示。
- 发行目录对照源码与固定运行库的 284 项文件验证通过。
- 打包主程序以普通权限完成正常及兼容启动检查；额外无注入真实普通启动通过，使用独立空白配置目录，未触发游戏或驱动写入。
- 并行压缩/测试期间曾有一次受控启动未在时限内回报，日志止于 state-store-opened。未改源码的顺序重试通过；保留该失败记录，不把它计作通过或声称已查明原因。
- Setup 和 portable 内嵌的 175 个实际文件与解压版一致；未执行 Setup 安装。
- 完整 ZIP 的 175 个文件逐项 SHA-256 与解压版一致。

旧 beta.1 发行目录保持冻结。最终候选位于独立工作树 manager-beta2-manual-feedback-20260909 / dist-beta2-final；dist-beta2-release 是未交付的中间检查包。真实游戏清理和另一台电脑的残留仍由用户手动验收，本轮没有操作真实游戏目录。
