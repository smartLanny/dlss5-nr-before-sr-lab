协调代理负责主进程接线、基线对照、问题整合、提交与最终验证。明确范围的采集、归纳、实现和测试任务使用 `gpt-5.6-luna`、`max`；子代理不继续委派。

| 工作流 | 范围 |
| --- | --- |
| CI 与收包验证 | 读取 #244 与父提交的 Actions 结果；Windows 离线导入、重复与冲突统计、只读驱动清单。 |

## 已确认的问题

1. 云端两个 Actions job 尚未运行任何步骤。检查注释说明账户付款或 Actions 支出额度阻止启动，父提交的 job 同样失败；workflow、依赖和锁文件没有发生 PR 差异。因此不能把云端红灯当作测试断言失败，也不能把它算作已通过。
2. 原 PR 在启动前无总时限地等待反馈元数据。已增加短时限，超时继续正式启动，并取消晚到快照的发布，防止把启动后的数据标成启动前证据。
3. 父版本的 HoYo 原生路由测试未指定其已准备的 DX11 配套，错误选择缺少 carrier 的默认稳定夹具。父版本与 PR 同条件复现 `DEPLOYMENT_PACKAGE / carrier`；本地只修正测试的版本选择，不降低生产载荷验证。
4. 文件保存对话框返回后再次校验反馈预览和当前身份；选择路径期间改动配套或会话时拒绝写入。已有同名文件保持原样并给出明确提示。
5. Windows 的目录链接测试采用真实 junction 验证拒绝路径，保留生产检查；原 Electron 夹具只统计真正原厂控制器创建，避免组合适配器让计数重复。

## 合并双方语义

- 云端 HoYo 外层工作流持有反馈入口，覆盖已绑定客户端的安装失败、等待和恢复状态；嵌套设置页不重复挂载。
- 本地保留卡片离开工作区时关闭旧反馈的生命周期保护，以及启动采集取消与代次检查。
- 云端保留不完整原因、游戏/配置位置/版本身份，以及缺 EXE 或未绑定渲染 GPU 时的分组隔离。
- 本地保留读取失败与成功返回空组件列表的区别；缺失元数据不能发布或复用精确启动快照。
