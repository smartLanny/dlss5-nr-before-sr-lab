## 已确认的问题

1. 云端两个 Actions job 尚未运行任何步骤。检查注释说明账户付款或 Actions 支出额度阻止启动，父提交的 job 同样失败；workflow、依赖和锁文件没有发生 PR 差异。因此不能把云端红灯当作测试断言失败，也不能把它算作已通过。
2. 原 PR 在启动前无总时限地等待反馈元数据。已增加短时限，超时继续正式启动，并取消晚到快照的发布，防止把启动后的数据标成启动前证据。
3. 父版本的 HoYo 原生路由测试未指定其已准备的 DX11 配套，错误选择缺少 carrier 的默认稳定夹具。父版本与 PR 同条件复现 `DEPLOYMENT_PACKAGE / carrier`；本地只修正测试的版本选择，不降低生产载荷验证。
4. 文件保存对话框返回后再次校验反馈预览和当前身份；选择路径期间改动配套或会话时拒绝写入。已有同名文件保持原样并给出明确提示。
5. Windows 的目录链接测试采用真实 junction 验证拒绝路径，保留生产检查；原 Electron 夹具只统计真正原厂控制器创建，避免组合适配器让计数重复。
6. 原主进程隔离夹具未注册新反馈服务，导致 35 项依赖初始化的测试失败。已按现有业务 mock 模式接入，并增加五个反馈 IPC 的 sender 与参数转发覆盖，未放宽生产构造或原有断言。
7. 启动记录返回 `record-unavailable` 对象时，也记录 `SESSION_RECORD_UNAVAILABLE`；`null` 仍代表没有会话，手动反馈和技术 unknown 不变。
8. ZIP 写入、同步或关闭失败时，仅清理由本次创建且身份仍匹配的文件，保留被外部替换的路径；已有同名文件始终不覆盖。
9. 离线报告在同目录临时文件完整写入、同步和关闭后，以不覆盖的硬链接原子发布，避免半份 JSON 占据不可变 reportId。临时名碰撞不删除原文件；不支持硬链接时明确失败，可改用本机 NTFS 私有目录。
10. 重新打开反馈时清除上次切换客户端的旧提示。同一客户端的刷新不会误关弹窗或丢失草稿。
11. 新工作目录的 CRLF 转换破坏固定资源和加载助手源文件的原始哈希。已在 `.gitattributes` 禁止转换，恢复 manifest 所要求的 LF/CRLF 原字节；15 份资源提交仅改变行尾表示，没有文本内容变化。22 份受约束的已跟踪文件均验证 Git blob、磁盘字节和固定哈希一致。
