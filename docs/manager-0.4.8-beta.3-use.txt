DLSS 5 AI 超分管理器 0.4.8-beta.3

先退出旧管理器。完整 ZIP 请全部解压后运行；便携 EXE 可单独运行。
管理器默认普通权限和沙箱；受保护目录的已预览操作按需单独请求 UAC。
管理器版本为 0.4.8-beta.3，当前 Core 基线为 0.4.7beta，Feeder 为 0.15.1；三者版本号不同。

开始使用
1. 选择实际游戏 EXE，展开游戏卡片，核对图形 API、位数和显卡。
   “自动”跟随独立检测结果；无法确认 API 时，先选择游戏实际使用的 API。
   dxgi.dll、d3d12.dll 等加载入口文件名不会把游戏切换成另一种 API。
2. 在“安装与画面”选择配套及 NR 设置，在“超分与补帧”选择游戏已有功能的覆盖。
   改动先暂存，再预览并应用。打开或刷新页签只读取信息。
3. 完全退出游戏后应用。检查“高级与维护”中的实际加载目录和组件清单，再启动游戏。
4. 新安装默认按 = 打开 ReShade 面板（KeyOverlay=187,0,0,0，不带 Ctrl／Shift／Alt）。
   已有明确自定义按键保持原样；在“高级与维护”点击“恢复默认 =”可改回默认键，重启游戏后生效。

安装位置与加载方式
普通游戏默认使用游戏目录；已有安装保留原部署方式。普通原生 DX11/DX12
可选择每游戏外置目录，当前界面先完成代理安装，再切换到外置加载助手。
HoYoShade 模式首次就直接建立外置目录并使用加载助手，无需先装游戏目录代理。
常规 Feeder 使用 EXE/_DLSS5_Feeder15 专用目录；Vulkan 保留既有独立配套。
修复会保留已安装的固定配套，不会把旧 Feeder 0.13.1 隐式升级为 0.15.1。
历史 Feeder 0.13.1 保留其原有配置；各路线已经明确设置的 ReShade 自定义快捷键均保持原样。
跨代更新需要明确选择完整新配套；不能只混换 provider、宿主或 Core 中的一个。

Feeder 0.15.1 的路线
- DX9：x86、x64，使用本项目自编入口调用 Windows 系统 D3D9On12，再由 x64 宿主运行 NR。
- DX10：x86、x64，使用共享纹理接入 x64 宿主，包含纯 D3D10.0 路径。
- DX11：x86 使用 x64 宿主；x64 在游戏进程内处理。
- DX12：x64，在游戏进程内处理。
DX9 仅提供本地入口，不提供 HoYoShade 组合。OpenGL 不在本次 Feeder 配方矩阵中。
上述路线为使用游戏颜色、深度和 VORT 运动估计的后处理 NR；不会为原本不支持的
游戏注入原生 DLSS 超分或原生帧生成。当前受控验证针对 SDR，画质仍按具体游戏核对。
RTX40 与 RTX50 使用各自的 NR 运行库，不能互换；x86 游戏的宿主和 NR Core 仍是 x64。
DX9 游戏面板提供“装机宅 DLSS 5 · DX9 回填”的独立总开关，便于同场景开关对照。
取消“启用 NR 回填”后停止向 NR 宿主提交和写回；重新启用会重新建立当前帧历史。
此开关独立于 ReShade 的全局效果开关，关闭全局着色器效果不等于关闭 NR。
完整 Core 参数仍在管理器的“安装与画面”中调整，退出游戏后应用；不会在32位游戏面板中显示64位宿主的完整 Core 面板。

DX9 的替代方案
本版不携带 dgVoodoo。官方 2.87.4 下载在更新 Defender 规则后仍被检出，且其条款
限制通用框架捆绑，因此改用自编入口与 Windows 已有的系统 D3D9On12。
不要自行加入被拦截的压缩包，也不需要关闭防护或增加排除项。

原生超分与补帧
管理器根据游戏集成、实际 EXE、显卡和驱动证据判断是否可配置，不再使用用户勾选
“我已开启”来解锁功能。无法读取游戏开关时，会提示在游戏内开启；配置读回也不代表
游戏本次已采用。缺少验证所需配置时，先正常运行游戏一次，再重新检查。
默认模型按显卡选择；只改模型时保留游戏 DLSS 档位与输入比例，已有设置不会被重置。
RTX40 默认 MFG Unlock 0.7 中文版，可选 0.7 官方原版或 0.6.1 回退版；只安装所选版本。
它需要已确认的原生 Streamline FG、x64 DX12 及匹配运行库，选项按检测结果开放。
本功能不补装 DLSS-G 或 Streamline DLL；倍率选项、配置值或 FPS 上涨不能独立证明实际倍率。
原生 DX11 默认使用 NIGos Bridge 1.4.12 的本项目 NR 适配版，1.4.11 用于明确回退。
同版本号的上游原版不能直接替换适配版；原生 DX12 不安装 DX11 桥接器。

米哈游游戏
在“米哈游兼容”选择 HoYoShade，再选与实际 EXE 匹配的正式客户端和渠道，绑定已安装的
HoYoPlay（根启动器 C:/Program Files/miHoYo Launcher/launcher.exe）或 Starward（Starward.exe）。当前正式流程针对 x64 DX11/DX12。
预览会列出独立外置目录及已有 Add-on 的保留、隔离安排。首次可直接应用这一配套。
使用 HoYoPlay 时，先从管理器启动，等助手就绪，再在 HoYoPlay 点击该游戏的启动按钮。
客户端要求管理员权限时，仅本次后台加载助手请求 UAC，界面保持原权限。
官方启动器等待时间最长五分钟。拒绝、超时、取消或退出管理器只结束本次助手等待和观测，不结束游戏。
使用 Starward 时，先在 Starward 注册 URL 协议；管理器核对绑定后通过协议启动。
游戏或启动器更新后需重新核对绑定。“助手就绪”“ReShade 加载”和“NR 成功”是不同状态。

手动游戏插件更新包与管理器
另行提供的游戏插件手动更新材料按 26 个路线目录组织，并共用 RTX40/RTX50 两份大运行库。
它不是管理器安装包，也不是管理器“导入 OTA”支持的格式。手动维护的安装按其中的
“目标路径清单.json”操作，配置 .example 仅供合并参考，不直接覆盖个人 INI、CFG 或预设。
已经由管理器接管的游戏，请使用管理器预览、应用和恢复，让组件、备份与收据同步更新；
不要手动覆盖后修改收据摘要。HoYo 手动材料的目标只能是当前已核验活动目录，不能猜路径。

检查、恢复与验收
同一实际加载目录只保留一套 Core／桥接器；改名的旧副本同样可能被加载。
预览按实际 AddonPath 和组件身份处理已有文件；确认冲突的组件会隔离，未知 Add-on
可按预览明确选择保留。保留的滤镜、纹理、HDR 配套和个人配置不应被整目录覆盖。
先退出游戏，有未完成事务时先恢复。卸载可选“干净移除”或“恢复安装前”，核对清单再应用。
干净移除让旧代理留在备份；恢复安装前只使用有记录且摘要匹配的原件，未知 .bak 不冒充原件。
隔离与恢复均保留必要记录；手动改动导致摘要不符时，先处理冲突再继续。

本批 7 条 RTX50 受控程序路线均取得 NR 完成、重置后继续处理及进程正常退出证据，
这不代表真实游戏已通过，也不代表画质已经验收。RTX40 文件与配套已核验，硬件实测待用户完成。
BL3、Batman、米哈游、2077、BG3 与 RE 游戏按 beta.3 验收记录逐项填写。
反馈时保存同次启动的游戏 EXE／API、组件版本、活动目录、日志、NR 完成记录及同场景画面。
