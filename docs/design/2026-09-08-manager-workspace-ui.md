# 现用管理器工作区调整 · dev.5

2026-09-09 / dev.8 更新：主代理再次检查实际包内 renderer 的宽/窄布局。沿用顶部 API/核心和两页签；SR/FG 选后自动应用，连续编辑合并，保留滚动与焦点，仅一个总恢复。D3D12 兼容修复直接可见；游戏卡增加同风格改名入口和安装 spinner。下面 dev.5 中“保存/预览/下次启动”是旧流程，已由用户新要求替代。验证与截图索引见 [dev.8 交接](../handoffs/2026-09-09-manager-dev8.md)。

根据用户最终布局选择，API 与核心版本在顶部直接显示，安装状态与画面设置放在一起，只将超分补帧独立为第二页签。实现沿用现用 xiaofeng 的深色/绿色主题和已选定的 DLSS5 装机宅图标。旧 manager-launch-controls 测试 UI 未参与开发。

## 使用流程

- 游戏详情仅有「画面设置」「超分补帧」两个页签；API 和核心是共同顶部区域，不归属任何页签。已安装和未安装游戏默认均为画面设置；安装前条件在同页给出。页签切换复用现有控件，保留 SR/FG 草稿，不触发写入；键盘方向键、Home/End 可操作。
- 画面设置保留风格、模型强度、额外强度；皮肤结构保护开关及强度直接显示，无需展开。NR 自动保存状态就地展示，避免与需要明确保存/预览的超分补帧操作混淆。
- SR/FG 首次打开页签才加载。模型 K/L/M、固定倍率和动态目标帧率仍可直接选择；实验参数及说明折叠，不隐藏当前实验状态。RTX40 准备组件及运行库恢复入口、RTX50 原生路线不变。
- API 与每游戏核心版本在顶部并列，窄屏纵向排列。自动检测显示「DX11 桥接（自动）」或「DX12（自动）」，游戏卡片同步标注；用户可指定 DX12，重新扫描不会覆盖。共用 nrchain、自动桥接和已保存 EXE/API 规则不变；安装状态在画面设置旁边，异常优先，通过的文件检查折叠。卸载与修复保持明确距离。
- 组件管理集中来源、OTA/核心导入、新安装默认核心、可用版本和折叠历史说明。设置页只保留管理器偏好与产品信息。来源切换会更新保留中的版本下拉框，不丢弃仍有效的选择或 SR/FG 草稿。
- 修复页异步结果绑定当前选择；旧请求不能覆盖新游戏。未选择游戏时不允许修复、卸载或复制诊断。

## 主代理视觉验收

使用当前 Electron renderer 的隔离数据捕获，逐项对比修改前后截图，并对包内实际 ASAR 重测。没有借用原生已安装应用或游戏的画面作为夹具证据。

| 项目 | 检查与调整 |
| --- | --- |
| 字体 | 主标题、面板标题、字段与辅助说明形成统一层级；版本身份单独标注，长路径换行或截断，不压住操作。 |
| 间距 | 仅超分补帧独立，API/核心始终可直接访问；皮肤设置常显。宽屏组件来源与导入并列，窄屏堆叠。第一轮发现可用版本被过长说明挤出首屏，已压缩说明并复查。 |
| 色彩 | 沿用绿色主动作，次要内容适度提高对比度；焦点轮廓一致。错误同时使用文字说明，不单靠颜色。 |
| 图标与控件 | 保留用户选择的装机宅图标；展开按钮具备名称与展开状态。隐藏页签使用 hidden/inert，避免键盘进入不可见字段。 |
| 文案与行为 | 明确自动保存、下次启动请求、预览应用、撤销本页设置。文件检查通过不等于游戏运行通过；外部组件来源不称为运行时外加载。 |

1280×900、900×620 交互通过；900×780 多页面截图复查。检查包含两页签循环/草稿、顶部 API/核心在两个页签均可见、皮肤无需展开、DX11 自动与手动 DX12 相互独立、延迟加载、来源拒绝/失联/返回随包、下拉目录更新、旧诊断竞态和独立 SR/FG 恢复。完整 Node 回归与实际包内 UI 的最终记录见交接文档。

本地证据在 `build/revision5-final-tests.log`、`build/revision5-packaged-1280.log`、`build/revision5-packaged-900.log` 及 `build/revision5-*.png`。这些是界面与交互证据，不证明真实游戏、真实 GPU/驱动请求、反作弊环境或新 carrier 兼容性。

## 仍需运行时分支交付的内容

Manager 外部组件目录只改变安装来源，游戏仍通过已部署的 ReShade/Add-on 加载。#171/#175 的外部 provider 接入 Own Core 已有受控宿主结果；#194 的 DX11 carrier 已完成设备匹配、激活与资源退役保护的受控验证，但没有新增真实游戏通过结论。Vulkan、TAA/TSR、FSR/XeSS 的输入与加载链路仍须逐路验收，不在本次 UI 更新中暗示通用支持。
