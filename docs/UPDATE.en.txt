Author: @野生的装机宅 Bilibili
Official releases: https://space.bilibili.com/941799

What this update is

This update simplifies the controls and fixes a resource-binding problem when the post-SR mode copies the original picture. New installations request strength 1.2 and colour follow 0.75. Existing values, including zero, are preserved from the previously selected mode. The slider displays the actual request, from 0 to 2. Before-SR remains the default; effective colour follow stays zero for unknown HDR inputs.

Use this package with an existing 0.3.5 maintenance installation. Its core update files are the addon, Instructions.txt, Collect-Feedback.cmd and collect-feedback.ps1, with additional verification and source manifests. Keep both existing DLLs and nr_before_sr.ini; there is no need to download the large runtime again.

0.4 r4 belongs to a separate experimental line. Keep its installation and settings separate. Do not mix files and then treat the result as a comparison of the same version. To return from the experimental line, restore the maintenance installation and settings before applying this update. The 0.4 outdoor-image problem is still under investigation; this package does not establish a fix for it.

How to update

Exit the game completely. Back up the current addon outside the game directory, then replace it with this addon. Keep only one active copy; do not load old/new or Chinese/English copies together.

Keep nrchain_nvngx.dll, nvngx_dlssnr.dll and nr_before_sr.ini. Place Collect-Feedback.cmd and collect-feedback.ps1 together beside the addon. Do not swap runtime DLLs between GPU packages.

Start the game and check that the addon panel says beta0.3.7. First-time installations or missing runtime files require the full package for your GPU.

What changed

For the new Forza Horizon crash report, the stable build once again refuses to insert NR while the command list has a null PSO. It also avoids publishing the wider graphics-state hooks used only by that high-risk restore path. The report contained no crash dump, so this is a conservative fix based on the exact version regression and still needs game testing. Keep ExperimentalNullPsoCarrier=0 unless you are running a controlled compatibility experiment; changing it requires a full game restart.

The DLSSNR.UICorrection parameter now uses the unsigned type read by the runtime. New installations enable “HUD / text protection (model)”; an existing explicit 0 or 1 is preserved. This can help only when a game provides a separate UI layer. It cannot discover subtitles or HUD pixels already baked into SceneColor.

Post-SR preserves the game's original output and copies it into an owned intermediate. Its resource descriptors are now created directly, avoiding a descriptor heap that is not a permitted CPU copy source. Software GPU checks passed; individual games still need testing.

Older strength settings no longer get overwritten by the other mode's higher value; a saved zero is retained. Binding status is reported only after an actual call for the matching configuration, with pending or expired records kept distinct from current state.

When the game's Ray Reconstruction (RR) owns the rendering path, F8 collects screenshots, settings and logs and records why NR stage images are unavailable. It no longer waits for NR stages that cannot be produced while RR is active.

If F8 times out, a stage request that has not started can be cancelled so the next F8 can retry. This does not force-stop work already started; not every timed-out capture can be cancelled.

The panel shows the current bypass ahead of Settings pending, instead of hiding it behind that message. Your saved requests are retained.

The two experimental controls now explain their scope: Lighting Match adjusts local brightness, and HDR Highlight Detail changes highlight mapping before NR. Neither unlocks colour follow. Check the effective value and reason beside Colour Follow.

For NTE players reporting no effect

The supplied NTE log shows that the game enabled Ray Reconstruction, RR took over, and this addon stopped NR. That is the current safety bypass. It is not evidence that RTX 40 cards are unsupported, or that every no-effect report has been fixed.

To test this addon's NR, disable Ray Reconstruction in the game. If the panel still shows an RR bypass, exit the game completely and restart before testing. This update does not change that rule.

Reporting a problem

Stop where the issue is visible, press F8 or click Collect feedback ZIP, and keep the camera still until completion. Collection waits up to about 30 seconds; background packaging takes additional time, especially on a slow drive.

feedback.zip normally appears under Documents/DLSS5-Feedback. If Documents cannot be used, collection tries the system temporary directory. Use the actual path shown in the panel or its copy-path button. A partial bundle is useful too.

The ZIP contains three current-view screenshots, available NR stages, image information, settings and logs. The three screenshots are not an automatic on/off comparison. The program does not switch settings or upload files for you. For comparison, keep the camera fixed, toggle NR yourself with F6, collect once per setting, and label each bundle with its version and on/off state.

Send the ZIP with the game name, GPU model, HDR or SDR setting, and the problem. Weak effects, Spider-Man and Wuthering Waves image quality, and Dragon's Dogma 2 crashes still need reports. Applied does not necessarily mean a stronger visible effect.

If the game cannot start, double-click Collect-Feedback.cmd with collect-feedback.ps1 in the same directory. Send feedback-offline.zip from the printed path. It collects existing information and cannot recover unsaved images.
