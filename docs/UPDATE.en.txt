Use this package with an installation that already has the runtime. Keep nrchain_nvngx.dll, nvngx_dlssnr.dll and nr_before_sr.ini. Replace only the addon and place both feedback-tool pairs beside it. Do not load old/new or Chinese/English addon copies together.

Picture defaults

New installations start with final effect strength 1.2. The slider is the actual request, from 0 to 8; there is no hidden multiplier or 1.2 shortcut. New colour follow is 0.75. Unknown HDR contracts remain luminance-only. Explicit existing settings, including zero, are preserved.

The 0.4.2 NR quality setting changes only Feature 18's working resolution, not the game's DLSS mode or the NR/SR order. High strength at a low NR working resolution can amplify grain. Raise NR quality before attributing that result to jitter.

Stability changes

r3 delayed command-signature observation whenever its device-init snapshot of the in-memory switch appeared disabled. Exact r3 Wuthering Waves packages prove that the startup observer count stayed at zero even when the installed INI requested Enabled=1; the cause of that transient false snapshot is not established. Character, UI, map and rain work then reused permanently unknown ExecuteIndirect signatures. The last rain capture ran 1,507 native SR calls with zero new NR submissions. beta0.4.2 always installs only this narrow observer at device creation. Null-PSO admission and the wider graphics-state hooks remain disabled by default. The WARP regression proves that a signature observed before NR activation stays restorable regardless of switch state. Wuthering Waves, Where Winds Meet and other games still need beta0.4.2 retesting.

The default order has not changed: Mode 2 is before-SR NR followed by the game's native SR. Only an explicit Mode 1 selection, or an existing configuration already saved as Mode=1, uses post-SR NR. NR quality / WorkMode changes Feature 18's working resolution; it does not change processing order.

The new Crysis 3 Remastered package proves that its presenting API is D3D11, so there is no native D3D12 Feature 1 for this add-on to intercept. beta0.4.2 now says “D3D11 unsupported; D3D12 required” directly in the panel instead of leaving players to interpret a waiting-Feature-1 status as a strength or HDR problem. The check uses only the current presenting runtime and cannot be permanently tripped by an auxiliary D3D11 device in a D3D12 game.

The Chinese build no longer forces Chinese text through a Latin-only ReShade font. Its exported add-on name remains ASCII-readable; when the active font lacks common Simplified Chinese glyphs, the panel falls back to English and explains how to select zh-CN/System Default or Microsoft YaHei under Overlay & Styling. Chinese returns after the font is changed and the game is restarted.

The RDR2 report confirms that this add-on and renodx-dlss5.addon64 were loaded together. r3 detects that exact competing module, keeps the native game result, and tells the player to remove it and fully restart. The two NR owners cannot coexist.

The Black Myth log shows all three lifecycle hooks failing with MinHook status 9 when nvngx_dlssd.dll was loaded at a low address. r3 extends the safe relay search range, logs the readable status name, and preflights loaded NGX modules before the first SR Create. A native harness reproduces the old failure and passes with the fix; the game still needs retesting.

The Forza package contained no crash dump. beta0.4.2 therefore keeps null-PSO admission and the wider graphics-state hooks disabled by default. That risk reduction and the command-signature correction both still need an in-game Forza retest.

A Cyberpunk 2077 run reproduced and fixed a default NR-quality path that submitted no NR work. The game supplied typed four-channel half-float motion vectors, while the older path accepted only two-channel formats and safely bypassed. This build admits only that explicit typed format and reads its XY motion components; other unknown formats still bypass. Automated GPU checks cover all three admitted formats, and a short local run reached 6,546 actual submissions with no queue-state mismatch. This validates the processing path, not picture quality.

For the Forza Horizon crash regression first reported after 0.3.3, the stable path once again bypasses a command list whose PSO is null. It also avoids publishing the wider graphics-state hooks used only by that high-risk restore path. The report contained no crash dump, so this is a conservative fix based on the exact version boundary and still needs game confirmation. Keep ExperimentalNullPsoCarrier=0 unless running a controlled one-variable experiment; changing it requires a full game restart.

Older builds wrote DLSSNR.UICorrection using the wrong parameter type. It now uses the unsigned value read by the runtime. New installations enable “HUD / text protection (model)”; an existing explicit 0 or 1 is preserved. This can help only when a game supplies a separate UI layer and cannot discover subtitles or HUD already baked into SceneColor.

Updating

Exit the game completely, back up the old addon outside the game directory, then replace it. Keep both runtime DLLs and the existing configuration. In game, confirm beta0.4.2 in the ReShade addon panel, compare with F6, and verify that the NR-success counter continues increasing.

Reporting

For picture problems, keep a fixed camera and press F8 or click Collect feedback ZIP. Wait about 30 seconds for completion and collect one package per setting. The package identifies display screenshots and GPU stages separately; it does not claim they are the same final-SR frame.

After a crash, run Collect-Crash-Feedback.cmd. It derives one unique absolute game EXE path from the newest ReShade.log and collects only existing Windows 1000/1001 summaries, WER reports and dumps from the last 72 hours that pass its identity rules. A record containing AppPath must match the current game path. Standalone CrashDumps do not contain their source path, so they can only be filtered by exact EXE basename and time; the package records this limitation. The tool does not enable dumps, modify the registry, launch the game or upload. A dump can contain process memory and local paths, so decide whether to share it.

For a startup problem without crash evidence, run Collect-Feedback.cmd. Keep each CMD beside its matching PowerShell script.
