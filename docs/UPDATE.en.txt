Use this package with an installation that already has the runtime. Keep nrchain_nvngx.dll, nvngx_dlssnr.dll and nr_before_sr.ini. Replace only the addon and place both feedback-tool pairs beside it. Do not load old/new or Chinese/English addon copies together.

Picture defaults

New installations start with final effect strength 1.2. The slider is the actual request, from 0 to 8; there is no hidden multiplier or 1.2 shortcut. New colour follow is 0.75. Unknown HDR contracts remain luminance-only. Explicit existing settings, including zero, are preserved.

The 0.4.1-r2 NR quality setting changes only Feature 18's working resolution, not the game's DLSS mode. High strength at a low NR working resolution can amplify grain. Raise NR quality before attributing that result to jitter.

Stability changes

A Cyberpunk 2077 run reproduced and fixed a default NR-quality path that submitted no NR work. The game supplied typed four-channel half-float motion vectors, while the older path accepted only two-channel formats and safely bypassed. This build admits only that explicit typed format and reads its XY motion components; other unknown formats still bypass. Automated GPU checks cover all three admitted formats, and a short local run reached 6,546 actual submissions with no queue-state mismatch. This validates the processing path, not picture quality.

For the Forza Horizon crash regression first reported after 0.3.3, the stable path once again bypasses a command list whose PSO is null. It also avoids publishing the wider graphics-state hooks used only by that high-risk restore path. The report contained no crash dump, so this is a conservative fix based on the exact version boundary and still needs game confirmation. Keep ExperimentalNullPsoCarrier=0 unless running a controlled one-variable experiment; changing it requires a full game restart.

Older builds wrote DLSSNR.UICorrection using the wrong parameter type. It now uses the unsigned value read by the runtime. New installations enable “HUD / text protection (model)”; an existing explicit 0 or 1 is preserved. This can help only when a game supplies a separate UI layer and cannot discover subtitles or HUD already baked into SceneColor.

Updating

Exit the game completely, back up the old addon outside the game directory, then replace it. Keep both runtime DLLs and the existing configuration. In game, confirm beta0.4.1-r2 in the ReShade addon panel, compare with F6, and verify that the NR-success counter continues increasing.

Reporting

For picture problems, keep a fixed camera and press F8 or click Collect feedback ZIP. Wait about 30 seconds for completion and collect one package per setting. The package identifies display screenshots and GPU stages separately; it does not claim they are the same final-SR frame.

After a crash, run Collect-Crash-Feedback.cmd. It derives one unique absolute game EXE path from the newest ReShade.log and collects only existing Windows 1000/1001 summaries, WER reports and dumps from the last 72 hours that pass its identity rules. A record containing AppPath must match the current game path. Standalone CrashDumps do not contain their source path, so they can only be filtered by exact EXE basename and time; the package records this limitation. The tool does not enable dumps, modify the registry, launch the game or upload. A dump can contain process memory and local paths, so decide whether to share it.

For a startup problem without crash evidence, run Collect-Feedback.cmd. Keep each CMD beside its matching PowerShell script.
