# Manager 0.4.5-hotfix.2：API 与组件部署

安装器界面/产品版本为 `0.4.5-hotfix.2`，Windows 文件版本为 `0.4.5.2`。
内置插件仍为 **0.4.5-DX11-兼容增强**，核心 PE `0.4.5.104`，固定核心源码
`dccb5b398ccc540723f84a6ef789dd70dbda5cd3`。本次不重新编译核心或 carrier。

## 已核验的问题与规则

旧 `isDx11Only()` 把 `DirectX 11/12` 或 DX11 标签加 `dx12=true` 误判为纯 DX11，
版本解析随后覆盖用户选项。旧部署又只检查 payload 是否含 carrier，因此 DX12
选择最新核心时也会安装它。这两处可通过源码和回归夹具复现。

carrier 接收 DX11 原生/模组 DLSS 输入并提供桥接；D3D12 核心路线不需要它。
`nrchain_nvngx.dll` 两路共用，不参与 carrier 清理。安装、修复、版本切换及 OTA
都使用同一个最终 API 判断：

| 最终 API | 部署行为 |
|---|---|
| DX12 | 所选核心 + nrchain + 必要运行组件；移出并备份旧 carrier |
| DX11 | 要求已支持 DX11 的成套核心、nrchain、carrier；缺件拒绝，不能临时拼旧 carrier |
| 混合/未知 | 提示用户按游戏启动设置选择 API，不自动装 carrier |

核心选择顺序为明确请求、游戏版本锁、明确全局选择、默认建议。
不兼容选择会解释并拒绝，不静默改成另一版本。API 选择保存在用户设置且绑定 EXE；
重新扫描保留，改选 EXE 后不沿用旧覆盖。保存 API 只改变下一次操作，需安装/修复/
应用版本才调整游戏文件；部署路线不一致时 Manager 暂停启动该已安装游戏。

## API 证据边界

读取 EXE imports/markers，同时检查相关引擎模块，避免 first-hit 忽略 DX12 引擎。
排除图形代理、NGX/nrchain/Streamline 运行库及 Addon 本身；模块最多8个、每个32MiB，
EXE imports 最多128MiB、markers 最多32MiB。超过读取范围不会伪造运行时结论。
单独静态 DX11 仍待确认；单一 DX12 线索可作安装推断；双 API 保守标为混合。

只读取所选 EXE 目录中的既有 `ReShade.log`，首16KiB/尾64KiB，核对日志时间和
初始化行的完整 EXE 路径。日志中的设备创建仅为历史线索，不能证明当前呈现 API，
更不能因为 carrier 自己创建过 D3D11/D3D12 设备就自动激活路线。
Steam 本地启动配置按 appid 有界读取，只展示 API 相关线索；多用户/多路线冲突
保守处理，不输出无关参数。Manager 当前直接启动 EXE，不自动附加 Steam 参数。

用户明确选择 DX11/DX12 高于这些推断，但不会绕过 x64、已有普通 DLSS、组件校验
和游戏关闭检查。反馈 TXT 同时记录原始 API 标签、最终选择、证据及部署 API。

燕云历史 #98 附件为另一旧版本；存在 carrier/NR 活动计数，但不足以确认本次安装器
或燕云的具体根因。本轮没有燕云、2K27或其他游戏实机兼容验收。

## 备份、回退与 ReShade

已知新旧 carrier 按角色移入 `_DLSS5_Backup`；受管文件被用户改动时，先拒绝覆盖。
冲突移动加入真实文件事务；第二次移动或后续写入失败可回滚。卸载先检查受管文件
及原始/冲突备份 SHA，损坏就停止，不先拆掉安装。持久原始备份不在事务提交前删除。

DX11 明确部署时仅解除配套 carrier 的 `@精确文件名` 禁用项，遍历重复 `[ADDON]`
及 `DisabledAddons`，保留其他项和逗号转义；改前保存 `ReShade.ini.bak`（占用时带编号）。
`显示名@文件名` 同样会触发 ReShade 的预加载过滤，但属于用户具名配置：Manager 保留原文、
将诊断标为未完成并提示在 ReShade 中手动启用。若 PR #160 已生成 receipt，Manager 不解析或
恢复该 receipt；后续改写会使其哈希保护拒绝覆盖新配置，原 receipt/backup 证据保持不变。
卸载不盲写整个 ReShade 配置，历史侧备份保留供回退。DX12 通过移出文件避免部署 carrier，
不修改 `LoadFromDllMain`。另一路 ReShade 预加载排除工作见 PR #160；本安装器不冒充
已实现自动运行时 API 激活，也不能保护所有手工复制/第三方加载 DLL 的路径。

## OTA 与验证

支持原 `nr-branch-ota-v1` 标准 DX12 包及已发布的中文兼容精简 ZIP。严格区分一个核心
与可选的一个配套 carrier；校验清单/大小/哈希，拒绝重复路径、大小写碰撞、缺件和
多核心，不按 ZIP 中第一个 Addon 猜角色。保存组件哈希并在应用前再次核验。

测试覆盖真实服务/API设置/文件journal、DX12→DX11→DX12部署及OTA链、版本锁、
重新打开设置、导入源篡改、原始备份损坏、移动/写入失败、卸载提交失败、INI处理。
成品还需独立解包核对源码、完整载荷与版本身份；这些验证不等同游戏运行通过。
