# NVFP4：完整 NR 耗时与优化选择

本轮已接通真实 Core 的 NR→原生 SR，并定位主要 GPU 时间区间。当前证据不支持完整 NR
降低10%；同shape短实验中，已知 FFN 剩余时间占比较小，尚无支持10%新增收益的依据。
短实验发现的新增候选是合成阶段诊断门控，局部约节省0.04 ms；它在所测静态和运动捕获中
与各自原版本逐字节一致。五轮长程计时确认了局部节省，但没有建立完整NR变快的结论。
默认保持原 FP8，Auto 合格策略表为空。

## 测量对象与边界

硬件为 RTX 5090 Laptop GPU（SM120，82 SM），实际驱动610.62。固定签名 NR 运行库、
模型、强度、曝光、DLSS Quality 和场景；NR 工作分辨率为2560×1440，对应实际 M960，
原生 SR 输出为3840×2160。实际FFN参数的空间网格为24×40，故M=960；expansion的
GEMM维度为(M,N,K)=(960,4096,1024)，contract为(960,1024,4096)。shape 来自实际
Feature18参数读回与descriptor，不由输出分辨率推断。

- Feature18：签名 NR Evaluate 的 GPU 时间区间。
- 完整 NR：Core EncodeBegin 到 CompositeEnd，包含编码、Feature18和合成。
- NR→SR：同一 EncodeBegin 到原生 SR 结束；包含完整 NR、交接间隔和 SR。

真实Core链路时间戳在实际提交、fence完成且合法命令列表 Reset 后读回。链路样本以
进程ID、启动标识、epoch和frame配对；保留64位整数原始tick，逐条重新计算。后文五查询
阶段记录也保留原始tick；较早的Feature18短筛选仅持久化毫秒。读回和Present不计入上述区间。
桌面、启动器和远控应用被保留，未证明 GPU 独占；以下短实验是定位与筛选证据。

## 原始 FP8 的完整 NR 成本

真实静态 Sponza，128帧预热后64帧。表内使用同一批逐帧区间的算术平均值，可相加；
不能把分项中位数相加成总时间，也不能跨不同输入批次拼接绝对时间。

| 区间 | 平均 ms | 占完整 NR |
| --- | ---: | ---: |
| 输入编码 | 0.053778 | 0.513% |
| Feature18 | 9.969576 | 95.026% |
| 合成 | 0.467977 | 4.461% |
| 编码后至 Feature18 的间隔 | 0.000091 | 0.001% |
| 完整 NR | 10.491421 | 100% |

同批 SR 为2.336490 ms，NR→SR为12.828076 ms；交接间隔约0.000166 ms。
完整 NR 中位数10.518368 ms，逐帧8.424928–14.398432 ms，表明短批波动明显。
证据：`resume-20260909/chain-fixed-passthrough-r5/root-verification.json`。

## Feature18 内部已定位的区间

Windows Nsight Systems CLI需要当前会话没有的管理员权限，因此使用现有 GPU 时间戳。
每调用插入查询的诊断会使 FP8 约慢12.38%，不能把它的绝对时间当正常执行成本。
最终使用每帧5个时间戳形成4个不重叠区间，每角色两轮反序、共128个有效样本。
这一批是固定合成输入；它与上方真实 Sponza 批次只比较结构，不能相加绝对毫秒。

| 已识别的执行阶段 | 原 FP8 平均 ms | 占 Feature18 | 上游 FFN 配置平均 ms |
| --- | ---: | ---: | ---: |
| 前部多层 Swin | 4.108230 | 39.123% | 4.064153 |
| ViT 1D（包含被替换 FFN） | 1.642951 | 15.646% | 1.516418 |
| 后部多层 Swin | 3.842904 | 36.596% | 3.638967 |
| 尾部处理 | 0.905423 | 8.622% | 1.052393 |
| 查询范围外间隔 | 0.001320 | 0.013% | 0.001345 |
| Feature18 | 10.500828 | 100% | 10.273275 |

前后 Swin 合计约75.72%。阶段的时间覆盖约99.987%，不等于数学、访存和等待已分别解释。
带 wait／tile-sync 名称的内核也融合计算，不能将其整体称为纯同步开销。诊断中可识别的
repack中位数约0.010240 ms、copy中位数约0.029136 ms，来源为8帧逐调用插桩诊断，
其均值分别为0.010284和0.057452 ms；尚无证据证明其中存在可直接删除的冗余。
FFN计时嵌套于ViT区间，不能重复加到表内。证据：`stages-m960-three-way-r2/stage-composition.json`。

## 同条件三方对照

上游基线使用锁定的 v0.7.1-hybrid 内核与权重，由共同后端执行；这是内核算法对照，
没有把它写成未经改动的整个上游插件二进制。另做上游原始SM=170参数控制：M960的
完整输出与SM=82逐字节一致，所有dispatch Info一致。block31参数有额外36字节差异，
已保留；当前cubin指令审查未发现消费该区域，不声称所有参数字节相同或完整插件等价。

共同 M960 的原 FP8 实际替换为0；上游与自建普通收缩均每帧8对、32次调用、40个UAV依赖。
以下是owned signed Feature18宿主的固定合成输入、无SR短筛选，不是真实Sponza Core
完整NR计时。两轮各64帧、反序运行，正数表示耗时减少；未满足长程性能资格。

| 对照 | FFN 耗时变化 | Feature18 耗时变化 | 两轮 Feature18 范围 |
| --- | ---: | ---: | ---: |
| 上游相对原 FP8 | +22.817% | +2.243% | +1.757%至+2.729% |
| 自建普通收缩相对上游 | −2.417% | −0.462% | −2.315%至+1.391% |
| 三次调用融合相对上游 | −2.955% | −1.435% | −3.422%至+0.553% |

因此本轮没有选出优于上游的 FFN 内核。22%左右来自相对原FP8的FFN区间，不能写成
我们超过上游22%，也不能换成完整NR或游戏FPS收益。M640新增覆盖单独保留：上游完整
hybrid模板不支持该shape，不能构造相同shape的上游完整替换对照。
证据：`feature-m960-screen-r4/screen-comparisons.json`、`sm-count-m960-control-conclusion.json`。

## 真实完整 NR 的五轮结果

同一r6渲染宿主、固定512帧准备、128帧预热，每角色每轮600帧且不捕获。五轮交错比较
原FP8、上游FFN共同后端配置、同上游FFN＋诊断门控；15次运行共9000个有效样本及63000个
uint64原始tick全部核验通过。每轮内部的完整728帧历史元数据相同，实际替换与Reset闭合。

下表先对每轮两角色的600帧中位数作差，再平均五轮；百分比也是每轮相对收益的平均，
不是平均毫秒之比。95%区间通过联合重采完整三角色轮次的3125种组合获得，不重采单帧。
正数表示节省。分项中位数不能相加成整体中位数。

| 对照／区间 | 平均节省 ms（95%区间） | 平均节省 %（95%区间） |
| --- | ---: | ---: |
| 上游→本次候选：合成 | +0.040835（+0.039997至+0.041846） | +10.724（+10.516至+10.984） |
| 上游→本次候选：完整NR | +0.008992（−0.252720至+0.227680） | +0.050（−2.703至+2.334） |
| 原FP8→上游：完整NR | −0.013738（−0.223971至+0.281702） | −0.171（−2.323至+2.828） |
| 原FP8→本次候选：完整NR | −0.004746（−0.164189至+0.180912） | −0.059（−1.701至+1.859） |

五轮合成节省分别为0.040032、0.039920、0.042528、0.041616、0.040080 ms。
上游→候选的完整NR变化为−0.462096至+0.352768 ms，明显大于约0.04 ms的局部改动。
未修改的Feature18区间也变化；其平均节省为−0.046851 ms，95%区间跨零。因此可保留
重复出现的合成优化，不能据此声称完整NR变快、10%目标成立或游戏FPS改善。

运行期间保留桌面启动器和远控；开始前两启动器3D占用合计约7.4%。CPU功耗未锁，前三轮
可能与质量数据CPU分析并行，最后两轮在该分析完成后运行。所有数据明确标记`shared_gpu`，
上述置信区间不消除这些环境限制，正式性能资格及Auto始终为false。即使只关注统计结果，
完整NR区间也跨零。证据：`perf512-experiment-r1.json`、`perf512-summary-r1.json`及背景收据。

## 按实际毫秒选择实验

| 候选 | 成本与事前预期 | 实现与质量风险 | 最小实验及当前结论 |
| --- | --- | --- | --- |
| 合成诊断门控 | 合成中位约0.38 ms；预计省0.02–0.05 ms，约完整NR的0.2–0.5% | 两处诊断计算移入原采样条件；低实现成本，仍需检查编译浮点与时域输出 | 静态和所测运动捕获逐字节一致；五轮合成平均省0.040835 ms，完整NR收益未建立，保留局部改动 |
| 更窄收缩tile | 当前收缩约0.21 ms；事前假设省0.02–0.06 ms | 沿用已恢复接口，中等成本；需保持量化／scale／布局 | M960两轮完整输出相同但FFN约慢4.95%，否定假设，停止推进 |
| 前后Swin实现／同步 | 占Feature18约75.72%；尚无可信可节省范围 | 权重、参数和chained协议未恢复；实现成本高，数学及生命周期风险高 | 锁定资产和源码审查仅确认FFN模板；未找到成熟可直接复用接口，不贸然替换 |

两次调用融合已暂停：有明确变慢证据，当前分析没有提供恢复该方向的可信理由。
同一合成输入短筛选中，原FP8约0.65 ms FFN占Feature18中位时间约6.5%，上游剩余
约0.50 ms占其Feature18约5.1%。在其余区间不变的模型下，这只是把整个FFN区间免费化的
量级估算；不能与另一批真实Core毫秒拼接成完整NR的严格上限。实际还需保留必要计算、
转换和依赖开销。当前仍缺少完整NR达到10%的可行证据。要推进该目标，
需要在占比大的阶段恢复可验证接口并取得新的节省证据，不能靠削弱增强、改工作分辨率
或把SR时间算入NR目标。

## 画质与当前验收边界

保持独立NR/SR历史，使用纯SR的S、原FP8的F、候选C，在原始RGB上定义
`effect_gain=sum((C-S)*(F-S))/sum((F-S)^2)`，
`residual_nrmse=sqrt(sum((C-F)^2)/sum((F-S)^2))`。
指标明确写出本地定义；未找到用户所指原调研的定义文件，因此不声称完全复用了原定义。

已执行128帧预热＋720帧运动序列，捕获第648–711帧，跨越第二次相机回程转向。
四角色848帧历史元数据与64帧原输入、深度、MV相同；参考与诊断门控SR的RMS差值为
0.00003783。同参考版本复跑的320个原始平面全部逐字节一致，但参考准备6帧、候选7帧。
随后固定64帧的一次运行因hybrid未就绪被严格拒绝，未开始测量。

最终五角色统一固定512帧准备，并独立Reset、预热128帧和运行720帧。每个Core在epoch前
有510次实际NR成功，原始tick、替换、fence和Reset均闭合。门控前后分别在原FP8与hybrid
两条路径进行比较，每对64帧×5平面共320份捕获全部逐字节相同；两对合计640项相同。
五角色完整848帧历史元数据一致，固定512目标和实际准备计数一致。新reference／diag实际
均在第7准备帧观察到Ready；不能声称这个实验单独证明旧差异由准备帧数导致。

同512初始化的新S／F／reference与S／F／diag分别重新计算，逐帧及汇总指标完全相同：

| 指标 | 上游FFN配置 | 上游FFN＋本次诊断门控 |
| --- | ---: | ---: |
| 汇总effect_gain | 1.00973531 | 1.00973531 |
| effect_gain逐帧范围 | 0.996192–1.026671 | 0.996192–1.026671 |
| 汇总residual_nrmse | 0.08974568 | 0.08974568 |
| 增强残差RMS | 0.0032298053 | 0.0032298053 |
| 对原FP8的RGB误差RMS | 0.0002859524 | 0.0002859524 |

原FP8增强残差RMS为0.0031862523，候选与它的RMS比值为1.0136690。63个相邻帧误差变化
的RMS中位数两者同为0.0001106798。门控没有改变所捕获片段的细节、颜色或时域输出；
这些指标也保留了hybrid与原FP8之间原有的量化差异。
相邻帧误差变化未做运动补偿／遮挡掩码，不能称为完整flicker验收。实机游戏、HDR、DRS
和Auto资格仍未完成。新批次未制作视频，旧r5视频不作为新512批次的视觉证据。
证据：`motion512-chain-verification-r1.json`、`motion512-reference-vs-diag-raw-r1.json`、
`motion512-fp8-vs-fp8-diag-raw-r1.json`及`motion512-enhancement-analysis-r1/reviewed-summary-r1.json`。

源码、全部早期失败、修正后的捕获和原始时间戳均保留。公开源文档只列证据ID；原始
捕获、私有路径和NVIDIA载荷不进入源码导出。当前研究分支保留诊断门控与测量设施，停止
已被否定的窄tile／复杂融合方向；没有在数学与同步协议未确认的Swin阶段实施猜测性替换。
