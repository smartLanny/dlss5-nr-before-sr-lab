## 颜色跟随到底是什么

“NR 颜色跟随强度”决定最终画面跟随 NR 生成的 RGB 色彩变化有多大。它不是模型强度、锐化或总效果开关：设为 0 仍可传递 NR 的明暗/结构变化；提高后才更多跟随模型改动的肤色、材质颜色等。具体是否允许传色，以当前输入格式、曝光和编码的已验证条件为准。

在 0.3.3.5 维护线中，已验证的 SDR 路径可以在 NR→SR 传递颜色。未验证的 HDR NR→SR 会把有效颜色强度限制为 0。SR→NR 另有 FP16/单位曝光的已验证例外，因此同一游戏两种顺序可能不同。显示器是否开 HDR、SR 叠加层的 LDR 字样，不足以单独证明 NR 边界的数据合同。

“实验性光照匹配（NR→SR）”校正局部明暗，减少 NR 对原场景照明的偏移；“实验性 HDR 高光细节”改变模型看到的高光映射。两者都可能改变观感，但都不是颜色准入开关。代码独立性检查覆盖 160 组控制组合；故意把实验开关接入颜色解锁的负控出现 45 个失败。

## 霍格沃茨与后处理效果差异

附件实际运行 0.4 r4；本地 `beta04-local-merged` 的版本标识与之相同，但缺少附件 addon 的哈希，不能将同名标识视为二进制完全相同。

六张截图前已经切到 Reference，日志中 V2 工作尺寸与 render 一致，因此不能把这六图的室外弱效果直接归因于 Quality 降采样。日志还显示更早的两次阶段导出成功，但这些阶段文件夹没有包含在附件里，补充它们比再猜参数更有用。

日志中室外原始 PreExposure 约 0.000287，创建时钳到 1/1024，对应 SourceToCanonical=1024；室内 PreExposure 约 1.872，转换尺度约 0.533。室外确实触及已有曝光范围边界。这个证据说明模型输入尺度可能受限制，不能直接证明扩大范围就会改善画质。

核对本地 r4 V2 源码，NR→SR 会对有界代理部分进行修改，再加回保留的 HDR 高光余量。高亮中代理只占原始亮度的一部分时，整幅原图上的相对改变自然会更小。日志还确认该 Mode 2 样本启用了非零光照锁定，颜色跟随请求为 0；未记录光照锁定的具体值，不能假定是默认值。Mode 1 走另一条旧合成路径，不能用 V2 的原因解释所有后置样本。

室外后置截图只在启用约 1 秒后拍摄，室内后置也刚经历大幅曝光合同切换；附件没有 A/A 噪声基线或同帧阶段图，因此暂不做像素差值归因，也不把不同单位的 ColorDiag 数值相除当作“削弱比例”。

对 RenoDX/OptiScaler 的“更强”反馈，本轮仅提出可验证的原因：后处理直接修改 SR 后的完整画面；前置结果还会经过 SR 的时域重建。光照保护、颜色限制、工作分辨率和高光余量处理也会影响可见差异。同样的强度数字不能视为同等算法增益。尚无同机位、同运行库、相同输入与设置的受控对比，不能排出单一根因；本轮不提高强度上限、默认值或颜色权限。

建议霍格沃茨先保留现有 r4：室内、室外各固定机位，在 Reference、强度 1 下分别采集 Mode 2 与 Mode 1，切换后等曝光和画面稳定；使用该版 F7 阶段采集及减号截图，并附配置与日志。0.3.3.6 的 F8 包不能代替 0.4 的同版本证据。

## HD2 可借鉴的边界

提供的桥源码仅读取 Output，修改单资源虚表以返回另一格式，且依赖已加载名含 renodx-dlss5 的插件。它既不是 SR 实现，也不是本项目的通用资源合同适配器。typed view 的正确思路可以参考；storage format、SRV/UAV format、实际数值域和资源状态仍需分别证明。

不复制其 hook：源码存在跨线程读取虚表时原始指针可能被清空的窗口，Evaluate 期间反复拆装指令补丁也没有覆盖其他执行线程。本项目已有旧 HD2 日志在 hook 内存保护修改阶段失败，该问题早于颜色格式准入。这些均不足以支持“一次简单修改即可兼容”的判断。本轮未执行附件中的程序或安装到游戏。

## 实际修复与验证

- F8 开始时识别 RR 或其他 NR 插件占用；仍保存三张当前画面、日志和设置，在包里写明 NR 阶段为何缺失。
- 采集中途 RR 接管或总开关关闭时，结束等待；超时或后台任务无法创建时，撤销本次尚未开始的阶段请求。
- 请求身份在状态预留后核对；不会取消后来出现的新请求，也不会释放已录制/导出中的 GPU 资源。取消发生在反馈锁之外，保持既有锁顺序。
- 反馈包新增起止 SR/RR 活动、存活 RR 对象和其他 NR 占用计数，明确它们是累计值；历史 applied 参数不表示当前正在运行。
- UI 旁路提示优先、实验开关解释改进；未改变着色器、NR 强度、颜色准入或运行库。

真实生产采集函数回归从 222 项/17 失败变为 222 项/0 失败，并验证真正写出的 ZIP 图像字节。阶段生命周期新增回归从 165 项/1 失败变为 180 项/0 失败，包含锁等待、陈旧请求、已 armed 和导出状态。颜色策略及真实 UI 路径覆盖 40,960 组合同、164,842 项断言，全部通过；旁路优先级修复前已验证红测。独立审核未发现本轮锁顺序或生命周期的确定性 P0/P1。

中英文 addon 与桥两次构建字节一致，三个 LLVM analyzer 目标均为零诊断。桥 DLL SHA-256 仍为 `46041A5FF91AE2FD907E310D132AABC3C4A1ECD48DACE511B8672909D5D9C2FB`；运行库与配置没有改动。轻量包只含 addon、TXT 说明和两个离线收集小文件。

本轮是离线证据复核与代码回归，没有运行这些玩家的游戏或完成新候选的显卡实机画质验证。F8 卡住与状态误导已在对应生产路径复现并修复；法环 SDR、霍格沃茨户外效果和跨插件强弱比较仍待补充材料，不能宣称所有画质反馈均已解决。
