# beta0.4 强化测试分支：本地合并版说明

日期：2026-09-04。作者：@野生的装机宅 Bilibili。官方发布地址：https://space.bilibili.com/941799 。

这次把 GitHub 的 `codex/beta0.4-perfect-chain`（507992b）与本地 `codex/beta0.3.3-tuning-r8`（9085a4d）合并，产出中英文插件和桥接 DLL。源码保存在独立分支 `codex/local-beta04-merged-20260904`。这是本地测试构建；界面沿用上游 `beta0.4-perfect-chain-r4` 身份，准确来源以包外 BUILD-PROVENANCE.json 和 SHA256SUMS.txt 为准。

## 小白版：这次改了什么

1. **新增画质／性能档位。** 默认 Mode 2 先在可调大小的画布上运行 AI，再合回游戏渲染画面，最后交给游戏自己的 DLSS 放大。新增参考、高画质、平衡、性能、超级性能、自定义档位，默认高画质。目标是减少 AI 运算成本；目前没有本次合并版的实测帧率提升数据。
2. **效果强弱更好调。** 新的“效果强度”可调到 8，按模型的明暗变化比例放大；它与“NR 模型强度”是两个不同按钮。先用 1，需要时再试 2；4、8 属于强效果测试，数值越大不代表画面越好。默认最大亮度倍率为 4，限制极端变化。
3. **更照顾原来的光照和细边缘。** 新增光照锁定和边缘保护，目标是减少整幅画面明暗漂移，以及头发、细线和字幕边缘被过度修改。默认分别为 0.20、0.25。
4. **HDR 高光处理更新。** Mode 2 默认使用混合高光曲线，让明亮区域以新的方式进入模型。颜色跟随默认仍为 0，先确认明暗稳定再加颜色。旧版的 ExperimentalPeakShoulder 实验保留且默认关闭，仅用于旧 Mode 1 路径；Mode 2 使用新的 HDR 代理曲线设置。
5. **切分辨率更稳妥。** 加强动态分辨率、运动矢量、相机抖动和结果纹理尺寸检查；输出纹理实际尺寸变了会重建对应结果资源，避免沿用不匹配的纹理。不能确认尺寸时，回退到完整渲染分辨率或原生 SR。
6. **保留原有稳定性修复。** 保留本地 D3D12 状态恢复、截图短文件名和 F7 阶段采集生命周期修复。遇到无法确认的游戏命令状态，会跳过额外 AI 处理，保留游戏原生 SR。
7. **保留完整诊断流程。** F6 开关效果，主键盘减号截图，F7 请求阶段图。本合并版仍保留本地“重建历史、等待至少 64 次成功评估、采集后退休实例”的流程；因此采集时可能短暂预热。阶段图与另外按减号截取的显示画面不是同一帧，不能把两者当作严格同步对比。

## 怎么安装、怎么开始

1. 完全退出游戏，备份原插件、桥接 DLL、运行库和配置。把旧 `.addon64` 移出 ReShade 的插件搜索目录，避免新旧同时加载。
2. 按显卡选一个包：RTX50 包沿用已有签名运行库；RTX30-40 包沿用已有 ShortFuse SF-v2 社区兼容运行库。每包只有一种语言的插件，不要同时加载中英文插件。
3. 把包内四个运行文件放在同一 ReShade/RHI 插件目录：`.addon64`、`nrchain_nvngx.dll`、`nr_before_sr.ini`、`nvngx_dlssnr.dll`。使用本包新配置，不要直接覆盖回旧配置。
4. 需要已安装可加载插件的 ReShade/RHI，以及游戏原生 D3D12 DLSS Super Resolution。不要同时启用另一个 ShortFuse/RenoDX Direct Neural Rendering 插件。
5. 首轮关闭游戏的光线重构（RR），选择 Mode 2、Reference（参考）、效果强度 1、颜色跟随 0、最大亮度倍率 4。在固定位置用 F6 比较。确认正常后再试默认 Quality（高画质）或 Balanced（平衡）。
6. RR 活跃时会安全旁路；游戏若保留 RR 对象，关闭 RR 后可能需要重启游戏才能继续 NR 测试。
7. 如果回退旧版，退出游戏后移出新插件，恢复备份的整套旧文件和配置。

本次只生成本地构建和安装包，没有改动游戏安装目录，也没有推送 GitHub。

## 本次验证结果

- 中英文插件和 `nrchain_nvngx.dll` 均编译成功。编译提示来自 ReShade 头文件的兼容性警告，没有项目源码警告。
- 共 17 项验证任务通过：beta0.4 结构、DRS 结果尺寸、数学、诊断身份、历史映射、旧高光实验、截图标签、着色器编译、资源合同、观察器、阶段采集、阶段生命周期、原生命令状态、D3D12 命令状态、D3D12 编解码、静态分析、命令状态故障对照。
- 编解码检查覆盖 43 组配对／网格场景；命令状态检查覆盖 12 场景。故障对照能正确拒绝故意破坏的状态恢复。
- D3D12 图形测试使用 Windows 的 WARP 软件设备；这不是显卡上的真实游戏测试。调试层不可用，但图形输出数值检查通过。
- 中英文插件及桥接 DLL 的静态分析均为零诊断。
- 尚未验证本次合并版在真实游戏中的画质、帧率、HDR 闪烁、启动／退出稳定性或 RTX30/40 兼容性。不能据此承诺消除崩溃或提升帧率。
