# D20：FG 呈现保护与描述符开销恢复候选

从已交付 D19 R3 `bbfc0b9315679d21b44671773f3a4a1600865ab4` 接续，保留 R2/R3、三入口、低成本多层与开发者选项。云端 D19 修复包作为局部源码输入；其未完成的临时缓存接线在独立工作树补齐。没有合入 #236 旧分叉，也没有改动游戏文件。

## 行为

- FG 拥有呈现链时，禁止以最近 SR 回执将不明归属的最终 backbuffer 当作真实帧执行 NR。兼容模式请求可在有效的原生 SR 边界临时走后置 NR，保留用户保存的起点和游戏 FG 设置。界面和日志显示实际位置。
- 这条替代路线处理 FG 消费前的重建结果，不等同于 FG 开启时的最终整图 NR。缺少合法原生入口时跳过，不能把停用 NR 当成兼容成功。
- 成功观察到的 Streamline DLSSG 设置仅作为呈现拥有权证据，不证明生成帧身份。旧 FG 实例的设置不能授权新实例；开关和生命周期变化不会永久覆盖保存的 Present 路线。
- 描述符资源身份在已有、持有引用且完成发布的对象内记录上读取；只有首次发布需要全局锁。维持原有对象退休、别名和格式合同。
- 描述符复制临时记录按线程复用两个有界缓存，嵌套溢出独立分配。地址预检失败不结束旧缓存中的写入票据。默认完整描述符镜像保持开启，不通过降低模型精度或层数获取性能。

## 证据与边界

2077 的失败样本显示兼容路线仍在处理最终输出，且开启 FG 的标注窗口有更多 Present 机会。崩溃记录为 120 秒 Watchdog 超时，来自另一进程；尚未证明插件访问违规或特定队列死锁。

鸣潮样本内部版本分别为 D13 和 D18，D18 窗口存在大量描述符复制。外部文件名中的帧率不是连续测量，不据此承诺恢复到某个 FPS。测试结果、冻结 HEAD、生成清单、PE 版本及中英双语常规／测量产物哈希随候选交付，游戏验证保留待验。

## 集中验收

1. 使用常规版，先在 2077 固定场景选择兼容模式、保持 NR 开启。记录 FG 关闭时效果和 F8；开启 FG 后确认实际位置、NR 可见效果和 FG 帧率收益均存在。
2. 重复关闭／开启 FG、读档和进入场景，观察持续闪烁或超过正常加载时间的停顿；稳定运行至少五分钟。出现异常立即保留该进程的 F8 与崩溃报告。
3. 鸣潮或掉帧游戏按相同存档、相同 SR/FG/NR 精度和层数比较 D13 与 D20 常规版。稳定后分别记录 F6 开／关的帧时；若仍有差距，再使用测量版采集一次 F8，避免将测量开销混入常规版 FPS。
4. 开发者选项先保持默认。若需要比较描述符低开销模式，单独改变该项并重启进程，保留两份样本；不要同时改变 FG、模型比例和层数。
