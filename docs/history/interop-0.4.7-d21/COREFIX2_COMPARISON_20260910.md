# Corefix.2：默认迁移、完成等待与闪烁对照

本候选接续 `bba65ebd`，版本 `0.4.7beta-corefix.2`，PE `0.4.7.7`。冻结验收源为 `92c5eacc03eb21b80d4390e8f8f7b154a7ef7f33`，分支 `codex/corefix2-integration-20260910`。本轮实现共用机制，不以游戏名称增加渲染例外。

## 行为

- 实验 NR jitter 新装、首次升级与恢复默认关闭。复用 `JitterPolicyVersion=1`，关闭值成功写入后再写标记；失败保留可见状态与本次会话的手动选择。已迁移后手动开启可跨重启保存。原生 SR jitter、POST 已解析颜色网格的零坐标、额外增强算法和其他个人设置不变。
- 已提交 NR 工作默认使用精确 fence/value 的事件等待，保留 50ms 总预算、原上下文锁与队列准入。每次醒来复查实际完成值；事件创建／注册等失败仍走原轮询。每个既有队列最多一个待通知事件，超时或设备移除不会提前释放仍被注册引用的句柄／fence。
- “反馈与诊断”新增正常／暂停自动采样，以及事件／旧轮询对照与新计时段按钮。对照不落 INI，不停止 NR、不重置历史；暂停包含恢复探针，迟到读回保留原采样身份。F7 显式采集独立，比较期间不混入图像采集。
- F8 区分实际路线、配置、Feature／设备、采样和等待阶段，保留有界 CPU 阶段直方图与近期调用身份。普通 SR 与实际 RR 各有载体记录，RR 不借用普通 SR 的恢复结果。旧载体后续工作不能进入新阶段统计。
- 恢复说明分别展示连续调用／提交事实与存储比较缺口。部分存储期望仍是 unknown；执行事实不再被误报为全部缺失，也不把执行成功提升为最终画面恢复。

`scripts/summarize-runtime-timing.py` 读取 F8 当前元数据，输出当前计时段的累计 CPU 观察。嵌套阶段不可相加，p95/p99 是直方图区间，混合身份、溢出或缺少时钟不能作为干净的性能数据。它不输出游戏 FPS、GPU 推理耗时或输入到显示延迟的通过结论。
