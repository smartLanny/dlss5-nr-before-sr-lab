# D9：完整输入采集与独立模型实验

这是0.5精细画质计划的第一批实验基础，不是人脸或反射修复。继续保持单次NR与独立D分支。

## 已接入的入口

“反馈与诊断”新增完整模型重放采集。它临时独占诊断设置，从新实例开始记录16次连续成功推理；不改写INI。完整活动原图、模型代理、模型输出、深度、运动、可用曝光和实际合成结果分别保存。代理和导引保留实际模型资源网格；原图与合成只读完整活动矩形，不导出私有结果纹理未写入的边缘。

`.nrf`是固定宽度小端格式，保存类型化GPU读取值、格式、物理尺寸与矩形、参数存在性、曝光、实例/帧/配置及重置身份，以及实际合成常量。它不是PNG，也不是旧五平面采样包。只有精确队列完成信号和命令列表释放均满足时才移交文件线程；重放列表、未提交列表或失去连续性会使结果不完整。

采集上限为16帧、每帧512 MiB、驻留缓冲请求合计1.5 GiB、序列8 GiB；分配、读取、写入或30秒等待失败均保留不完整状态。配套运行库、桥接和参数分配函数所属模块的文件哈希由导出线程记录；这是加载路径文件身份，不能冒充映射内存哈希。正常运行不启动该采集，显式采集期间可能增加GPU/IO开销。

旧分组截图、旧采样和新重放采集串行取得设置控制权。无法取得时不修改设置，也不释放其他诊断持有的控制权。异步导出不访问已经释放的渲染槽。

## 独立工具

- `scripts/nr_replay.py`检查完整序列、参数、空间和历史连续性、文件大小与哈希；按需映射单个平面。
- `tools/nr_model_lab.cpp`在独立进程创建D3D12设备、队列及NR实例；支持完整序列和明确标注的“裁剪代理+合成零导引”实验。后者不能代表完整游戏回放。
- `scripts/run-nr-replay.py`核对当前运行库与采集身份，执行模型并逐帧比较实际NR输出。相同参数不能复现参考时，不得将改参结果提升为已复现游戏问题。

独立工具中的运行时回调仅用于实验进程；Core没有注册它。当前重放工具支持实际FP16 RGBA代理、FP16/FP32双通道运动与FP32深度，其他导引存储明确拒绝，不猜测转换。

## 已取得的研究结果

相同裁剪代理、零深度/MV、同一310.8运行库的独立实验已实际执行：结构1/1.5/2与Skin0/2及AutoMask关闭对照、结构回调覆盖、1→2→1切换和重复基线。该裁剪实验未复现“高结构下人脸控制失效”；回调结构2与普通参数冷建结构2在检查区域一致。普通重建和回调切换返回1后的区域结果也与对应冷建帧一致。这不排除完整场景、导引和游戏生命周期问题。

重复输入仍有帧间变化，不能将64次运行直接称为已收敛。独立模型自带文字显示区未纳入脸内与图像区域比较。实际参考来源、参数、逐帧输出及校验数据留在私有证据中。

同一YuNet模型以固定0.6阈值检查18张原代理脸部裁剪：192×192输入全部检出，512×512全部漏检。样本来自一个角色；这只是尺度实验，不是多人物、全屏、时序或游戏性能验收。

## 验收边界

新采集的实际WARP像素、类型转换、矩形、精确完成与文件解析有独立测试。完整生成Core、双语界面及实际游戏采集结果另行记录；独立模型运行不能代替Core在游戏中的验收。

人脸识别运行时、原图保护、可信反射分区、前后置合成优化以及整帧GPU中位数/P95不超过5%的目标仍在后续批次。没有合并ABC新修复、main或稳定版。
