# D21 Perf8：两条 NR 路线共有的生命周期与复制成本

Related to #277 / #272 / #273，接续 Perf7。增量基线 `a3ea8f9cbf3e06662e622852dc11581973798d18`，研究目标仍为 `next/0.5`。不混入 colour/uniform/D22，不自动合并 main、部署游戏或发布 Release。

## 实测依据

重新读取维护者的两份 Perf7 ETL、逐帧 CSV 和 F8，确认均为交付 Core `b72b5c38…`，参数 2/2/2，单层。前置 NR→SR 工作尺寸 2228×1253，后置 SR→NR 的 NR 工作尺寸为 3520×1984、源/输出为 3840×2160，分别比较，不能把前置约 63 FPS 与后置约 51 FPS 当作版本收益。

| 路线 | 首次 OFF FPS | ON FPS | 再次 OFF FPS | 对应插件 self CPU ms/s |
|---|---:|---:|---:|---|
| NR→SR | 81.69 | 62.98 | 82.56 | 37.76 / 106.62 / 65.39 |
| SR→NR | 84.18 | 51.16 | 84.52 | 36.25 / 93.07 / 71.82 |

两份 trace 均零 lost events/buffers，CSV 无重复起点。CPU 显式 UTC 区间与 PresentMon 录制相对窗口分别位于稳定阶段，未声称恢复精确 QPC 对齐，不计算跨窗口 CPU-ms/帧。前置首次 OFF 的后台安全扫描负载明显不同；不把跨次小幅 FPS 差异全部归因于代码。

使用匹配 Core 的编译函数区间聚合全部 sampled-IP 样本，而非仅看前十名。ON 的 SourceStateTable::Rebuild 为前置 8.70、后置 11.32 CPU ms/s；ProcessCommandListReset 为 11.62 / 9.01 ms/s。实际指令表明 Reset 内的热点包括内联 EraseListLifetime/EraseIf 的 256 项扫描，随后调用 Rebuild。这是原 Perf7 查找优化没有完整覆盖的生命周期成本，不把整个 Reset 自耗时错误地归因于大对象清零。

两路还共有 NormalizeUnknownRanges 的比较排序热点，首次 OFF 约 7.63 / 6.20 ms/s。原始排序快路只帮助已经有序的输入，无法消除实际未排序批次的成本。

## 本轮实现

### 来源状态：查询和退休使用同一套可维护索引

`src/nr_source_state_table.inl` 保留 256 个稳定值槽和 512 个开放寻址桶。加入每槽 home/当前位置，以及以 list+lifetime 分桶的相对成员链。Reset/全录制失效只遍历相关成员，完整录制失效仍比较 reset/device；哈希冲突必须比较完整身份。

删除使用 backward shift 修复受影响探测簇，更新被移动桶的当前位置，原值槽不移动。无需清空并重哈希其他录制。资源地址/列表地址退休仍按原谓词覆盖所有相关生命周期，不减少失效范围。链中的碰撞成员和同地址不同代次不会误删；删除过程先保存下一成员，不跳项。

保留 first-free 顺序、容量、无淘汰、满表失败、空键诊断、来源字段和调用者原有 EXCLUSIVE source_lock。索引和成员链均为固定数组，无热路径分配。复制/清空整个表时所有相对索引一起复制/清空，不能跨对象保存指针。

### 命令列表 token：只缓存槽位置

`src/nr_command_state.inl` 的 FindCommandStateTokenLocked 加入 64 项线程局部槽编号提示。调用者仍先持有原 registry shared/exclusive 锁；每次命中读取当前 token，其他 native/ready/reset/meta/state 校验照旧。未命中不缓存否定结论，退休/槽复用时旧 token 不可命中。临时 alias 规则与 COM 私有数据读取没有绕过。

这不是把快照内容或有效性结论放进 TLS，也没有改动成功 Reset 的事务顺序、失败 Reset 行为、状态恢复和 GPU fence 退休。

### 复制范围：重用存储并按真实形状选择排序

`src/nr_descriptor_provenance_runtime.inl` 的 UnknownCopy 使用既有可重入 ScratchBuffer 模板持有范围数组，完整 native copy 和未知窗口结束前不释放。与排序临时区共享最多两个 2048 项线程局部块；嵌套/大批次保留独立 owned 存储，分配失败仍走原保守处理。每个活跃线程两块范围存储合计约 96 KiB，线程退出释放；不是 GPU 资源缓存。

`src/nr_descriptor_provenance.h` 对已经有序/小数组保留原路径。较大的单类型反序数组反转；常见局部地址的乱序数组使用稳定 byte radix，只处理变化的低地址字节。分散地址、混合类型或临时存储失败仍用完整比较排序。只操作插件自有数组，不改变原生 API 参数。

相同起点的末端无需预先排序，因为最终同类型并集取 max(last)；结果仍与旧规范化输出一致。只能合并相交或字节相邻区间，不填补 descriptor stride 空洞，不把未知 view 当作有效。

未修改 NR 层数/模型/shader/尺寸/subrect、SR/RR/FG 路由、HDR、曝光、抖动或深度/MV，也没有关闭 hooks、跳过恢复、扩大批次容量。首次 NGX 加载/Feature18 创建卡顿没有通过 OFF 预热或任意后台线程隐藏。

## 新回归与实际结果

`scripts/validate-perf8-lifetime.py` 从冻结 Perf7 Git 对象提取旧生产头文件/函数，以当前实际文件为候选。计数只注入临时副本，不进入 DLL。

- 12,000 步混合状态发布、精确删除、Reset、资源/列表退休；2,000 次满表中局部 Reset；复制后的容量行为与原表逐项一致。
- 实际函数 4,000 次 token 槽位替换；真实 Windows SRW 下 40,000 次并发查询穿插 4,000 次退休/发布事务，旧 token 不能复活。
- 1,000 次局部 Reset/重登记，旧扫描/重哈希计数 512,000，候选成员/探测簇/哈希计数 7,194。32,000 次热 token 查询的全表比较 65,040,000→0；仍有每次必做的当前 token 检查。
- 完整 Reset→Put→Get 的 20,000 次合成事务，旧约 28.5–28.8ms，新约 2.14–2.17ms；普通 Get 基本持平。包含实际操作和可观察校验和，不是只对比理想查找。
- 300 组范围并集差分，包括高地址、同起点、反序、混合类型、非法输入、字节空洞和两层占用 scratch 后的独立回退。
- 初版 radix 在分散地址/反序上退化，已调整为形状选择。最终 650 项局部乱序的 500 次完整规范化约 2.03→1.10ms；650 项反序约 0.89→0.60ms。小数组和分散地址保留比较排序；不是所有微场景都更快，4096 项完全分散地址单次测试仍有波动/少量分类成本。
- 继承 Perf7 的 3,500 混合 Barrier、真实 SRW 快照、纯 UAV 身份副作用和前后路由 36 项及负控已通过；Perf6 缓存/有序范围门禁通过。

新增 ScratchBuffer 依赖已显式加入旧描述符抽取夹具，不使用静默 skip 掩盖缺失头文件。生产 ScratchBuffer 本身未修改。

以上是源码/Windows CPU 验证，不是游戏 FPS。完整双语构建、WARP 和产物身份以同名 Windows 交接文档及实际回执为准。

## 下一轮验收

同镜头、同 INI/模型/桥接器/画质分别测试前置与后置的 OFF→ON→OFF，保留两条现有 Perf7 作为匹配基线。优先检查实际 Reset/重建成本、范围排序与分配的变化，再看 RHI/提交线程和帧时间。不要重录旧四版本矩阵，也不把低分辨率前置与 4K 后置的差异算作本补丁收益。
