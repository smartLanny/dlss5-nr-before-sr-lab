# D21：启动起点与关闭态开销候选

从冻结 D20 `7a0b5717aab11fe5ef7b4efabc074e71615b2f58` 接续云端性能优先增量，保留 R2/R3、D20 FG 呈现保护与多层 NR。云端已写入的规范资源身份缓存合并到独立工作树；没有覆盖原工作树或用户游戏配置。

## 本次行为

- 默认每个新进程从「先增强，后放大」开始，由已有状态机按需尝试后置、兼容模式。旧 INI 的手动 Present 不再自动成为新进程起点。
- 「下次仍用此手动起点」显式设置 `RememberProcessingStart=1`，才跨启动保留手选 After/Present。本次手选不会被定时 Reload、F6 或普通设置保存覆盖。只切换记忆偏好不改变路线选择序号，不重置 NR 历史，也不打断已经工作的回退。
- 生产启动默认使用低开销描述符记录，包括配置读取前的早期观察。完整 GPU 诊断由 `DescriptorFullGpuDiagnostics=1` 明确开启，在下次进程生效。仍保留原生调用、CPU 视图准入、对象生命周期、退休和地址复用检查；未镜像的 GPU 修订证据继续是 unknown。
- 重复规范原生 CreateView 可复用已发布且同设备的资源身份索引；代理和未知情况仍走原验证路径。
- 测量版追加小数毫秒字段，保留旧纳秒字段；不改变指针和本地路径脱敏。常规版明确标为未测量，不伪造零耗时。
- 模型层数、NR/SR/输出尺寸、原生 SR/RR/FG 调用数、合成和 fence 合同不变。顶部追加说明只解释状态，F6 不会清除未知生命周期等进程保护。

## 来源接线与验证

云包 staging 工具沿用旧的生成器导出行与单个描述符快照假设。本地只适配实际导出锚点及带计时的快照块，并修正记忆偏好不应进入历史比较这一缺口。版本、配置模板与测试依赖随候选更新；原报告和最终 HEAD/pins 核对分别保留。

需要验证真实 Win32 INI 保存／新进程启动、手选和 F6/Reload 保持、Remember 不改变历史；完整诊断与正常低开销下的原生 CPU Clear 准入、规范／代理身份与退休；实际 F8 格式化、脱敏和文件写回；普通／测量双语构建和默认低开销下的真实 NR 输入／输出。结果与产物哈希以冻结交付记录为准。

## 游戏待验与开放问题

用户现有 D20 性能日志所标产物为测量版，OFF 时 NR/输出/导引增量为零，但描述符记录仍有显著 CPU 工作。该证据支持优先减少常驻诊断工作，不能证明其解释全部掉帧，也不能承诺恢复某个 FPS。

先在异环／2077补同条件 ReShade-only 与新常规版启动即 OFF 的独立短窗口，再看同模型工作条件 ON、ON 后 OFF 的恢复和 FG 开关。不重复索要已有 F8/CSV；测量版只用于定位，不混入常规 FPS 验收。

本增量未修复古墓暗影 #223：direct late-core Evaluate 的未知句柄缺少完整创建／转发记录，已有成功 preflight 不足以追溯证明它。继续保留原输出和失败保护，不能猜作 Feature1。#272/#273/#223 在游戏证据通过前保持开放。
