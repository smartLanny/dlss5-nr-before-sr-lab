# D21-223fix1：首次 Core 生命周期入口

基于冻结 D21 `6c3a26fb610fb0b4d3de661fe7db25479a0a24f9`，保留其性能与配置修改。新版本为 `beta0.5-dline21-223fix1`，PE `0.5.1.22`；原始 D21 不重标。

古墓丽影暗影 #223 的原始 F8 首个故障显示模型层 Create 已观察到，但 Core 首次 Evaluate 没有对应的完整生命周期记录。不同日志 token 不足以证明是不同物理句柄。证据与外层 Core Create 已开始后才安装 Core 钩子的时序缺口一致。

在 NGX loader 的 Init / Init_Ext / Init_ProjectID 返回边界安装 Core 生命周期观察，使后续首次 Create 进入已有记录链；透传原参数和返回值，原生 API 仍只调用一次。模型尚未加载时也覆盖已加载 Core。Init 完成、初装及后续扫描采用统一发布锁序，避免半发布表与错误的模块代次变化。

不降低 unknown-evaluate 保护，不猜测 Feature ID，不清除已有不确定故障，也不依赖提高扫描频率。若实际游戏初始化在插件可观察之前已经完成，仍可能保持隔离，必须由实测 F8 区分。

F8 新增 loaderInitHooksReady、loaderInitCompletions、coreLifecycleReady，不输出应用 ID 或项目路径。相关自动检查覆盖实际生产 detour 的 Init→Create→Evaluate、关闭启动后再创建、模型晚装及并发发布；游戏 #223 仍待用户验证，模拟检查不能代替游戏结论。

交付只选中文测量 Core 与配套 bridge。D13 使用原二进制作为基线。测量版本自身有计时开销，比较需固定场景、处理位置、精度和层数，并记录 F6 开/关及 F8。
