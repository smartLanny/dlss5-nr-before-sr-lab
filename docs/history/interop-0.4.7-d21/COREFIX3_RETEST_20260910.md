# Corefix.3 实机复测：输出观察盲区与阶段隔离

维护者复测仍失败。死亡搁浅同进程、同配置、固定后置路线依次测试正常采样、暂停采样、仅输出状态切换、恢复正常采样：正常与仅状态切换时偶发闪烁，暂停时不闪，四阶段都没有持续可见效果。后续补充确认闪烁更像 NR 增强短暂出现。近期状态的“正在检查”与“已观察到”跳动在暂停时仍存在。绝区零仍无效果。

五份实际报告均绑定冻结源 `462e61d7617b2f8d15b6e35587d87cfe17275bca` 和中文 Core SHA-256 `d0018ab108e901e8bb51f4f601a15353b4946b2d5fd84401923e7360910365a9`。它们不是新候选的实机验收。原始报告、路径、详细日志、哈希清单及私有复现保留在本地证据区。

## 死亡搁浅：处理持续，最终显示未闭合

四次 F8 各自约 0.8 秒的收集区间中，NR 成功／输出提交分别增加 `23/23`、`25/25`、`24/24`、`24/23`；未增加未知队列旁路、队列不匹配、退休等待或超时。配置与 Feature 范围保持不变。最后一份差一次提交不能推导为整段未执行。

首尾正常采样的实际 Output 稀疏读回发生变化；暂停和仅状态切换报告保留的是先前正常阶段的旧样本，不能冒充当前阶段读回。期望量化值仅在部分采样点唯一，而实际统计覆盖全部点，所以不同 hash 不是写回错误证明；存储比较仍为 unknown。仅状态切换有本阶段的明确记录，但它不测量像素。

原生调用期间确有对 Output 的 UAV 清除；它发生在本插件后置合成之前。后续 RTV 绑定、Draw 和 RT 清除的目标均未解出，不能断言覆盖了 Output。Execute 数组位置还表明 CPU 录制先后不等于 GPU 使用先后。当前证据既没有确认最终消费者，也没有证明后续覆盖。

暂停仍持续进行普通后置快照及 NR 合成。与正常／仅状态切换的差异涉及合成后的附加 UAV 屏障和状态往返，不能概括为暂停取消了所有 Output 状态转换。普通合成已有 UAV 屏障，因此不能仅凭闪烁先补一条同类屏障并宣称修复。维护者“增强短暂出现”的观察提高了写入可见性和后续消费问题的排查优先级，但还不能区分具体原因。

## 绝区零：原生视图解释仍未取得

报告收集区间载体增加 40，NR 与输出提交均为 0。Output 是 typeless R8 资源；硬件支持多种合法解释不等于已确认原生使用哪种。报告已捕获显式 Output UAV 清除，但描述符使用链仍为 `list=0`、`identity=0`、`paired=0`、`typed=0`，因此拒绝继续。不能再表述为“未出现 Clear”，也不能据可用格式默认选择 UNORM。

两款游戏都有描述符观察链缺失：现有命令状态捕获可经私有 token 找到原生命令列表，新观察入口却按原始接口地址查找。ReShade 的代理还会共享底层私有数据、返回虚拟 CPU 描述符地址并在转发时转换到原生地址。相同对象不一定具有相同接口地址或 CPU 句柄数值。

未修改冻结源的完整生产翻译单元已通过 27 项纯 CPU 复现断言：原生对象对照成功；代理对象可被既有状态捕获识别，但新观察器丢失列表身份与 CPU/GPU 描述符配对；转发复制还会造成重复观察。该测试未创建 D3D 设备、未提交 GPU、未加载 NGX。它证明观察器的共享身份／句柄域缺陷，不证明游戏实际格式或画面根因已经确定。

## 面板状态：需记录真正触发重置的事件

“正在检查”只在 UI 近期活动窗口无效时显示。现有条件包括初次观察、绘制间隔超过两秒、时钟倒退、配置／管线范围变化、计数回退，以及读取期间范围变化。探针 phase、Output token 和路线锁不参与此判定。

当前 F8 没有 UI 绘制线程、实际间隔和重置原因，不能从 NR 持续增加推导 UI 窗口必然连续有效。接续只记录同次真实 UI 调用的原因和最终选中文案，保留原阈值、观察次数及显示判据，避免用旧状态掩盖问题。

## 接续边界

- 修复可验证的对象别名、生命周期和 CPU 描述符域关联；歧义、过期和未观察情况继续拒绝，不引入游戏名单或默认格式。
- 为暂停／仅状态切换阶段增加独立 CPU 只读边界票据，不增加 GPU 命令，不改写旧样本的 frame、phase 或 trace；仍限定一组 18 条事件。
- 为近期状态增加有界 CPU 回执，F8 只读取已经产生的记录。

这些是下一候选的实施目标，验收、产物、部署另行登记。Corefix.3 的实机视觉失败继续有效；本地复现、编译、软件 GPU 检查和真实游戏验收分开记录。
