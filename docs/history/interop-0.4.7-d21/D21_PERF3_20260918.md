# D21 Perf3: descriptor-range and source-lineage hot paths

Related to #277, with shared OFF-state overhead tracked in #272/#273.
The owner requested continuation after the four-version OFF/ON/OFF recordings.
This candidate is based on the actual Cursor Lock2 build branch at
`63efc2bd5f55a4e9035b8b454dec5a8bb598f5d1` (tested runtime source `1bacd72c`).
Online main was checked at `dae86e9898399c20e52ada54a5ec4350da4d4fa1`;
no newer implementation of these two mechanisms was found in open PRs/branches.
Keep this as a temporary research candidate for `next/0.5`, not main/stable.
Do not merge colour/uniform/D22 changes or deploy into a game automatically.

## Evidence and scope

The matching Lock2 binary/linker map placed OFF samples in
`Registry::InvalidateUnknownSlotsLocked` / `BeginLocked`, and ON samples in
`Lineage::Add`. The four recordings are single-run package comparisons, not
per-patch causal proof. The patch below addresses work reproduced in the real
production headers. CPU microbenchmarks cannot predict a game FPS improvement.

Only two production files change:

- `src/nr_descriptor_provenance.h`: exact-key invalidation for narrow descriptor
  ranges, a single decoded interval for broad single ranges, and validity-gated
  descriptor payload updates.
- `src/nr_source_frame.hpp`: a four-entry per-Lineage batch-index cache, checked
  against the complete recording tuple on every hit.

Models, layer count, NR/SR/RR/FG routes, shaders, extents/subrects, colour/HDR,
exposure, jitter, depth/MV and user settings are unchanged. No hooks are disabled.

## Descriptor correctness

The existing full-key slot index is reused; no dynamic index allocation or
native descriptor read is added. Inclusive handle ranges are intersected with
validated heap extents and converted to indices using division/remainder,
without overflowing at UINT64_MAX or rounding to a neighbouring descriptor.
For small ranges, probe exact `(heap, index)` keys. For large/sparse scopes,
retain the existing heap-membership walk. A single broad range is decoded once.
Live overlapping heaps are all visited independently, including unaligned bases
and different strides. Wrong descriptor types are excluded as before.

The new heap-bucket population counters include colliding heaps, matching the
actual membership traversal. Allocation, eviction, heap retirement and device
retirement maintain them under the existing registry mutex. Default registry
size is 16,581,048 bytes on the Windows toolchain, below the unchanged 16 MiB cap.

Invalidations preserve revision/epoch, pending-write overlap and sticky unknown
semantics. Overlapping ranges may revisit a slot with the SAME revision; this is
idempotent and changes only work counters, never observation validity or LRU.
BeginWrite invalidates `View::known` rather than zeroing the unused payload.
Read returns an empty View for an unknown value before exposing its bytes;
pending reads already return earlier. Finish publishes a complete validated
View; inventories also test validity first. The differential test compares
unknown receipt payloads as well as successful receipts, not just boolean status.

## Lineage correctness

The four cached entries are relative indices into the same fixed 64 batches,
not borrowed pointers. Every hit rechecks list address, lifetime, reset and
device. Invalid recording keys use the original search order. Reset, list
retirement, slot reuse, copies of the Lineage object, submission and capacity
handling remain valid without a separate cache-invalidation epoch. The runtime's
existing external lock still serializes access. No new lock or TLS lifetime is
introduced, and no events/taint/FG-consumed state are removed or merged.

## Executable regression loop

`validate-perf3-hotpaths.py` reads the exact old headers from the frozen Git
object and includes the actual new headers. Temporary instrumented copies count
only full-table comparisons; timed builds and the shipped Core have no added
per-call timing/count instrumentation.

- Old narrow-range negative control: 8,192 slot visits; new: 28. Same eight
  destination indices, with all unrelated receipts and pending rejection kept.
- Old four-list batch lookup: 1,000,000 full-table comparisons for 16,000 hot
  calls; new: zero after warmup. Full tuple validation still runs on cache hits.
- 800 nested-range scenarios plus 4,000 source-state transitions compare exact
  public observations, labels, return values and semantic counters with Lock2.
- Existing randomized descriptor matrix: 120,000 operations and 8,000 threaded
  lifecycles pass against the same frozen Lock2 reference.
- Existing descriptor registry: 2,225 CPU checks pass.
- Existing source ownership policy: 399 checks pass. Its missing
  `ForgetPresentDemand` extraction fixture was supplied as an explicit recorded
  callback and retirement assertion, not by changing the runtime.

Local uninstrumented microbenchmarks measured narrow range widths 1/8/512,
whole-heap scopes and repeated source events. The broad path was checked as well
as the favourable narrow path. Keep the raw timings with the validation receipt;
none of these timings are GPU or game performance claims.

## Build and validation contract

Successor entry point: `scripts/build-perf3-candidate.ps1`, with the same five
path arguments and optional exact-source `NrchainReuseRoot`. Old Lock2/Lock1
entry points forward to it; they must not label new bytes as the historical DLL.
The output identity is `beta0.5-dline21-perf3`; numerical PE identity is inherited
0.5.1.23, so always use the version string, source commit and SHA256 together.
The generator pins the two new production blobs before building.

The builder retains inherited Windows checks, real SRW/Lock2 regressions,
canonical full bilingual build and WARP, then the whole staged Core descriptor
WARP and source-transport WARP. Packaging is allowed only after these succeed.

`post_sr_snapshot_gpu` remains strict about the debug layer by default. On a
host lacking Graphics Tools, the explicit `-AllowMissingDebugLayer` build switch
permits the same WARP byte-readback and wrong-pixel negative control without
InfoQueue validation. The final receipt separately records
`snapshot_debug_layer_verified=false`; it must never be called a debug-layer
pass. No Windows feature, driver, security policy or game is modified to enable
this mode. The snapshot's 1,045 readback checks and transport's 1,700 checks have
been executed in preliminary Windows tests; final build receipts are the source
of truth for delivered artifacts.

## Owner acceptance and remaining risk

Verify a single Core is loaded; retain current INI, model files, ReShade/bridge,
and matched D21 nrchain. First compare Lock2 vs Perf3 in the same fixed scene:
cold OFF, ON, and OFF after activation. Record transition spikes separately.
Pay particular attention to active NR success counts, reset/rebuild, descriptor
copy-heavy scenes, post-SR/Present route, RR and FG compatibility. Broader game,
NVIDIA inference and weak-CPU FPS acceptance are not replaced by host/WARP tests.

A bypass, missing effect, flicker or crash requires rollback and an F8 TXT/Core
log with version/hash in a bug report. Safe bypass is NOT a performance pass.
First-activation and disable-transition stalls remain a separate follow-up;
Perf3 does not claim to fix them. Unknown/pending data, resource lifetime and
submission safety take precedence over reduced overhead.
