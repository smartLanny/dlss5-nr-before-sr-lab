## Evidence motivating this change

Perf4 reduced the sampled source-lineage saturation path but its descriptor
hotspots still landed in the `!indexed` heap x range fallback. The ordinary
trace could not distinguish which fallback condition fired. The preceding
microbenchmarks did not cover all density, repeated-range and fallback costs.
This candidate changes the runtime input representation and the fallback query,
not only the favourable heap-index branch.

## Runtime changes

`NrDescriptorBeginCopy` already allocates and owns a metadata copy of unknown
destination ranges. Before publishing that scope, it now sorts this private
array by type/address and coalesces its EXACT inclusive address union. No extra
allocation is introduced, no application argument is mutated, and preparation
happens outside the registry lock and before the original D3D12 call.

Only same-type overlapping or byte-adjacent intervals merge. Descriptor-stride
gaps do not merge: an overlapping heap with a different base/stride may contain
a valid descriptor in a gap. Input validation precedes mutation; zero handles,
inverted/missing ranges and allocation failure retain the old global-unknown
path. Maximum-address operations avoid incrementing UINT64_MAX.

The registry detects sorted/disjoint arrays rather than trusting a caller flag.
It retains them for exactly the existing UnknownCopy lifetime. Ordered masks
and fallback heap intersection use binary endpoint queries. The per-heap
preflight uses two binary bounds; if more than 64 fragments overlap a heap,
it uses the existing slot walk with logarithmic masks instead of scanning all
fragments before that walk. Sparse heap lookup, pending/revision/epoch rules,
resource lifetime, overlap ambiguity and native-call lock boundaries remain.
Raw/nonordered API clients remain valid through the old exact path.

The fixed registry gains six batch counters (48 bytes, no new per-slot timer):
ordered copy scopes/ranges, raw scopes, indexed invalidations, ordered and linear
fallbacks. They are written under the existing mutex once per metadata batch
and copied to F8 as `descriptor.rangeQueries`. This lets the next game recording
prove whether the new runtime path is used rather than inferring it from a
missing top-ten hotspot. Values are cumulative operations, not CPU/GPU time.
The default registry remains below 16 MiB (16,581,096 bytes on the Windows build).

Only `nr_descriptor_provenance.h`, `nr_descriptor_provenance_runtime.inl` and
`nr_feedback_capture.inl` change in production. Perf4's source-lineage fix is
unchanged. Shaders, NR/SR/RR/FG routing, models, layer count, extent/subrect,
format/HDR/exposure/jitter/MV/depth and INI settings are unchanged.

## Regression loop

`validate-perf5-ranges.py` extracts the actual frozen Perf4 headers as reference
and compiles actual candidate headers. Only temporary test copies contain work
counters. Timing runs include per-copy array copying and normalization costs;
measurements are CPU microbenchmarks, not predicted game FPS.

The dense-overlap negative control performs 343,000 tested predicates; the
candidate performs 3,426 with the final bounded preflight. The reference must
fail the work budget, not merely compile successfully. Ordered and raw fallback
counters are checked through Begin/End and scope reuse.

Additional cases cover type changes, repeated ranges, unsorted fragments,
nested scopes, pending writes with late Finish, heap retirement/creation while
a scope is active, exact unknown receipt payloads, 64 deterministic range-union
sequences, UINT64_MAX, malformed input and byte-address gaps. A 128-fragment
case uses two overlapping heaps offset by one byte: unaffected aligned
slots must remain valid both during and after the copy. Existing Perf3/4
randomized/concurrent descriptor and source saturation regressions remain.

The runtime preparation seam is verified before scope publication, and the
complete generated Core is used by the inherited descriptor WARP test. The
canonical bilingual build, real Windows SRW, source transport WARP and
snapshot readback/negative controls are not skipped.

## Primary API contract reference

Microsoft documents descriptor copies as immediate CPU-timeline operations,
with potentially multiple source/destination heaps and free-threaded execution
only when conflicting writes are avoided:
https://learn.microsoft.com/en-us/windows/win32/direct3d12/copying-descriptors

The patch preserves those original calls and their arguments; it optimizes
only the layer's own conservative observation metadata.
