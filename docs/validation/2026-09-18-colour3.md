# colour3: owner-feedback quality experiment

This candidate follows real owner testing of colour2. It is intended to isolate remaining structure loss and the observed pre-SR 99%/100% colour/brightness cliff. Source changes are not game-validation evidence.

## What changed

- `ColourRestoreMode=2` is a **raw model RGB-edit reference**. It bypasses D21's aesthetic output attenuation (overall transfer target, LightingLock, DetailStability/edge/region/face attenuation) while retaining finite/gamut/MaxLumaRatio and all resource/view/subrect/queue/writeback safety.
- `ColourScaledProxyMode=1` is a **pre-SR sub-native input topology** experiment. It prepares each source tap into the model proxy first and then exact-area averages the stored proxy. D21 mode 0 keeps source-average→encode. This selector resets NR history.
- `ColourInputCurve` remains an independent paired-N2 experiment and defaults to 0.

No new texture, descriptor, NR invocation or GPU pass is added. Proxy-first preparation increases per-tap ALU for sub-native exact-area input and must be profiled after quality is established.

## Model controls

Use `LocalTone=1` and `LocalStructure=1` for the first nominal comparison with RenoDX, then repeat at 2 only as an experimental sweep. The fixed model DLL does not expose `DLSSNR.GlobalToneStrength` according to the current Opti source/model scan, so colour3 does not add a GlobalTone UI that would imply a verified model capability.

Keep the character/clothing region in the centre and capture StageCapture/model-before-after:

`original → proxy → neural → composited → final screen`.

Interpretation:

- D is Reno-like but B is weak → D21 output protection/compositor is suppressing model detail.
- D neural is already weak → focus next on model input, actual LocalTone/LocalStructure binding, work size and guides.
- D-P99 removes the dark-character cliff relative to D-99 → retain encode→downsample topology, then optimize its ALU.
- D-P99 still differs heavily from D-100 → next isolate motion/depth guide scaling; do not hide it with colour tuning.

Compatibility/Present is a different source stage and remains a separate comparison. Its different colour/brightness is not evidence that native NR→SR or SR→NR is correct or broken.
