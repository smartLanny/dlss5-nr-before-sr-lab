# colour2: build gate and controlled owner comparison

This document accompanies the source implementation, not a tested addon. No installation was performed. No RenoDX-level quality or FPS improvement has been measured.

## Windows build gate

Use a clean checkout of `codex/d21-colour-texture-lab-20260917`, the existing pinned upstream v1.4.12 checkout, existing LLVM-MinGW/ReShade inputs and the normal bridge/NGX inputs. PowerShell, not bash:

```powershell
.\scripts\build-colour-lab.ps1 -UpstreamRoot '<existing pinned upstream checkout>' -OutputRoot '%DLSS5_PRIVATE%\build-colour2'
```

The output directory must be new. Parameters/environment retain the existing build contract: `DLSS5_LLVM_MINGW_ROOT`, `DLSS5_RESHADE_ROOT`, optional `DLSS5_FACE_RUNTIME_ROOT`, `DLSS5_NGX_SDK_ROOT`, `DLSS5_VCVARS_PATH` and `-ReuseBridgeRoot`. Do not substitute a different model DLL or disable an existing face backend without recording that difference.

The wrapper runs production-math tests, full raw-source contracts, pinned generation, real generated-source contracts and then the existing Windows Core build. The latter must compile all embedded codec/face/dual variants. Missing/failed steps abort. Inspect build outputs and the colour2 manifest/source identity before packaging. Do not distribute a uniform3 output from the old build entry under the colour2 name. PE numeric version is inherited; runtime string, commit and hashes identify this experiment.

No script copies into a game directory. A future tested package must include the chosen Core variant, matched bridge requirements, source identity, SHA-256 and an INI backup/rollback note. This publication contains source only.

## Owner comparison after a successful build

Keep scene/save/camera, game settings, NR model DLL hash, actual model parameters, NR layers, NR input dimensions, SR preset, exposure/paper-white and all picture-protection values fixed. Start with FG off. Do not silently switch native input versus final Present sources to make one candidate look better.

| Group | ColourLabMode | ColourRestoreMode | ColourInputCurve | Purpose |
|---|---:|---:|---:|---|
| A | 0 | 0 | 0 | Inherited configured D21 baseline |
| A1 | 1 | 0 | 0 | Isolate colour admission alone |
| B | 1 | 1 | 0 | Against A1: isolate RGB recovery, same NR input/history |
| C | 1 | 1 | 1 | Against B: paired N2 HDR input; allow history to settle |

A→B changes two things; A1→B is the compositor-only comparison. Old colour opt-in may make A and A1 identical. On bounded SDR/model-value inputs C legitimately retains the original input; inspect the recorded input-curve reason. An SDR monitor does not prove the internal source is SDR. The Legacy button restores 0/0/0, not every other user's saved preference.

Run each group separately for native NR→SR, SR→NR and RR→NR. Present is an independent compatibility test. First preserve normal protection settings. For a mathematical reference only, repeat at T=C=1, LightingLock/EdgeGuard/detail protection 0, neutral light/region/face controls, and an explicitly recorded ratio cap; never call this neutral setup the default aesthetic recommendation.

Minimum image checks: skin/colour, formerly zero or highly saturated channels, wall/fabric fine texture, dark gradients, bright lamps/specular highlights, slow camera motion and disocclusion. Test C=0/0.5/1 and T=1/2 independently. The model may supply little colour change in some scenes; slider movement alone is not a required visual difference. Capture same-stage original/proxy/neural/composited samples where possible, plus final screen evidence.

Runtime regressions: F6 off/on, save/restart, changing restoration without input-history reset, switching N2 with reset/settling, resize, resolution changes, camera/scene cuts, native SR/RR fallback, more than one NR layer, face on/off, and later FG reintroduction. Check frame time, GPU memory and frametime tails; no zero-cost claim follows from zero added passes.

On bypass, wrong colours, crushed blacks, high highlights, flicker, no visible processing, crash or unexpected baseline fallback: retain/restore the original path, collect F8 and report the game, candidate identity, selectors, actual dimensions, fixed model hash and the failing group. Do not disable GPU lifetime/queue protections to force a comparison.

## Limits

Source-reference RGB + paired N2 follows the tested mathematical idea, not a reconstruction of every RenoDX source-domain/gamut/default branch. Existing bounded model decoding, source units and filtering contracts remain. Negative original channels currently retain the exact original, and HDR calibration, low-resolution edges, temporal effects and external plugin interactions still require owner evidence. Analytic inversion of the edited neural image is not implemented. Full-source generation and Windows/GPU validation are release gates, not optional documentation checks.
