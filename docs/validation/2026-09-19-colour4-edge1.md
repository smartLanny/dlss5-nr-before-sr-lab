# D21 colour4-edge1：可开关的配对边缘恢复

## 接续关系

本轮提交前发现 colour4 分支已前进到 `843d1e1c7f61e563b8913242b8756542af169a80`（#288）。该提交已处理原始 RGB 的提前执行、N=P 会话对照和 F7 入口。因此不覆盖它，也不提交此前准备的另一套重复 raw/neutral 实现。

本候选从上述新 HEAD 另起 `codex/d21-colour4-edge-recovery-20260919`，只增加9份边缘恢复、构建、测试、说明文件，继承 #288、#285 和 #281。旧 colour3/colour4 构建入口与所有原文件不变；Perf/lockperf 不变。新增入口输出 `beta0.5-dline21-colour4-edge1`。

这是运行代码候选，不是已安装或已编译的 addon；尚无完整 Windows/HLSL/GPU/游戏验证，也不称已解决衣物结构差距。

## 实现

`ColourEdgeRecovery=0` 默认保留 D21 双线性；设为1时，只有实际 scaled V2 RGB 合成并且存在本次槽位/serial的输入编码记录才启用 bit24。100%和旧倍率合成不改变采样。后置如确实使用 scaled V2 RGB 也按实际条件准入，不能从菜单路线名称猜测。

新恢复使用原有四个 bilinear tap，附加由完整原图 prepared proxy 和每个低分 proxy 之间差异决定的正权重：

`w = spatialWeight / (1 + 64 * distance^2)`

RGB距离先以二者最大绝对值归一化，防止HDR平方溢出。Proxy与Neural使用完全相同的权重与分母，不用神经模型的新输出作为引导；保持 signed 修改，不在采样阶段裁剪。原有限值、模型footprint、alpha、源色域、MaxLumaRatio、master/readiness 与资源/队列安全不变。最终神经结果仍通过已有多层 accessor 获取，不改NR数量、模型参数、输入曲线、层数或工作尺寸。

受保护RGB和#288的提前raw参考均接入；#288的中性probe仍独立存在并保持实际N/history资源不变。其N=P消费者能够使用同一边缘配对。F7/F8中的P/N则继续记录真实模型输入/输出，只换成实际有效的边缘采样权重，绝不把模拟N冒充实际模型输出；E是实际写回结果。可选细节决策平面沿用旧过滤诊断，不代表edge/raw消费者。NR→SR的E仍为游戏SR之前的图，不是最终O。

UI通过原有pending事务保存请求，显示已录制模式和未采用原因；异常旁路、光晕、闪烁须F8/BUG反馈。只有输出设置相等性改变，不进入NR历史签名。切换后仍应等待游戏SR历史稳定。

## 为什么是实验开关

该候选针对低分修改跨轮廓传播，不是增加锐化，也不是把Lanczos替换为默认。正权重并不保证最终画面无光晕：模型、源解释和原生SR仍可能是主因。颜色相近的跨材质边界可能无法区分，过强配对也可能压弱真实编辑、改变细线或引起时域变化。

没有新增纹理、描述符、root DWORD、NR/GPU pass，但ALU、分支、寄存器占用可能增加。GPU成本和游戏收益均未测。受控阶跃探针的改善不能换算成画质或FPS结果。

## 构建与交付

必须从本分支执行新增 `scripts/build-colour4-edge.ps1`，不是旧 `build-colour-lab.ps1` 或 `build-colour4.ps1`。使用现有固定upstream、LLVM-MinGW、ReShade、NGX/可选FaceRuntime参数，新建输出目录，不覆盖已测包：

```powershell
.\scripts\build-colour4-edge.ps1 -UpstreamRoot '<已有固定上游>' -OutputRoot '<新的colour4-edge1目录>'
```

入口保留#288原有源码选择、RGB数学、stage数学与源码门禁，再增加edge检查。生成时依次验证完整colour3导出、#288 colour4导出，最后应用edge并校验生成结果；所有tracked输入和祖先检查、临时发布、manifest哈希保持。随后调用既有完整Windows构建，不安装游戏。失败应修复，不允许把实际源码检查退回跳过。

## 最短实测

保持已测场景、单层、颜色优先、受保护RGB、原输入曲线、99%，零修改probe关闭；只切换“D21双线性 / 配对边缘匹配”。先看裙摆、头发和衣服轮廓光晕是否减少，并检查真实细节是否一起被压弱。之后100%重复一次，作为不改变采样的负对照。

若99%仍异常，使用继承的零修改probe，采集F7/F8后关掉。N=P时E仍改变，优先查配对/恢复/写回；N=P干净不能证明真实N、非零恢复和SR全链正确。正常采集的P/N/E可定位首次异常；不要为测试更换模型或同时改N2、结构强度、层数。

#274/#281相关画质问题保持开放。未合并任何主线、未发布Release、未宣称达到RenoDX水平。后续根据P/N/E证据推进输入/参数、恢复或SR配对；私有残差SR/RR、显存与人脸模块仍独立推进。
