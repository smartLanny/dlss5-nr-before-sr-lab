# 现用管理器 SR / FG 控制

产品仍是 `xiaofeng-dlss5-manager`，沿用当前游戏卡片和黑绿界面。
管理器版本为 `0.4.6-hotfix.3`；内置默认核心为 `0.4.6-hotfix.1 · Beta`。
0.3 是稳定基线，0.4 全系列仍为 Beta，常规分发不再包含 0.4.5。

## 玩家操作

- SR 可管理原生 NVIDIA 每应用档位、33–100% 自定义输入比例及 K/L/M 模型，
  也可管理已存在的 OptiScaler 输入比例配置。只改模型可保留原有档位。
- FG 可管理已安装的 RTX40 control v11 的跟随、固定、动态设置，以及
  RTX50 官方配置的关闭、固定和动态请求。2–6 是请求的总倍率，不能据此断言游戏支持该倍率。
- 保存仅记录当前 EXE 的启动请求；预览后确认应用会在游戏退出时写入并读回。
  管理器启动游戏前采用同一路径，失败会阻止本次启动并显示原因。
- 还原只恢复本工具接管的键，保留其他设置。出现未完成操作时先恢复，
  再安装、修复、OTA、切换组件或启动。

管理器不会用创建一个配置文件的方式冒充已安装帧生成后端，不会在此功能中
给没有 FG 的游戏注入新的帧生成实现。配置已读回和游戏实际采用分开显示。

## 实现和恢复

`launch-settings-service` 统一提供保存、预览、应用、启动前执行与恢复接口。
配置文件和安装器共享 `file-journal` 事务，驱动写入有持久化恢复记录，
按设置键执行比较后写入，避免恢复 SR 时覆盖其他 FG 设置。

原 SR 模型模块仅用于尚未接管的旧设置。新 SR 接管前核验原 EXE 和旧基线，
恢复并读回后才捕获新基线。还原新 SR 后仍保留接管标记，旧自动模型写入不会复活。
无法可靠确认旧记录归属或检测到外部修改时保留原数据并停止写入。

旧独立 Manager 仓库保持冻结；本实现选择性复用了其纯配置编译和 NVAPI
适配逻辑，没有复制旧测试 UI，也没有引入另一套独立的安装 Engine。

## 验证边界

源码回归、实际 Electron 控件操作、打包对应性以及独立合成 EXE 的 NVAPI
读写和恢复分别留存证据。合成 EXE 不执行，不修改玩家游戏配置。
这些检查不证明特定游戏的实际输入尺寸、帧生成倍率、性能或长期稳定性。
