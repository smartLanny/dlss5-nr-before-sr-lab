# 现用管理器 SR / FG 控制

产品仍是 `xiaofeng-dlss5-manager`，沿用当前游戏卡片和黑绿界面。
管理器版本为 `0.4.6-hotfix.5`；内置默认核心为 `0.4.6-hotfix.1 · Beta`。
0.3 是稳定基线，0.4 全系列仍为 Beta；0.2.0 显示不带 Beta，但保留原始文件身份。
常规分发不再包含 0.4.5 和原版 0.4.6，已有安装仍如实显示实际核心版本。
portable 外层与内部程序都要求管理员权限启动；Setup 保留按用户安装方式。

## 玩家操作

- SR 管理原生 NVIDIA 每应用档位、33–100% 自定义输入比例及 K/L/M 模型。
  比例始终显示，档位会更新近似比例（100/67/59/50/33%）；修改数字自动切换自定义。
  标准档位仍写入对应驱动档位，自定义才写入精确整数比例。
  页面初始比例是待保存的配置，不能当作已读到游戏当前设置。
  不再提供 OptiScaler 选择；旧请求和已应用记录保留，先撤销后才能设置原生 DLSS。
- FG 根据实际显卡选择路线：RTX 50 使用原生配置的关闭、固定和动态请求；
  RTX 40 提供“准备兼容组件”，通过检查后开放跟随、固定和动态设置。
  2–6 是请求的总倍率，不能据此断言游戏支持该倍率。
- RTX 40 组件准备检查所选 x64 EXE、DirectX 12、游戏已有的 Streamline FG、
  可用的早期 UAL 代理和 ReShade Add-on 运行环境。它安装已校验的兼容组件，
  不替换游戏的 NVIDIA 或 Streamline DLL；代理名被其他组件占用时保留原文件。
  DXGI 或混合 API 需先确认实际 API。NR 兼容桥接由 API 路线自动决定，
  与 RTX 40 FG 的兼容组件职责不同。
- 游戏图形 API 的自动项显示具体检测结果；手动选择绑定所选 EXE，重新扫描不覆盖。
  DX11 自动部署兼容桥接，DX12 无需此桥接；DX9/DX10/Vulkan/OpenGL 可保存选择，
  但当前不支持 NR 安装。改变已安装游戏的 API 会同步安全处理旧 carrier，保留共用 nrchain。
- “模型强度”绑定 Intensity（0–2）；“额外强度”绑定核心面板的 NR 效果倍率，
  同步 TransferStrength/PostTransferStrength（0–4）。默认均为 1；修改不改变 ColorStrength。
- 保存仅记录当前 EXE 的启动请求；预览后确认应用会在游戏退出时写入并读回。
  管理器启动游戏前采用同一路径，失败会阻止本次启动并显示原因。
- “使用原有设置”或“撤销本页设置”只恢复本工具接管的键，并取消本页覆盖，
  不等于关闭 SR/FG。“关闭帧生成（驱动）”才写入原生 FG 关闭设置；游戏菜单可能仍显示开启。
  当前没有可通用于所有游戏的设置读取接口，界面不会把驱动配置读回当作已知游戏内开关。
  出现未完成操作时先恢复，
  再安装、修复、OTA、切换组件或启动。

管理器不会用创建一个配置文件的方式冒充已安装帧生成后端，不会在此功能中
给没有 FG 的游戏注入新的帧生成实现。配置已读回和游戏实际采用分开显示。

## 实现和恢复

`launch-settings-service` 统一提供保存、预览、应用、启动前执行与恢复接口。
配置文件和安装器共享 `file-journal` 事务，驱动写入有持久化恢复记录，
按设置键执行比较后写入，避免恢复 SR 时覆盖其他 FG 设置。

`fg-components` 管理 RTX40MFG-Unlock v1.2 和 UAL v9.7.4 的校验、部署和还原。
每个 EXE 的恢复记录区分新增、修改和已有文件；还原先恢复 FG 设置，再处理
本工具管理的组件，保留共用 ReShade 和非本工具文件。存在无法确认的旧前端、
组件被外部修改或未完成事务时，不覆盖原文件。RTX 50 上如有本工具准备的旧
RTX 40 组件，可用“切换到原生路线”先清理，再使用原生 FG。

构建资源通过 `scripts/prepare-fg-components.ps1` 从固定上游版本准备，
`npm run verify:fg-components` 校验清单、哈希和许可证；资源缺失会阻止打包。

原 SR 模型模块仅用于尚未接管的旧设置。新 SR 接管前核验原 EXE 和旧基线，
恢复并读回后才捕获新基线。还原新 SR 后仍保留接管标记，旧自动模型写入不会复活。
无法可靠确认旧记录归属或检测到外部修改时保留原数据并停止写入。

旧独立 Manager 仓库保持冻结；本实现选择性复用了其纯配置编译和 NVAPI
适配逻辑，没有复制旧测试 UI，也没有引入另一套独立的安装 Engine。

## 验证边界

源码回归、实际 Electron 控件操作、打包对应性以及独立合成 EXE 的 NVAPI
读写和恢复分别留存证据。合成 EXE 不执行，不修改玩家游戏配置。
这些检查不证明特定游戏的实际输入尺寸、帧生成倍率、性能或长期稳定性。
