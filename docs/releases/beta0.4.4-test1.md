# beta0.4.4-test1 — D3D12 定向兼容测试版

这是从 `release/0.4@647ac292433bf00506eead16ccda1a30c2b3a153` 建立的独立分支测试版，不替换 `beta0.4.3r3` 稳定对照，不自动合并 main/release/next。**不含 DX11，不含 0.5 高强度算法，不提供新的 MFG 解锁或倍率控制。**

## 给玩家：只需更新、进游戏、看效果

1. 完全退出游戏；由维护者/机器人把旧版同类 addon 备份到游戏目录外，再放入一个语言版本的新 addon。保留 `nr_before_sr.ini`、ReShade、`nrchain_nvngx.dll` 以及原有显卡对应的 NR 运行库；不要中英文一起装，不混入第二个 NR 所有者。
2. 在面板确认 `beta0.4.4-test1`，进入之前有问题的游戏位置，按该游戏 Issue 的简短步骤试用。默认不要求改驱动、换 DLSS DLL、跑 benchmark、关闭系统安全功能或分析技术日志。
3. 回复“生效/不生效、还闪不闪、有没有崩溃”。能进游戏时按 F8 收核心包；只有画面异常且方便时补 F7。闪退/黑屏/持续异常就停止，恢复备份，不要求反复崩溃。

本测试版不是完整首次安装包。已有 30/40 系与 50 系的运行库配置各自保留。反馈文件仅本地生成，由玩家/维护者自行发送，不自动上传。

## 具体改动

### 1. 关闭 NR 时仍保持 NGX 透传嵌套边界

四个 Evaluate 入口的 master-off / other-owner / overflow 快速分支改用既有嵌套透传函数。旧分支直接调用原函数，公共 wrapper 转发到 core 时，内部句柄可能被误当作外层未知 Feature，导致永久的 observer fault。

此项不恢复真正未知的句柄、不猜 Feature ID、不清除既有不确定锁存、不规避 RR。旧源码在生产函数提取回归中产生明确的嵌套误判；修正后必须通过全部边界。

映射：#68 的启用/关闭与 late-core 路径是候选；若实际仍为真正漏 Create、未知 Evaluate 或外部热补丁创建失败，本项不能解决。#63 的 `MH_ERROR_UNSUPPORTED_FUNCTION` 不属于这个修复。

### 2. 漏登记修复请求不被其他载体取消

未登记列表出现后，repair-needed 保持到本进程结束，由原有已启用/已见载体的提交门禁限制开销。另一个已登记视图插队 Evaluate，不再把请求改回 false。只有真实 ReShade 提交回调提供 owner 映射；仍需成功 native Reset 和完整观察才能插入 NR。

映射：#65 多列表调度下漏登记恢复候选。若游戏的列表从未经过可观察的 ReShade 提交，则仍拒绝；不凭裸指针创建“安全”状态。

### 3. 有限视口/裁剪框的 known-null 自动恢复

在 R3 pristine-null 之外新增 `guarded-null-raster`：完整 hooks 发布后新的成功 Reset，已知空基线，无 unknown/opaque taint，且只记录 viewport/scissor 两类值数组。验证数组上限、视口有限范围/depth 区间、裁剪框非反向。资源相关动态图形状态、VB/SO、predication、render pass、protected session、work graph 等不进入该自动路径。

使用原有 ClearState + 精确根参数/heap/viewport/scissor 恢复。完整动态回放仍受默认关闭的实验开关控制，不能把该开关打开作为玩家测试前提。旧 pristine 路径保留。

映射：#53 后置状态及 #38/#50/#64 的相邻合同候选；不是已证明这些游戏只差 viewport/scissor。后置仍对原生 SR 返回后的状态重新取快照，不把 SR 前状态强行套到 SR 后。

### 4. UI 与反馈

- 显式“后置对照设置”会退出诊断原图模式；新增“显示 NR 效果”按钮，避免模型在运行但画面被用户遗留的诊断选项主动丢弃。
- 自定义前置工作分辨率用 50–100% 显示，并解释为 N/R 线性宽高比例；旧 WorkMode/CustomWorkScale 和已有偏好保留。后置完整输出参考不改变，不把这个 UI 改动冒充 #82 的低分后置实现。
- 后置在原生 SR 成功后、命令状态准入失败时明确记录停止阶段，区分 prepared-only 和已调用 Feature18。
- 源码 build_id、ReShade 名称、文件名、Windows 文本/数值版本与包内清单统一。

## 发布门禁与验证边界

发布工作流必须依赖同一个提交的完整 0.4 验证与跨平台反馈矩阵；失败不上传 Release。包含生产函数提取、旧源码红例、真实 native Reset/混合列表登记、WARP 正例和错误恢复负例、中英文完整编译与静态分析。还会执行已有 viewport 错误恢复的 GPU 负例，不能把任意崩溃当作负例通过。

这些属于 source-level / compile / CI / WARP；**真实游戏、NVIDIA 模型、FG 显示节奏与帧时间须由后续实测确认**。新增 Hook 观察与 sticky repair 查询可能有额外 CPU 开销；没有测量则不宣称提速。shader、NR 模型参数默认值、jitter/MV、曝光公式、RR 排除和原生队列/fence 回收均未主动改写。
