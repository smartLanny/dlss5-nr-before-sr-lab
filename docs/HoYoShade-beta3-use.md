# beta.3 米哈游兼容模式

本模式为每款游戏建立独立外置运行目录，并由管理器自己的加载助手等待已绑定的正式客户端。首次安装即可直接选择 HoYoShade，不需要先在游戏目录安装代理。普通游戏的默认部署规则仍是游戏目录，已有部署保留原选择。

## 配套与范围

配置参考固定于 [HoYoShade V3.0.0-Beta.9 源码](https://github.com/DuolaD/HoYoShade/tree/23761f935444a78388c028fbfda921965177c453)，使用官方完整 Add-on ReShade 6.8.0。本版使用管理器实现的配置与加载流程，不运行上游注入器或 `ini_builder`，不整包复制上游的滤镜、预设或个人配置。

当前正式流程针对 x64 DX11/DX12；原生输入与 Feeder 0.15.1 输入使用不同的完整配套，由预览确定。DX9 系统 D3D9On12 路线仅提供 local 入口。

| 游戏 | 当前可绑定正式渠道 | 实际 EXE |
| --- | --- | --- |
| 原神 | 国服、B站渠道服、国际服 | `YuanShen.exe` / `GenshinImpact.exe` |
| 崩坏3 | 国服、国际服 | `BH3.exe` |
| 崩坏：星穹铁道 | 国服、B站渠道服、国际服 | `StarRail.exe` |
| 绝区零 | 国服、B站渠道服、国际服 | `ZenlessZoneZero.exe` |

表格是客户端绑定范围，不是上述游戏全部通过真实 NR 验收的声明。游戏实测状态见 [beta.3 验收记录](beta3-acceptance.md)。

## 首次配置

1. 完全退出游戏，选择真实游戏 EXE。在游戏卡片核对实际 API，并进入“米哈游兼容”。
2. 选择 HoYoShade、对应正式渠道和启动器种类，绑定已经安装的官方 `launcher.exe`／`HYP.exe` 或 `Starward.exe`。例如 `C:/Program Files/miHoYo Launcher/launcher.exe`。游戏与启动器分别校验身份。
3. 预览完整变更，查看活动运行目录、Core／依赖及现有 Add-on 的保留或隔离安排，再应用。
4. 从管理器启动游戏。HoYoPlay 模式会先启动加载等待流程并打开启动器，助手就绪后在 HoYoPlay 点击该游戏的“启动”。Starward 模式核对其已注册 URL 协议后，通过绑定的协议启动。
5. 进入游戏后分别检查目标加载、Core 与 NR 完成状态，并在相同场景核对画面。已写入配置和助手就绪均不能单独代表 NR 工作。

Starward 尚未注册协议时，先在绑定的 Starward 中启用 URL 协议，再重新检查。游戏或启动器更新、移动后，重新核对并应用绑定；不要把另一个渠道或启动器目录冒充游戏 EXE。

正式客户端要求管理员权限时，管理器会为这一次加载请求 Windows UAC；界面保留原权限，只让绑定的后台助手和客户端使用同用户、同会话的管理员权限。助手就绪后打开官方启动器，等待用户点击开始，最长五分钟。拒绝 UAC、超时或加载失败会报告原因并回收本次等待助手，不结束游戏。取消等待和关闭管理器也不会结束游戏。

管理员后台持续核对本次进程、已加载组件与 NR 完成帧。观测超过十五秒未刷新、后台已结束或目标身份变化时，不沿用旧的成功状态。重复点击复用已有等待会话，不再启动第二个助手。

## 目录与已有模组

以管理器显示并核验的活动目录为准，不手填或猜测用户数据目录。该目录统一承载当前生效的 `ReShade.ini`、Add-on、NR 配置和相对着色器路径；管理器按当前布局更新自己拥有的项目。

预览按实际加载目录和组件身份检查重复 Core、旧桥接器及其他 Add-on。已确认冲突的组件隔离；未知组件按预览明确选择保留。个人滤镜、纹理、HDR 配套和预设按清单处理，不以整份上游配置覆盖现有内容。

此模式不会先在游戏目录建立普通图形代理，不会无条件清理游戏文件或结束游戏进程。加载受阻时，保留该次状态与日志，使用预览中的恢复流程。

## 更新与恢复

已受管理器接管的安装，继续使用管理器的完整预览、应用和恢复。切换输入路线或 Feeder 代际时，更新配套及其恢复记录，不能混放原生 Core、ExternalProvider Core、不同宿主或不同显卡族运行库。

单独提供的 26 路线游戏插件手动更新包不属于管理器的 OTA 导入格式。其中 HoYo 材料只适用于已明确掌握活动目录的手动维护场景；不能覆盖管理器接管的目录后再手改收据。所有 `.example` 文件仅作为个人配置的合并参考。

退出游戏后可选择“干净移除”或“恢复安装前”。若有未完成事务，先恢复该事务；以记录和摘要匹配的原件为准，不把未知备份文件直接当作原件。
