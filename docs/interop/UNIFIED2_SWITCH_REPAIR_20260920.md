# unified2：比例提交、创建峰值与颜色控制

本批继续 PR #300 / Issue #294，目标 `next/0.5`。不安装到游戏、不发布稳定版。
输入为 unified1 `cace3e64` 的完整组合历史；实际被报告崩溃的二进制来自 `5f8ebdee`。
本文的源码修正不等于游戏验收。最终构建和产物身份另记交付回执。

## 已确认的故障与边界

- 后置模型 100% 成功，随后 98% 创建返回 PlatformError/null；自动兼容回退令原 UI 改读兼容比例 100%。所选比例和实际路线共用编辑条件，造成回跳。
- 最后切换回后置、创建 2720×1528 的模型时，在 signed Feature18 Create 内发生写入空目标的异常。尚未进入这次 Evaluate；当时为单层。
- 同次 minidump 的有效 SystemMemoryInfo/ProcessVmCounters（不是 XML 中未填充的零值）显示：系统 commit 65.5743 GiB、limit 65.9008 GiB，余量约 334.3 MiB；进程 private commit 21.0730 GiB。物理可用量约 8.89 GiB。CPU 提交内存与显存是不同账目。
- 对匹配厂商二进制的有限故障指令核对，显示分配返回空后进入复制。结合上述余量，内存分配压力有具体证据；不能据此把全部占用归到 NR 或宣称显存耗尽。
- 旧模型被标记退休后，新模型先创建，旧模型才检查完成并释放，存在可避免的重叠。单独 NVIDIA 宿主的三尺寸创建序列验证这一成本：先释放约 1.6921 GiB 进程峰值，重叠约 3.1885 GiB。两个进程在充足余量下均成功，未复现游戏 AV。

原始转储、完整日志、个人标识、恢复路径只保存在私有证据中。
计数结构按 [Microsoft minidump 定义](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/um/minidumpapiset.h) 解析并校验版本、长度和重复字段。
`PrivateUsage` 是[进程提交内存](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters_ex)，不能称为显存节省。

## 修正范围

1. 工作比例编辑绑定所选起点，RR 和用户 Present＋FG 重定向仍使用后置比例。拖动锁定目标，松手一次提交；外部配置、后置 revision 或选择代次变化取消旧编辑并明确提示。实际执行尺寸另行显示。
2. 没有匹配实例、即将新建时，再收集一次刚退休的模型。已排队释放的实例先在锁外完成释放，本源帧保留原生输出与所选路线；下一正常源帧重试。释放从待销毁表移出到真正完成的间隙有占用计数，不能趁间隙抢先创建。仍未完成 GPU 工作的实例保持原来的独立寿命条件；不假定主层完成就是辅助完成。
3. 匹配的有效模型仍能复用；F6 关闭不因此强制卸载缓存。新逻辑不改变模型尺寸、层数、SR/FG 设置，不忙等 GPU，不把暂时释放状态降级成新 Present 模型。
4. Create 边界记录系统 commit/limit、当前进程 private commit 和读取有效性；Evaluate 没有新增每帧内存采样。这不是整个 NGX 的分配跟踪或自动显存预算器。
5. 每层结构、色调、原生皮肤和 UI 选项直接展开。新配置/本层重置的原生 mask=true、skin=0.4、UI=true；显式旧 INI 值保留。独立脸区模型仍为默认关闭的实验功能。
6. 颜色优先与保守模式下，旧 HDR 许可控件显示实际策略且不可重复编辑，旧值保留给 Legacy。日志区分准备阶段许可与最终 ColorDiag 系数，不再把中途判断当作最终颜色采用量。

## 颜色仍需继续定位

实际配置是颜色优先、旧 D21 合成和旧输入。前置 100% 和 99% 都是 EncodeV2/CombineV2，分别在原生输入网格及稍小网格运行；没有变成后置。
后置本来有不同输入与合成路径，外观接近不能证明路线被切换。

使用实际曝光 1.6、归一化 0.625、LightingLock 0.2、EdgeGuard 0.25 的生产着色器非零矩阵在 NVIDIA 上通过 360 项；错误源区域负控正确失败。固定平坦 HDR 相对修改的各尺寸输出没有新增差异。N 是人为指定的修改，未包含真实模型响应，不能据此关闭 99%/100% 色差问题。

## 下一性能节点

本批验收切换瞬时重叠及恢复；RR＋NR＋FG 稳态等待/提交锁继续单独取证。相同参数、相同工作量、相同 NR 采用率的源帧时间才可比较。独立 SR、跨 RR 与 AMDOF 仍按统一交接顺序推进，不借本批创建修正宣称已经实现。
