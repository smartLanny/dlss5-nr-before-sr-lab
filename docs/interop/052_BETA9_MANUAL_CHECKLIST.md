# Beta 9 维护者实机验收

先核对部署回执中的版本与 Core 哈希，保留原 INI 和运行库。代理只准备包，不启动游戏。此前 Beta 8 的 SR/RR 录制已找到，无需补录旧包。

1. **开启 RR 与界面。** 异环中手动开启原生 RR，确认无创建闪退、NR 确实生效；检查 Esc 菜单往返、切镜、人物和局部处理关闭时有无 NR 消失或闪烁。若触发内存保护且一直旁路，保存 F8；不要把旁路变快当作优化。
2. **层数和驻留。** 在同场景由原有多层降至一层，等待在途工作完成；记录显存变化、恢复时间和画面。再检查同配置 F6 与处理位置切换。不刻意耗尽内存；未恢复时保留 F8 和完整日志。
3. **九组对照。** 原生 SR、原生 RR 各点击一次九组按钮，游戏模式由你手动切换。每组仍为 180 个有效源帧预热（最多20秒）、600个有效样本（最多60秒）、三张截图；不足有理由并继续。结束/取消必须恢复原设置。检查报告实际路线标签，原生无 NR 组计时为不适用。
4. **兼容路径。** “自动兼容”请求不等于已采用；F8记录当前拒绝原因即可。“RR 缺投影时尝试后置 NR”仅在正常投影缺失时尝试；不需要为触发它破坏游戏设置。
5. **质量与成本。** 普通均衡为起点，同档比较已有恢复/私有 SR 选项。另录静止、平移、物体运动、显露、切镜、反射和 HUD，检查暗部、发丝、文字、细线、颗粒和拖尾。三组时域未采用时不能判断其降噪有效。完整游戏帧成本需同 NR 工作量单独测量，报告局部计时不能代替。

保存完整反馈目录和 F8；保留 Present、地图省电、多层暗部验收。先异环，2077最后。失败不通过延长超时、强行采用历史或重置设置掩盖。回退使用部署回执保留的精确旧 Core。
