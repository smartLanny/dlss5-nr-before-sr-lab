# Corefix.5：共享活动窗口、描述符保持与当前原生格式请求

接续 `50660bfe529e789d0edfde119782b873df387271`。Corefix.4 的死亡搁浅最终画面无可见 NR、近期状态跳动，以及绝区零 Feature 重建后的格式未知仍是有效实机失败。本候选修复已复现的共享机制缺口，最终游戏效果另行验收，不按游戏名分支。[复测事实](COREFIX4_RETEST_20260910.md)。

## 改变的行为

近期状态使用进程累计计数，活动窗口也改为进程共享；短锁只保护取时钟、取计数和窗口更新，绘制与 F8 在锁外。旧线程自身 2156 ms 未读取、其他线程仅隔 63 ms 已读取的情况，不再错误清空窗口。真正全局停止读取超过 2000 ms、配置变化、计数回退与逆时钟仍使样本失效，旧配置调用不能擦除新窗口。CPU 回归包括 4000 次真实并发发布和原策略负对照。

活 heap/resource 使用完整键保存，真实退休才删除；CPU 与 GPU 槽池分开，成功复制和明确使用更新各自 LRU，只有满池时淘汰已完成槽。实际重复活地址、范围重叠及活对象容量缺口继续拒绝；不会用较新的记录猜测此前未知写入。活动原生调用中可通过真实 SetDescriptorHeaps 对象补登记 addon 初始化前的 heap，无法凭此重建旧 CPU 视图。默认固定内存约 13.81 MiB，编译期上限 16 MiB；CPU 构造吞吐不代表游戏性能。[容量与失效合同](DESCRIPTOR_REGISTRY_CAPACITY_20260910.md)。

原同步 CreateView、typed 资源和既有唯一格式准入保持。对于当前 Feature 的 typeless Output，原生成功调用中的 Clear 可以留下独立 CPU 格式请求：必须确认为同一 Output、设备、列表及完整二维视图，Clear 前后 CPU/GPU 描述符键、修订和内容一致；未知、冲突、溢出或失败均拒绝。请求只为下一次准备提供候选，写入任何后置 GPU 命令前还必须取得**本次**原生调用返回的相同请求，并重新检查当前对象、配置和同步证据。另一调用、旧代请求、缺少本次 Clear、格式冲突或失败都不能借用候选通过。CPU 描述符在 Clear 返回后的合法复用不追溯抹掉已完成的 CPU 请求；GPU 描述符使用证据保持独立。局部 Clear 矩形不证明全图覆盖，但不会改变该视图的类型。

UNORM 8/10 位诊断改为同一批稀疏坐标逐点比较允许的存储区间，覆盖转换边界处两个均合法的相邻编码。仅当计划、实际采样、期望写入与比较数量一致，协议、范围、有限值和覆盖均完整时，才给出已知匹配或失配；缺样、重复、旧槽、容量或格式问题保持 unknown。原合成公式、Output 状态声明、采样频率和暂停/仅状态切换语义保持。新增同步仅针对私有统计 UAV；不从 CPU 录制顺序推断游戏 GPU 覆盖。FP16/R11 原路径保持。

F8 将格式准备候选与 `format.output.freshGate` 分开；后者记录真实核验是否执行、结果、scope 及准备/本次/请求调用号，不反向参与渲染判定。`currentScope` 仅表示匹配最新已观察的原生调用/config，不是独立的对象存活或 GPU 证明。后置窗口只关联自己的恢复尝试和精确 native-use 调用，环槽过期返回空，不借用全局最新记录。元数据容量为 192 KiB，单 TXT 为 384 KiB；严格字段白名单保留长数字，原始日志仍脱敏。完整落盘测试覆盖七种时钟情况、六路摘要及故意删尾、减容量、抹数字等反向对照。
