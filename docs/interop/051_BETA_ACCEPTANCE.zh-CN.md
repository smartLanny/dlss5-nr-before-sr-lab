# 0.5.1 Beta 短验收指南

目标是确认新功能实际运行，并检查回归；“已勾选”与“F8 成功导出”都不等于画质通过。
已完成的旧版采样继续保留。本批先测下面约10分钟的异环增量，不重跑无效组合或模型 A/B。

## 安装前

退出游戏，备份旧 Core/nrchain 到游戏搜索目录外；保留 INI、模型、ReShade。
只使用一个语言 Core。D3D12 不需要复制 DX11 carrier；不要同时加载其他 NR 处理插件。
确认菜单显示 **0.5.1 Beta**，F8 内部版本为 `beta0.5-dline21-unified10`。
有保存旧颜色规则时会提示；调整 AI 色彩范围才采用新许可，不会在启动时静默改写旧值。

## 异环：本次必须补的少量测试

1. **颜色（约1分钟）**：同位置、NR开启，分别调0/0.5/1，松手后生效；检查颜色变化与保存。
   0仍保留明暗/细节，不要求等于F6关闭。别同时改光影、层数或实验恢复器。
2. **HDR 防闪（约5分钟）**：保持现有前置、模型、比例和层数，先防闪关闭，再选
   AMDOF＋整链。每次等待约3秒，再静止看草木/暗部、缓慢转镜、遮挡显露、明暗切换。
   每段留约20秒，最后F8。检查高光、亮度是否异常、NR效果是否仍在、拖尾是否加重。
   修前的前置 Native 和单层 Later 两组本来不适用，本次不要再跑。
3. **连续切换（约1分钟）**：AMDOF关→开→关，工作比例100→99→80→100，停留到状态实际采用。
   参数不能回跳、闪退或永久等待；不要把配置正在切换的瞬间当作稳定帧率。
4. **省电（约2分钟）**：开启要测试的省电模式，进入游戏暂停/地图/背包，停留数秒并F8；
   再返回游戏F8。记录是哪种菜单，是否开游戏FG。ReShade面板本身不是暂停证据。

F8 的 `temporal.submitted` 应在 AMDOF 开启后增长；`lastPreparedDomain=2` 表示最近准备
使用线性HDR历史，仍要看提交计数。预热/不支持段的零计数不是性能提升。
省电看实际“已暂停”和 `energyGate` 实收信号；总GPU功耗不是NR单项耗时。
异常只补对应场景的同次F8与Core日志，不重录整套。

## 其他游戏：按已有验收进度补缺项

- **燕云**：相同模型/层数/比例比较防闪关与AMDOF，包含明暗切换。区分NR接入中断与
  连续NR输出抖动；#246需要版本匹配的修后F8，不能只报“勾了防闪”。
- **鸣潮**：用户在游戏设置中开RR，确认实际RR→NR或明确后置候选，F8查看深度适配与NR成功。
  失败时原生RR应继续；#254必须有开RR后的修后F8，WARP不能替代。
- **2077**：手动确认RR/FG/HDR设置，测试本包实际支持的AMDOF路线、HUD、高光、转镜及切镜。
  原生MV的HDR/RR路线尚未接入，不把这些组列为失败修复验收。

## 性能与显存

做对照时固定模型、实际工作尺寸、层数、NR采用率、相机和游戏FG设置。
深度采集与性能采样分开；首次加载/切换卡顿与稳态分开。使用逐帧数据判断P95/P99，
反馈页回调间隔不是FG显示FPS。显存看同进程使用量/预算及切换后回落，不能只看自有纹理账。
FP16无快照为开发实验且默认关闭，不要求普通用户设置进程环境变量来验收默认包。

## 提交结果

只需：游戏/显卡/设置、内部版本、同次F8和Core日志；视觉问题补短片或同场景截图。
持续旁路、无效果、拖影明显加重、闪烁或崩溃时先回退。保留问题文件，之后只补异常场景。
