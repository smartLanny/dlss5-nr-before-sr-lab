# 有界描述符注册表的完整键与容量隔离

接续 `50660bfe529e789d0edfde119782b873df387271`。旧注册表只用取余后的单个位置保存活 heap、resource 与槽位；两个不同完整键会在仍有空闲位置时相互覆盖。CPU 源与 GPU 复制目标还共享同一槽池。这能造成明确视图证据消失，不能单独证明游戏最终画面失败原因。

现在 heap/resource 使用固定容量完整键索引，并且只在真实退休时删除。默认上限分别为 4096 和 32768。CPU 非可见槽池为 32768，GPU 可见槽池为 65536，使用独立索引、空闲链及已完成写入的 LRU。只有实际满池才会淘汰本域已完成槽，pending 槽不可回收；旧修订失效，GPU 复制周转不再淘汰 CPU 源。句柄定位使用固定有序区间索引，重叠仍视为未知。

heap/resource 满池拒绝新对象时，无法证明被遗漏的活对象不会与已登记地址/区间冲突，故该域进入持续 coverageLost；保留 active 和 drop 数，不将其伪装为退休或恢复。被遗漏对象的退休、设备退休及后续空位不会擅自清除此未知状态。实际重叠 heap 的出现也撤销旧槽修订，防止重叠期间未知写入在另一 heap 退休后复活旧证据。槽池容量耗尽的 drop 则只丢失该次目标写入，不升级为活对象域覆盖丢失。

原生 SetDescriptorHeaps 在活动观察范围内提供真实 heap 对象时，可补记 addon 初始化前创建的 heap 元数据。登记在 COM 调用之外的值锁中完成；COM 调用本身位于所有值锁和命令状态锁之外。没有活动观察时立即返回。此补记不重建旧描述符，不解析 GPU 内存，也不从 opaque CPU 句柄推测对象。

F8 分别报告四域 active/capacity/drop/eviction/coverageLost，最近 Clear 的 CPU/GPU 缺失原因和 heap/slot 也分开记录。`SnapshotNrDescriptorUse(call)` 只返回精确 call 的条目，环形槽已被复用时返回空；不带参数仍查询最新调用。原有格式准入与 NativeUse Finish/Execute 判定保持。

独立 CPU 验证通过 592 项，涵盖原直映表的 heap 10/266、resource 3448/5496、slot 0/8192 反例，以及真实满池、别名缺口、跨域 churn、并发重叠、退休/复用和精确 call 回绕。默认注册表实际 `sizeof` 为 13,467,920 字节（约 12.84 MiB），以编译期断言守住 16 MiB 上限，不分配增长容器。此组件结果未运行 GPU，不包含 NVIDIA、游戏画面、性能或整包验收结论。
