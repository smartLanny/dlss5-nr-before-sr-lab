# 有界描述符注册表的完整键与容量隔离

接续 `50660bfe529e789d0edfde119782b873df387271`。旧注册表只用取余后的单个位置保存活 heap、resource 与槽位；两个不同完整键会在仍有空闲位置时相互覆盖。CPU 源与 GPU 复制目标还共享同一槽池。这能造成明确视图证据消失，不能单独证明游戏最终画面失败原因。

现在 heap/resource 使用固定容量完整键索引，并且只在真实退休时删除。默认活对象上限分别为 4096 和 32768，索引预留一半桶为空，删除时修复探测簇，不累积墓碑。CPU 非可见槽池为 32768，GPU 可见槽池为 65536，使用独立索引、空闲链及已完成槽的 LRU。成功复制会刷新 CPU 源的使用顺序，成功明确 UAV 配对刷新两侧，单纯库存与修订诊断查询不刷新。只有实际满池才会淘汰本域已完成槽，pending 槽不可回收；旧修订失效，GPU 复制周转不再淘汰 CPU 源。句柄定位使用固定有序区间索引，重叠仍视为未知。

heap/resource 满池拒绝新对象时，无法证明被遗漏的活对象不会与已登记地址/区间冲突，故该域进入持续 coverageLost；保留 active 和 drop 数，不将其伪装为退休或恢复。同对象地址出现不同活 token 也单独计 ambiguity 并进入持续未知，地址检查只发生在冷登记，热复制不扫描资源表。被遗漏或冲突对象的退休、设备退休及后续空位不会擅自清除此未知状态。实际重叠 heap 的出现也撤销旧槽修订，防止重叠期间未知写入在另一 heap 退休后复活旧证据。槽池容量耗尽的 drop 则只丢失该次目标写入，不升级为活对象域覆盖丢失。

原生 SetDescriptorHeaps 在活动观察范围内提供真实 heap 对象时，可补记 addon 初始化前创建的 heap 元数据。登记在 COM 调用之外的值锁中完成；COM 调用本身位于所有值锁和命令状态锁之外。没有活动观察时立即返回。此补记不重建旧描述符，不解析 GPU 内存，也不从 opaque CPU 句柄推测对象。

F8 分别报告四域 active/capacity/drop/eviction/ambiguity/coverageLost，最近 Clear 的 CPU/GPU 缺失原因和 heap/slot 也分开记录。`SnapshotNrDescriptorUse(call)` 只返回精确 call 的条目，环形槽已被复用时返回空；不带参数仍查询最新调用。原有格式准入与 NativeUse Finish/Execute 判定保持。

独立 CPU 验证通过 1688 项，涵盖原直映表的 heap 10/266、resource 3448/5496、slot 0/8192 反例，以及真实满池、别名缺口、跨域 churn、冷热源淘汰、512 轮高占用删除插入、并发重叠、退休/复用和精确 call 回绕。默认注册表实际 `sizeof` 为 14,483,760 字节（约 13.81 MiB），以编译期断言守住 16 MiB 上限，不分配增长容器。

独立有界吞吐观测使用一个持久 CPU 源和八个 GPU heap 的 131072 个目标槽，先复制 500000 个元素，再继续复制 1000000 个元素。最终组件源的本地 CPU 构造运行分别用时 71.170 / 132.956 ms；CPU 源始终可读且没有 CPU 淘汰，GPU 池各发生 434464 / 1000000 次真实满池淘汰，drop 和 unknownWrite 均为 0。时间只覆盖值注册表 BeginCopy/Finish，不含 D3D API、COM、GPU、多个游戏线程竞争或实际游戏负载；没有硬性能阈值，不据此宣称游戏性能通过。

初版 `b8e9d425` 的同地址资源和最近写入排序缺口均以原提交生产头文件 CPU 反例重现，后续修正已纳入上述回归。此组件结果未运行 GPU，不包含 NVIDIA、游戏画面或整包验收结论。
