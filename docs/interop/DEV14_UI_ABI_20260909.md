# dev14 菜单返回ABI修正

## 真实复现

固定ReShade6.8.0.2155与实际dev11 Core构成独立WARP宿主，未加载NR模型，
没有Feature18或RR调用。SDK sentinel显式开闭菜单并选择真正Core页签。
无Core对照完成40次Present、6次菜单开闭事件及17次overlay绘制；
dev11 Core两次在选择Core页后访问冲突。初次仅打开ReShade主页的运行不算Core页通过。

异常发生于ReShade的GetContentRegionAvail返回：主机通过RCX隐藏输出指针写ImVec2，
MinGW Core却按RAX接收八字节值，未提供输出缓冲。故障现场指针为0x8。
对应新增风格三块布局的可用宽度读取。该场景独立证明UI接口故障，不需要NR/RR。
原游戏hang转储没有同一异常上下文，因此仍须修正后的游戏确认，不把受控复現等同
全部游戏根因已经证明。

## 修正边界

- src/nr_imgui_abi.h为x64 MinGW到MSVC ImGui函数表提供显式输出缓冲的通用ImVec2
  返回适配；本地调用者仍使用本地ABI。其他编译器保留原签名调用。
- 实际SettingsContentWidth使用该边界调用GetContentRegionAvail，保留窗口滚动、
  内容区和列宽语义，不用近似窗口宽度替代。
- 源码仅有这一处受影响getter。检查从固定SDK枚举14个同类函数，阻止新的直接调用。
  未改变第三方SDK结构布局、全局编译器、ImVec2输入引用或标量/引用返回。
- 自有测试DLL由Windows MSVC ABI目标编译，客户端用MinGW调用实际生产helper；
  空参和int/double/pointer/float混参正确。旧原签名在独立子进程实际访问冲突；
  负控不接受加载失败冒充ABI错误。

保留dev13的恢复NR100%、模型1.2、“额外增强”和默认开启的开发者色彩保护。
保留dev14隔离RR设备身份/拒绝原因修正。没有执行此前猜测的原生登记回退；
后续证据已经证明dev11也有上述独立UI故障。
