# Beta 8 维护者实机验收

先确认部署回执中的候选版本与 Core 哈希。不要重置 INI 或换运行库。代理不启动游戏。

1. 维护者先在异环手动选择原生 SR 或原生 RR，并记录模式、分辨率、NR 层数和工作量。在稳定可重复的场景点击实验页九组按钮一次；等待结束即可，取消也应恢复原设置。
2. 每组依次进行最多 20 秒的 180 有效源帧预热、最多 60 秒的 600 有效样本计时和三张截图。原生无 NR 计时为不适用；其余组不足或拒绝需有具体原因。截图完成不代表 GPU 计时有效；计时 complete 也不代表采样期历史采用已验证。采用字段会区分全组观察、采样期未知与截图窗口新采用。
3. 保存整份反馈目录，至少包含摘要、GPU CSV、诊断及截图清单。重点核查普通 NR 与私有 SR 是否有有效样本，AMDOF 是否实际采用；后置 RR 原生 MV 的明确拒绝属于当前合同。
4. 原生 SR 和原生 RR 分别建立报告，游戏模式由维护者切换。连续帧另录静止、镜头平移、物体运动、显露、切镜、反射和 HUD，观察暗部、发丝、文字、细线与拖尾；静态截图不能证明去拖影。
5. 保留 Esc/切镜、Present、地图省电和多层暗部检查。整游戏帧成本需在相同 NR 工作量下另测，不能用本地报告的部分 GPU 区间替代。2077 留到异环之后。

结束或取消后确认原插件设置恢复。若仍为零样本，保留原始诊断即可；不要通过延长超时、强行采用历史或反复重置设置把失败变成通过。

实验选项可保留多个已有、评估尚可的独立方案，供维护者同档比较；建议从普通均衡恢复开始，不覆盖已有保存设置。关闭的实验不创建其 GPU 资源或提交其处理，私有 SR 与外部时域继续互斥，后置 RR 原生 MV 继续拒绝。本轮细线修改保留未过门的新四点方案不加入产品。
