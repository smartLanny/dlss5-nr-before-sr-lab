# D7：可选位置的人脸自动对照

维护者指出人物无法移到画面中央，并要求独立诊断项自动切换参数和采图。
D7接续D6，采用九组有标签的对照：当前参数、模型基准、基准Tone2、基准
Structure2各一对FaceOff/FaceOn0，最后重复当前FaceOn0。每组一帧512区域内部
五平面及完整显示截图，沿用同帧身份、真实fence回读、配置冻结和自动恢复。
图像组按时间顺序，不是静止的同一帧；重复组用于估计漂移。

## 实现边界

- 新FaceDiagnostic枚举独立于旧Current和七组分享，F7默认保持。
- 参数表只调整七项模型字段；所有路线、光影、工作比例和颜色字段保持。
  使用完整原配置恢复，不用仅七字段且依赖代次的UI撤销快照。
- 九组的controller与GPU组索引上界同时扩展，GPU/CPU预算及描述符、Shader常量
  不扩展；每帧仍只执行一次NR。新增UI几何记录只含CPU元信息。
- 当前游戏Output的有效子矩形须覆盖整幅资源，并与ReShade截图尺寸一致；
  近期同代次/实例的Combine源比例和原点通过检查后，才显示可移动选区。
  点击开始时保存选框使用的源尺寸；首帧若因动态分辨率变化而不匹配，即停止
  并恢复，不能把变化后的采集范围重新当成用户确认的选框。
  不把纵横比相同单独当成完整映射证明。
- 取景框用规范化中心定位，边缘按实际源范围钳制。主面板在框选时暂时关闭；
  只在选区期间注册额外overlay绘制，确认、取消、销毁后移除。
- 每组需3秒、64次成功NR评估、实际七项模型参数匹配以及有效GPU回读；完成后
  才请求全屏图。跨组允许模型实例随参数重建，但路线、feature、几何和颜色
  合同不能混用；曝光值保留实际记录，不用相等假设代替场景稳定性。
- 九组原始区域约180MiB，截图及元信息也受512MiB限制。必需组文件优先注册，
  重复模块清单引用已配对核心报告；任何输入注册拒绝不得显示Complete。
- 取消、超时、运行时销毁和打包失败均保留明确状态；设置恢复与证据完整性分开
  记录，不把成功恢复等同成功采集。

## 预期辨识力

FaceOff/On0差异分别在当前、基准、高Tone和高Structure下比较，判断人脸控制
是否随这些条件变化。当前到基准涉及多项参数，不能仅凭这一对断言具体是
风格、强度或界面保护导致。模型输入/输出与合成平面用于区分模型变化和后续
放大；它们仍不是模型内部人脸遮罩。本版不宣称人脸或反射算法修复。
