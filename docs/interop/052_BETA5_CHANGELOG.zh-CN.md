# 0.5.2 Beta 5：相对 0.5 D21 的更新

这是供测试的候选更新说明。**最终包身份与软件验证范围见随包清单和回执。** 它汇总从 0.5 D21 初版以来的变化，不把旧 Beta 4 的测试结果算作 Beta 5 已重跑，也不宣称游戏问题已解决。

## 升级后能用什么

- **更清楚的菜单。** 画面、光影、实验、开发者和反馈分组显示实际版本与运行状态；AI 色彩范围合为一个滑条，新配置默认 0.5。模型输入、空间恢复和光影选项更容易对照；F6/F7/F8 可改键，失效路线会给出原因。
- **一至五层 NR。** 每层可分别调整模型参数，全链只应用一次工作比例；后置及符合条件的 RR/兼容路线支持低至 25% 的工作比例。部分关闭态 CPU、缓存、切换和资源退休问题已改进，但不能由此推断游戏 FPS 必然提高。
- **可选的时域防闪与私有 SR。** 已证明来源和相位时，可选原生运动向量或 AMD 光流作为时域运动来源，并在普通累积与低频重建之间切换。成功原生 SR/RR 后，还可对最终 NR 修改量只做一次私有残差 SR。两类功能默认关闭，不能同时叠加；光流本身不等于去噪，私有 SR 不支持 Present、FG 或多 GPU。
- **集中验收与一键截图。** 既有集中验收会临时切换插件设置，结束或取消后恢复。Beta 5 的实验页可在固定相机下依次截图九组：原生路线 NR 关闭、后置 NR 100% 空间恢复、50% 空间/私有恢复、25% 空间/私有恢复，以及 50% 原生 MV、AMD 普通、AMD 低频。每组默认三张，至少等待三秒并完成预热，核对相应功能实际采用。结束后恢复原插件设置，用户可**点击按钮**打开双选对比页；不会自动打开浏览器。截图来自不同显示时刻，**不是同一帧严格配对像素**。游戏 SR/RR/HDR/FG 均不自动切换。

## 升级与兼容要点

**保留现有 INI，不要求重置旧 jitter 或其他保存选择。** 但旧 D21 配置首次迁移到统一多层格式时，会保留层数和模型参数意图，旧 `NRSecondScaleNumerator/Denominator` 辅助层比例只归档、不再应用；辅助层改用主层工作网格，**实际工作量可能改变或增加**。比较升级前后性能时，请先核对实际层数、尺寸和工作比例。

Core-only OTA 只更新 **Core 与 nrchain**，不安装 NR 模型运行库、独立人脸资源，也不改原生 SR/RR 库或 Manager 默认组件。20/30 与 40/50 系 NR 运行库有各自独立包；选择须按对应硬件与清单核对，不能把 Core 更新视作运行库升级。新功能对新安装默认关闭，已有保存值不被新默认覆盖。

[Beta 4 软件与受控 GPU 回归](https://github.com/smartLanny/dlss5-nr-before-sr-lab/blob/fc436fd7ad3ab28b97ad4da889cea42b363f8319/docs/interop/052_BETA4_UNIFIED_ACCEPTANCE.md)已有双语构建、私有 SR 和 Present 真实 NGX 人工输入证据；这些属于 **Beta 4**，不能充当 Beta 5 回执。Beta 5 九组截图、配置恢复及打包的软件验证范围以**随包清单和回执**为准。游戏截图的画质判断、Esc/地图省电、2077 兼容以及新增成本占整游戏帧 **≤3%** 均待用户验收；4K 受控时域成本呈多峰，不宣传稳定低开销。
