# 共用机制：一次性命令列表的队列准入

修复边界是命令列表提交历史与资源退休合同，不是游戏名称。死亡搁浅1提供了
这次复现入口；实现没有检查其EXE、游戏名或引擎白名单。任何满足相同状态、
完成信号与所有权条件的D3D12调用都能使用此路径，所有回归测试也按机制组织。
当前已交给维护者测试的`ds1.1`文件标识保留，后续集成按共用机制命名。

维护者的新dev15报告证明安装的是修复候选：首轮录制状态已准入，
`firstRecordingObserved=1`、`baseline=Create-first-recording`、`captured=1`。
相同config/epoch窗口仍为`queue-affinity-unverified`，队列未知旁路2757→2866，
NR与合成均0。先前的状态修正有效，但没有解决整条游戏路径。

当前队列策略要求同一命令列表在同一队列有两次稳定提交历史。死亡搁浅持续创建
只用一次的列表，因此这些列表永远无法得到该历史；不能通过猜测“只有一条队列”
或虚构提交次数来绕过保护。

## 独立修正

`0.4.7beta-ds1.1`在全部前置状态检查之外，增加另一种队列准入证明：
前一轮NR上下文及本次使用的资源已经由精确完成信号证明结束。
此时不依赖尚未知晓的未来队列，首次使用记录不可变的`CompletedDependencies`。
实际Execute前再次检查上下文独占录制标记、完成信号和资源状态，再从真实提交队列
建立新的完成信号。未完成的未知队列帧仍保持原生画面；不加CPU等待或私有跨队列Wait。

已有稳定队列的重叠路径保持。缺少历史与读取失败/损坏标记明确区分；迁移标记
不能重新学习，实际队列检查、重复提交、未提交即丢弃、资源所有权和隔离规则保留。
F8增加`queue.retiredAdmitted`，用于与NR成功及实际合成计数一起核对，
该计数本身不等于NR执行或显示成功。
