## 主人最新实测（口述，不冒充本轮 GPU 验证）

- 旧 D21 合成在 99% 边缘相对干净，但 99/100% 本身存在明显色差。
- RGB protected/raw 在 99% 新增头发/裙摆/衣物亮边，未明显增加真实结构。
- 旧 EdgeGuard 调高反而亮边加重；配对 edge1 只有部分改善。
- N=P 时接近 F6 关闭；NR 仍执行。这仅支持零修改消费者无明显异常，
  不验证真实 N、非零恢复、每个像素、SR 后输出或目标格式量化。
- proxy-first 未改善该场景；不再把输入顺序当主因。
- N2 让头发阴影与脸部颜色过渡更一致，主人觉得更像 RenoDX。
  不能据此判定阴影更准确；也没有证据证明 N2+旧合成已保留该收益。

## 本轮实际代码

`nr_quality_recipe.h` 从现有六个选择器推导方案，不增加一套持久化状态：
- 颜色基准：颜色优先 + 旧合成 + 旧输入，退出 proxy-first/edge/probe。
- N2阴影对照：只把上述输入曲线改成N2；历史按既有规则重建。
- 其他组合显示“自定义”，不在载入或绘制 UI 时改写。

`nr_quality_ui.inl` 将这些方案、请求/已录制状态、回退原因、捕获入口放在
常用区域；研究开关和进阶光影分别折叠。只改变这个画质/光影组，不声称
已经重新设计整个 Overlay 或 Manager。现有模型、AI色彩强度、原始光照
等其他位置的控件不被覆盖。

`nr_colour_restore_policy.h` 仅将缺省恢复从1改为0。保存的0/1/2继续生效；
旧 RGB 用户看到警告并可主动选基准。所有shader数学、模型调用、资源、
同步、分辨率、历史合同不变；这里是停止新配置默认进入回归路线，不是
修复 RGB 算法本身。

修复累计生成器实际调用错误：`test_colour_stage.py` 的 CLI 强制 --repo
和 --generated 互斥，旧 edge 入口同时传两者会在 argparse 阶段失败。
改成各中间导出仅传允许的 --generated；raw门禁仍在builder独立运行。
没有跳过、降级或删除任何已有检查。

## 下一“大节点”：一次输入/输出一致性收口，不再逐旋钮发包

同一固定DLL与场景，由Windows执行Agent在本机完成下面整个批次：

1. 实际二进制/embedded shader与生成manifest核对；保存Create前和Evaluate
   的有效参数摘要、源格式、线性/编码域、参考白/曝光、有效subrect、真实
   Model尺寸、MV/depth/jitter/Reset。不把菜单值当真实模型值，不随意猜测
   SDK参数槽或写GlobalTone等未验证键。
2. 旧D21合成100/99以及当前RGB两条非零路径，用同帧S/P/N/E对照，检查
   首次出现差异的阶段和非零编辑幅度。N=P已有一次正向观察，不重复让
   主人手工测整张矩阵；加入受控正/负编辑、灰阶、彩色阶跃、alpha、FP16
   存储/写回及相位/subrect负控。失败定位后在同批次修正再回归。
3. 用N2与旧输入比较真实P/N，区分“阴影过渡改善”和“把真实阴影抹平”；
   用100%单层作结构参考，同时保留相同成本的低分路径。没有P/N证据前
   不新增锐化/补光/更多NR层去掩盖结构不足。
4. 已有F7/F8的E在前置是SR输入；检查原生SR后的O时用明确同帧标识和
   独立历史，不能拿跨帧截图或复用一套SR history谎报同帧A/B。先复用
   现有捕获，只有缺失才补这个接缝，不重复开发五种截图框架。
5. 交付一个带固定源码/二进制hash、旧输入基准与候选的包；提供静态和
   动态结果、代价及已知缺口。不要只交“新增实验按钮已编译”的节点。
