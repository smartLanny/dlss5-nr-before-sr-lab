# 共用机制：按近期提交显示 NR 活动

## 复现与边界

维护者在一次性列表候选中报告“闪烁、无效”，随后明确游戏画面不闪烁，只有
状态面板闪烁，且按 F6 后画面也看不出变化。不得将其记录为游戏图像闪烁。
维护者要求继续排查，不回退候选，安装器独立打包。

前版同一配置/生命周期窗口内，载体评估增加 72，NR 成功与输出提交各增加 36，
未知队列旁路增加 36；实际队列不匹配和标记失败均为 0。NR 中间合成读回也有
非零差异。它们证明部分工作发生，尚不证明最终显示或肉眼有效。

## 修改

旧面板的首行已经按一秒统计活动，但下一段仍每帧读取最后旁路原因。因此正常
提交和同步条件未满足交替时，完整状态会反复改变并自相矛盾。

整段状态现在共享同一个一秒采样窗口。有 NR 和提交增量且存在队列等待时明确
显示间歇处理；持续无新增输出时显示等待/该窗口原因。F6 关闭与零强度直接
显示原生输出。配置代际和处理生命周期变化使旧采样立即失效；绘制间隔超过
两秒也重置窗口，避免重新打开面板把很早以前的工作当近期活动。

窗口属于绘制线程，多个交换链不会因为抢不到共享锁而闪回“正在检查”。
读取配置/生命周期前后核对，不把跨代际数据用作当前状态。全部渲染安全准入、
队列退休合同和每帧 F8 记录保留，没有游戏名分支或模型/合成算法改动。

## 验证

生产活动头文件的 CPU 夹具重放两种相位的每帧运行/等待交替，并检查持续失败、
成功但未提交、仅延迟提交、配置切换、生命周期切换、重新打开、计数重置、
时钟回退及极值计数。它作为完整构建验收与打包的必需门禁。
源码/本地编译/WARP/真实 ReShade 菜单/实际游戏分别记录，不互相代替。

当前画面无效问题保持开放。下一步需要固定镜头的最终输出对照，区分中间合成
没有送达最终画面、间歇处理使效果减弱，以及模型本身的实际变化；不凭中间
计数直接宣布画面修复，也不通过降低安全准入门槛试错。
