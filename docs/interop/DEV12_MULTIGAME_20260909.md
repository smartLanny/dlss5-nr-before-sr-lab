## 异环 RR 深度适配（#99 / #101）

旧候选明确拒绝 RR 的 `DepthType=Linear`，因此原生 RR 能运行而 NR 准备始终退出。
本候选读取成功 Create 声明的深度类型，以及当前同一次 Evaluate 的 `ViewToClipMatrix`。
不使用一秒间隔的诊断矩阵缓存，不按游戏名猜比例，也不硬编码近裁面。

适配采用 NGX RR 的 ViewSpace 深度声明以及 RR Integration Guide 的行主序、左乘矩阵约定。
支持正向 view-Z 的标准透视投影：`clipZ / clipW = A + B / viewZ`，
其中 A、B 从当前矩阵取得。同一相机坐标系中的深度与投影使用相同单位；
无需猜测米或厘米。该声明是生产者必须满足的合同，不是 F8 矩阵本身证明了真实像素语义。
正向／反向、有限／无限远均支持；正交、负 Z、斜深度平面、不完整／非有限矩阵继续旁路。
矩阵按声明的行主序解释，不凭数值自动猜测或纠正转置布局。

线性 RR 输入没有可直接继承的硬件深度方向。私有输出的方向从投影推导，
同时匹配 NR Create flags 和 `DLSSNR.DepthInverted`，避免原 flags 未置反向位时误拒绝。
转换后的方向保持与私有硬件深度一致，不套用线性输入的旧方向或开发者强制方向。
仅接受单层、单 mip、单采样的 R16_FLOAT / R32_FLOAT 可读纹理，检查实际设备和格式能力。
只处理当前深度子区域，私有 R32 输出从原点绑定。无效深度或非有限投影样本映射到远平面。

原生 RR 的参数、深度纹理和返回值不被替换；原生调用仍恰好一次。
转换在原生成功后、NR 前执行，沿原有完整命令状态恢复、generation、队列与 fence 机制。
输入强引用、私有深度及描述符都属于对应 NR slot；只有退役 slot 才能重绑或调整尺寸。
深度平面计入单 slot 64 MiB / 总计 256 MiB 的附加资源预算，动态分辨率替换计算新旧共存峰值。
深度投影系数、方向或映射变更触发 NR 历史重置。无法准入／分配／证明生命周期时保留原生 RR。

F8 增加转换录制／拒绝计数；录制不等于 GPU 完成或真实画面正确。
维护者须用新版本实际开启 RR、检查 F6 与读档／RR 开关，并提供 F8。
旧 dev10 的 44 次深度准备拒绝是本次输入证据，不能冒充 dev12 验收。
异环人脸 #162 按维护者要求继续暂停。

## 街霸 6 原生登记（#65）

接续维护者提供的已过期独立草稿，原草稿保留。
成功的原生 Create 直接登记对象；Create 只证明身份，仍要求真实 Reset 和完整状态才准入 NR。
小型 COM private-data 通知跟随真实原生对象销毁退役记录，避免强引用环。
ReShade 包装对象先销毁时只解绑对应 owner；过期 owner 回调不能删除新 owner 的记录。
销毁、GUID 撤销、迟到的 ReShade init、owner 先于 Create receipt、失败 Reset 都有回归。
RE9 原有状态恢复仍保留。未将鬼武者及所有 Capcom 问题认定为同一根因。

## 通用后置回退（#190）

遵循维护者直接要求：新装默认 NR→SR，有效个人设置保留。
在前置 NR 尚未调用、尚未录制 GPU 命令的四个颜色准入边界，允许本次 Evaluate 尝试 SR→NR。
后置必须独立通过输出、曝光、引导输入、生命周期和命令状态验证；原生 SR 成功后才执行 NR。
总开关关闭、零强度、命令状态未知、其他 NR owner、失败 Create／生命周期隔离等仍沿原旁路。
用户 Mode 和 INI 不被改写；前置输入恢复可用后自然回到原顺序。
UI / F8 分别显示保存请求、实际处理顺序、回退尝试与录制，提示提供 F8。
统计及画质策略使用实际顺序，避免每帧在请求 Mode2 与实际 Mode1 间清空计数。

这完成 #190 的有界 Evaluate 前置→后置兼容分项。通用 Present NR provider、
菜单／加载／FG 场景的完整 Present↔Evaluate 切换尚未接入，#190 保持开放。
