# Corefix.3：区分采样、后置存储与最终显示

本批接续维护者的 Corefix.2 实机失败反馈。死亡搁浅在正常采样时仍无持续可见效果且偶尔闪烁，暂停后不闪但仍无效果；绝区零确认加载后仍无效果。两项游戏画面问题均保持开放。完整报告分析见 [Corefix.2 复测证据](COREFIX2_RETEST_20260910.md)。

## 三种采样状态

反馈页保留正常和暂停采样，增加“仅切换输出状态”。第三种状态沿用原自动采样时点，只执行该段额外的输出 UAV 屏障和状态切换，不执行诊断 clear、采样 shader、复制或读回；NR 处理继续。它有独立阶段身份和录制计数，不产生恢复存储证明，不写入 INI，不重置模型历史。旧阶段已提交读回仍按其原始身份退休。

生产路径 WARP 对照核对三种状态的输出及实际 API 调用差异，覆盖 R10 和 FP16、半分辨率和全分辨率处理、恒等和变化输出，并保留错误目标负对照。这是软件 D3D12 与构造输入验证，不代表 NVIDIA 模型或游戏最终显示通过。

维护者应在固定 SR→NR、同视角同场景下依次比较正常、暂停、仅切换、恢复正常，每段约 30 秒并保存 F8，分别记录闪烁和增强是否持续可见。仅切换也闪可支持继续检查这组屏障；只有正常采样闪则继续检查其余诊断命令与调度，不能直接归因为某一个 shader。自动转视角的片段不作为严格同画面因果对照。

## 输出去向与格式证据

新增观察保存有界的描述符创建、复制、覆盖和生命周期记录，区分原生调用结束与 Execute 入口时的槽位修订。显式原生 Output UAV clear 只有在 CPU 和 GPU 视图配对且当前绑定堆、资源和槽位身份一致时才形成观察事实。观察到的类型与准入所用类型分开，不把缓存或历史类型直接授予 NR 准入。

后置窗口补充 RTV 绑定、清除目标和范围，以及同一次 Execute 数组中的位置。未知目标保持未知，已知其他目标独立计数；多个矩形的包围框不宣称为实际清除并集。CPU 命令录制与 Execute 返回不等于 GPU 已执行，更不等于最终画面已经消费 Output。

绝区零当前缺的是 typeless Output 的唯一原生视图解释，NR 尚未执行。它不会因为强制后置或新观察器已加载而自动视为可用。死亡搁浅当前有采样帧 Output 变化，但后续最终消费仍未证实；新的 RTV 和提交位置证据用于缩小这一缺口。

## 自动兼容路线

真实 RR 保持专用 RR→NR 路线。普通 SR 的后置尝试、准入、录制、提交、存储验证和兼容锁分别报告。只有明确前置语义拒绝，加上同一设备、Feature、配置、资源生命周期及解释范围内连续关联的后置执行、提交和实际存储证明，才可锁定后置。

锁定仅省去已经证实不可行的前置准备，后置仍逐次通过完整安全检查。范围变化、生命周期结束或实际失败撤销旧证明，不修改用户保存的路线偏好。顶部给出原因和 F8 提示；执行及存储已验证时仍明确最终画面待确认。

## F8 数字与验收边界

修正真实 F8 中部分长十进制计时数字被误识别为地址的问题。只保留严格 timing schema 内的合法计时和计数字段；路径、凭据、对象地址、未知字段及原始日志继续使用原过滤规则。验证覆盖实际文字收集、落盘数值一致性和原汇总器，而非仅检查内存中的原始数字。

交付必须绑定最终冻结源码、全组装验证、双语二进制及实际菜单检查。分支组件测试不替代最终构建。性能、输入响应、真实 NVIDIA 和两个游戏的最终显示仍需各自独立证据；本批不据加载、NR 次数、提交或 WARP 通过关闭游戏缺陷，也不自动合入主分支或发布稳定版。
