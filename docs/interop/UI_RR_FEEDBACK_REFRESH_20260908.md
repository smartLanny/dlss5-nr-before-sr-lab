以及独立 F8 Capture 的嵌套窗口问题；修复、合并两 tab、默认倍率 1.0 和独立
`0.4.6-hotfix.1` 的 40 项验证见[发布后补正](FEEDBACK_UI_FOLLOWUP_20260908.md)。
原 fixture 的宏环境未覆盖该 Release 缺陷，不能把旧 UI 绘制结果作为主面板
入口存在的证据；原热键和后端一直保留，维护者 06:57 的新 TXT 已实证生成。

维护者在实际 2077 场景反馈了 RR 切换后 NR 停效，以及面板、F8 和 F7 的操作问题。
本批基于已验证候选的合并演练继续，保留 #149/#150/#151/#155/#156/#157/#160，

## 用户可见变更

- 主要分组直接展开；滑块和标签同一行，NR 工作比例连续 50–100%。前置保存
  独立 NR 工作比例，后置保存 Npost/O；都不代表改变游戏实际渲染分辨率。
- 游戏真实渲染比例归实验 tab；既有控制仅修改下一次引擎 optimal-settings 查询，
  支持观察 D3D11/D3D12，不能强制引擎立即重分配渲染资源。缓存回调或 RR 防护
  可使请求无效；本次 TXT 未提供该查询的足够证据，不能指定 2077 的具体原因。
  请求、查询建议与实际观察尺寸分开显示，RR 下暂停实验请求，仍可恢复游戏控制。
- RR 后置自动选择，旧 RRPostEnabled=0 不再是第二个开关。F6 总开关、资源合同、
  生命周期和失败回退继续有效。RR 保护期间显示后置并禁用前置选择；普通 SR 的
  原模式偏好保留，不通过永久写 Mode 来实现自动切换。
- 缩短顶部状态与可见说明；详细解释移至悬浮提示，仅开发者选项折叠。
  诊断 tab 保留观察值，去除重复反馈与旧阶段采集按钮。
- F8 一次生成一个有上限的 TXT，文件成功保存后自动复制 Unicode 文件路径。
  不再提供报告摘要、全文复制、重复路径复制及快捷键滑块。复制在 Present 回调
  交接，关闭 overlay 也能进行；剪贴板占用时最多跨帧重试 1.5 秒，不阻塞等待。
  成功、待复制和失败状态分开，失败不复用上一份报告。
- F7 当前状态为三个 512×512 原像素 ROI 加独立概览。分享矩阵依次采原生参考、
  NR→SR 50/75/100%、SR→NR 50/75/100%，每组两个 512 ROI 和独立截图。
  矩阵保持强度等画质参数不变，只改变模式和工作分辨率；RR 保护时跳过前置组。
  设置只在内存临时改变，正常结束、取消、超时和失败均走原有恢复流程。
  Current 保留用户模式偏好，同时按实际 RR 后置路径采样；中途路径变化标部分失败。

各组是顺序采集，需保持同场景和镜头，并非同一游戏帧。阶段平面来自同一次
合成 dispatch，独立截图属于后续 Present；不能声称获得了同帧原生最终 SR。
保留现有 64 MiB 单文件复制与 512 MiB 总归档限制。F8 TXT 不含这些图像。

### 发布版本必须保留的反馈入口

所有后续中英文 Release 构建都必须保留同一个 `reshade_present` 热键入口：F8
生成单个有上限的 TXT，并在成功写入后自动复制该 TXT 路径；F7 生成当前设置的
图像补充包，反馈页同时保留 Current 与七组 ShareMatrix 操作。按键使用物理边沿
与短按低位兜底，按住不能重复触发，松开后才能再次触发。采集和剪贴板状态由
Present 持续推进，不能依赖设置页或 overlay 正在显示。入口可以在主设置页内调整
位置，但不能因清理诊断页、删除重复按钮、Release/NDEBUG 或中英文条件编译而删除。
主设置页不得依赖构建脚本未定义的 `NR_HAS_F8_SEQUENCE` 等宏来显示这些入口；测试
夹具也不得通过额外定义该宏掩盖实际 Release 中的空白反馈页。

`validate-feedback-hotkeys.py` 必须编译从生产 `OnReShadePresent` 提取的 F8/F7
分发块，并与核心单 TXT、剪贴板及 F7 控制器门禁一起通过后，才可称为保留该合同。

## 颜色、算法及兼容边界

“NR 跟随”即色彩跟随参数：0 偏向保留游戏色相，1 请求有界 NR 色彩；它不是
总强度或 NR 分辨率。已有 HDR/曝光及超过 1 倍时的颜色预算保护继续保留。
本批没有声称加入 0.5 的新放大算法，也没有新游戏画面调优验收。

#15/#124 的后续实验可比较较低 Npost 工作尺寸、重建修改量再与原生 RR 输出
合成，参考独立 0.5 研究；测量 GPU 时间、显存、延迟、边缘、拖影及 HDR，
原生 RR 只执行一次。实验仍待方案与实测，不混入本批生产算法。

DX11 仍限 x64 原生/模组 DLSS carrier 路径。#153 游戏崩溃未定因；#155 是名称
识别，#157 是 source=off 私有设备启动保护。Manager hotfix.3 已独立发布，
#161 已合入 Manager，按明确 API 部署并在切回 DX11 时清理精确 ReShade
文件名禁用项。ReShade 预加载排除优先解决无关 carrier 部署；按实际 DX11
延迟激活及复杂 device/NGX/shared-resource 生命周期重做仍需单独决策。

## 新增证据后的 0.4.6 修复

第二份 2077 TXT 为 49,938 字节，SHA256
`d1ee2f5c5912015fd6fc18d76336c2b2196ec58f7f5fdb412132b19615da2af8`。
仍匹配 a2 中文 DLL，F6 开启；本次当前进程日志明确记录普通 SR 被一个存活 RR
句柄连续旁路到第 600、1200 次，NR 停在 2424。这次证据已定位直接阻断点，
不再把第一份报告的缺证结论当成最新状态。

修复把生命周期库存与当前执行分开：缓存 RR 句柄仍追踪、正常 Release 时仍退役，
但只在真正 RR Create 或 owner=2 事务期间阻止普通 SR 修改。识别到的最外层
Feature1 调用可恢复原请求，首次恢复重置 NR 历史；Feature13 继续实际 RR 后置。
没有按超时猜测或伪造 Release。若 RR 与 owner=1 的修改中 SR 真正并发，使用
原有 abort/quarantine；嵌套调用仍只 native forwarding 一次。UI、F7 和实验
渲染请求按最近实际载体区分当前路线，不以缓存句柄永久禁用前置。

维护者另提供异环七张前/后置、50/100% 及皮肤结构对照图，TXT SHA256
`18ef41a7c99cc7083e2df4d91d07bd46035a7054a8e2589d32828033a4b059c3`。
图像证明局部脸部变暗，具体设置与拍摄时刻不同，不能把全局稀疏均值当脸部定量。
原始图片与日志保持本地。

- `DetailDecisionV2` 原先向邻域均值插值会借用更强或反向的残差，低分辨率下
  可扩大当前像素暗化。现在稳定化仅能削弱当前像素自己的修改，不能扩大或反向。
- 后置 `LightingLock` 以前被常量与 UI 排除；现使用同域模型网格的亮度引导
  估计，只削弱宽范围亮度漂移。替换旧 full-grid 九点直接 Load，避免缩小 NR
  工作面时按错误网格采样。0 保持原路径，1 保留平场原始亮度；旧二进制标志
  继续兼容，正标量优先，0.2 不会被旧标志强制成 1。
- 后置仅放开原始光照保护，细节稳定/边缘保护仍是前置范围。颜色/HDR 准入
  不变，NR 模型参数与默认值不改，没有新增人脸识别或引入整套 0.5 算法。

上述修改已有实际生产代码的 CPU/Windows gate 与生产 HLSL WARP 正负对照。
它们证明对应控制流、数学边界及资源网格行为；不保证所有模型导致的肤色变化
消失。新 0.4.6 的 RR 热切及同场景人脸视觉验收仍需真实游戏确认。

品牌标题为“装机宅DLSS 5”，交流群显示二群 392308850。Core 版本 beta0.4.6、
PE 0.4.6.0，配套 carrier 代码与 045 文件名保持兼容。首份 F8 自动轮询已删除。
