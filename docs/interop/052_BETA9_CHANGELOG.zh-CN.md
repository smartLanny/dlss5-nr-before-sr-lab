# 0.5.2 Beta 9：RR、内存驻留与报告修复

相对 Beta 8 的统一修复候选，保留相对 0.5 D21 的既有功能与实验。普通均衡恢复仍是建议，不覆盖用户已保存选项。

- 新建 NR 前遇到严重可提交内存不足时保留原生 SR/RR 画面，并明确记录延后原因，避免在已知极低余量下继续进入厂商创建。1 GiB 保护线不能保证解决所有 OOM。
- 修复首层 RR 深度转换的绑定生命周期，包括关闭区域处理的路径，保留安全旁路。
- 优先复用已完成的匹配纹理；持久化降低层数或改变处理位置后，安全释放旧 NR 链再建立当前配置。普通 F6 和九组临时切换继续保留原规则，不强行释放在途资源。
- 增加有身份校验、大小上限和失败回退的插件计算管线缓存，减少重复冷创建工作；不缓存游戏历史或 NR 模型。
- 九组报告按实际游戏原生入口区分 SR、RR、混合和未知，修正 SR 被误标 RR；不把调用入口当作采用或 GPU 完成。

新游戏反馈已取得普通 NR/私有 SR 每组 600 个局部 GPU 样本；三个时域组仍未采用。自动兼容 Present 的当前帧来源证明仍未满足，未放宽保护。静态截图与部分 GPU 时间不能证明全面降噪、无拖尾或整帧新增成本 ≤3%。

保留现有独立实验选项，图像算法关闭时不创建其资源或提交处理。此前四点空间方案细线门槛失败，仍不进入产品；后置 RR 原生 MV、私有 Feature13 及私有 SR/外部历史叠加继续不准入。

双语构建、硬件与部署身份见配套验收回执。系统之前提交量增长的来源及所有界面闪烁尚未全部查明。保留旧包、用户设置及运行库；不改变分页文件，不启动游戏，不发布在线 OTA，不改 Manager 默认版本。
