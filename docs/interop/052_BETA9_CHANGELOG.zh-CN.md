# 0.5.2 Beta 9：NR 创建前内存压力保护

相对 Beta 8 的定向修复。异环开启原生 RR 后，后置 4K NR 创建在仅约 75 MiB 可提交余量时抛出 std::bad_alloc。RR 自身已经创建成功，系统在切换前也已出现低提交额度事件。

- 在真正首次创建或重建 NR 前检查本进程可提交余量；有效读数低于 1 GiB 时跳过本次新建，保留原生 SR/RR 画面。
- 独立记录 commit-headroom-pressure 原因，沿用 300 帧及设置变更重试。不把保护触发记成已调用 NR 或厂商创建失败。
- 已有模型、关闭和重试冷却路径不增加内存查询，不增加 GPU 工作或等待。

1 GiB 是严重压力保护线，不是模型的内存需求预测，也不能保证消除所有分配失败。系统此前为何积累到接近提交上限仍未查明；本轮不修改分页文件、运行库或已保存设置。

保留 Beta 8 的观测链路修正和已有实验选项。普通均衡恢复仍是建议；私有 SR、现有时域作为独立对照。空间四点新方案未过细线门槛，仍未进入产品。后置 RR 原生 MV、私有 Feature13 与私有 SR/外部历史叠加继续不准入。

此包为本地维护者候选，具体检查以配套回执为准。受控检查不能替代异环实机复验，游戏画质和整帧新增成本 ≤3% 未获证明。Beta 8 及原始失败证据保留。
