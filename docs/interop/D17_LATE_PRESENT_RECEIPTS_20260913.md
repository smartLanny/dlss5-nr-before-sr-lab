# D17: submitted native guides for compatibility processing

This candidate starts at D16 `3c13f69119ddb0a0c1246f0348eb15c8aac64f76` on an isolated 0.5 branch. It implements the owner's explicit change of Present admission policy. It does not claim an exact port of an unverified RenoDX binary or OptiScaler version.

## Runtime contract

Before/After keep their reconstruction and resource admission. Present uses the current swapchain image with an owned depth/motion snapshot from a recent successful native SR/DLAA/RR call. The matching producer recording must actually reach Execute and signal its own completion fence. A different Present queue on the same device uses that exact fence via a GPU queue Wait. Output extent, freshness, single consumption, device, source claims and known generated/FG-processed exclusions remain checked. Full intermediate image lineage is diagnostic; unknown labels, full-screen postprocessing and queue inequality alone do not reject a valid receipt.

Missing guides do not create dummy temporals or color-only NR. Such frames keep the game image. This deliberately supersedes the D16 no-native-DLSS color-only activation behavior. Source jitter is metadata; finished-picture jitter is not inferred from the original render input. Controls continue to use the current output's SDR/scRGB/PQ interpretation and existing Core composition.

Guide storage stays owned through the exact producer and consumer fences. An NR attempt consumes a receipt before private work, including on subsequent failure. No arbitrary latest-SR label is attached to the backbuffer. The relaxed placement contract does not prove every postprocessing transform or physical real/generated display cadence; those remain game acceptance limits.

Automatic Present fallback may retry the user's requested Before/After entry after sustained non-adoption and exact in-flight drain. A healthy fallback is retained, explicit Present does not move, and settings are not rewritten. Initial thresholds are 32 native opportunities since last adoption, or 256 during bootstrap; these are bounded retry-policy defaults, not performance measurements. Successful inline adoption clears that entry's accumulated route failures.

## Verification and handoff

The accompanying validation record must identify the frozen source, both Core artifact hashes, exact test commands and pass/fail results. CPU policy tests, WARP transport, controlled ReShade/NVIDIA processing and real game checks are separate evidence classes. The controlled native-seam host does not claim to run a real native SR feature or to verify a game.

Concentrated game acceptance remains: NTE After-to-Present on one fixed scene; Onimusha cold start through gameplay and sustained Before/After; Cyberpunk Present including enabled native FG where available; F6 off/on, resize and duplicate Present coverage. Owner logs and captures remain private. Do not close compatibility issues solely from compilation or artificial host results.

Multilayer resolution/quality investigation is deferred; this candidate does not change that algorithm. No release, main merge, Manager update or game deployment is implied by creating this source candidate.
