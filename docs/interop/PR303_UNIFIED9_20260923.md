## Changes beyond original #303

### 1. Build-time temporal bytecode, not only a runtime compile cache

Unified8/9's nine auxiliary entries do not include the temporal stabilizer.
They remain unchanged. Three temporal variants now have a separate, explicit
build-time artifact path: CopyCandidate, legacy CS, and opt-in FP16 in-place CS.
The helper calls FXC with exactly the old embedded source, source label,
RECORDING/INPLACE_FP16 macros, cs_5_0 and strictness flags. Generated bytecode is
not checked in; no algorithm, NR working size or model precision is changed.

The production module is compiled with NR_TEMPORAL_PRECOMPILED and requires the
generated header; missing/corrupt inputs stop the build. It does not silently
fall back to D3DCompile in the game. The standalone probe retains dynamic
compilation as an independent reference. The source generator copies the new
helper and artifact builder as explicit inputs, and the whole-Core test linker
checks artifact/header provenance in addition to source/object hashes.

The existing weak exact-device PSO sharing remains. In production,
DLSS5_TEMPORAL_PIPELINE_CACHE=0 disables PSO sharing, not build-time bytecode.
In standalone dynamic-reference builds it still disables both runtime caches.
Root-signature serialization/PSO and NGX model creation are NOT eliminated.

### 2. Remove repeated format-capability queries from the frame path

A context-owned three-entry successful-query cache replaces the repeated
candidate CheckFeatureSupport call. A successful hardware capability result is
reused only within that retained-device context. A failed query is not cached;
unsupported format bits remain unsupported. Resource identity, extent, active
rectangle, motion, typed-load/store and lifecycle admission checks remain.
10,000 mocked calls to the actual generic cache issued one successful query;
this establishes query reuse, NOT a measured frame-time saving.

### 3. Fix lazy-snapshot accounting before local integration

The original #303 can omit its FP16 snapshot then allocate it on a later
non-in-place input. Core had counted only construction bytes but retirement
subtracted the larger current byte count. A CPU test compiling the actual Core
Record wrapper reproduced the missing-growth failure before the fix. This
could undercount live/peak bytes and wrap the unsigned counter on release.
It is a new candidate-accounting defect, NOT a proven explanation of earlier
player VRAM exhaustion or #298's model-creation peak.

Core now accounts retained growth after record on all outcomes, including
refusal and quarantine, before any return. Repeated frames do not double-count.
Allocation refusal has its own status 20, a visible bilingual current-NR-retained
notice and an instruction to save/upload F8; it is no longer mislabeled as a
candidate/source mismatch. No unsafe early release or automatic workload
reduction is introduced.

### 4. Expand validation to the path that will actually ship

validate_memory_opt_gpu.py now compares four independent processes: dynamic
cache-off, dynamic cache-on, dynamic in-place, and precompiled in-place. It
requires real fast-path use, allocation counts and byte-identical native-motion
images (seven frames in each scope). Every GPU negative control rebuilds its
OWN mutated shader artifacts rather than accidentally reusing baseline CSOs.
These are pixel/correctness comparisons, not an E2E performance benchmark.

