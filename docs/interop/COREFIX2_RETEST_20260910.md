# Corefix.2 实机复测：采样相关闪烁与最终画面无效

维护者报告死亡搁浅固定 SR→NR 时：正常采样通常看不出效果并偶尔闪烁，暂停采样后不闪但仍无效果；暂停期间人物自动转动视角。绝区零经米哈游启动器与 HoYoShade 加载后也无效果。这里保留游戏失败结论，不用加载、调用、录制或提交成功替代画面验收。

## 报告身份

三条补充路径实际重复指向死亡搁浅第一份报告。已从维护者本机反馈目录取得相邻的第二份死亡搁浅报告，并以内部进程名、会话、采样模式确认；同一绝区零会话有四份报告，最新一份为主，之前三份用于区分尚未进入 SR、前置回退尝试与手动后置。原文和逐文件 SHA-256 保留本地，未写入源码仓库。

报告载入的中文 Core 哈希为 `1e4c597c1610ddc9004129e381c8dce1a514474d1b1fe562353a75e5bf091ad5`，冻结源 `92c5eacc03eb21b80d4390e8f8f7b154a7ef7f33`，与 Corefix.2 交付相符。

正常段末样本帧 7209 的 2040 个读取点中有 1939 个变化，但只有 1085 个点有唯一存储期望，完整比较仍为 unknown。它证明采样帧的实际 Output 中观察到变化，不能证明普通帧或最终显示。暂停段引用的样本帧 8289 仍是 normal／1，`probePhaseCurrent=0`；该旧样本不能证明 paused／2 的当前存储。

两段都持续执行 NR 与提交，暂停后的无效果不是“暂停同时停了 NR”。用户观察到的闪烁变化与采样有关联，但自动转视角使其不能作为严格同画面 A/B 因果证明。下一判别是在原有采样时点仅保留 Output 状态切换，不执行诊断 clear／shader／readback，分别观察闪烁和持续可见增强。

采样配对窗口仍记录到 NR 后同列表的 RTV bind、draw、RT-clear，其中目标未知；后续其他列表也有 Output 状态变化。当前没有 RTV 描述符目标、清除区域及提交数组索引的闭环证据，不能断言是某次 clear 覆盖了 NR。实际 NGX 输出为 1920×1080、呈现为 3840×2160，二者之间的后续消费仍待观察，不能把资源写入直接提升为最终画面修复。

## 绝区零

这是 NR 执行前的资源解释拒绝。当前 D3D12 普通 Feature 1，RR 句柄和 RR 调用均为 0。最新报告请求／实际模式均为后置，SR 载体 2580→2625，NR 与提交均为 0；运行库状态为 not-attempted，不能据此推断缺少运行库文件。

Output 是格式 27（RGBA8 typeless）、3840×2160、flags=0x5。28／29／30／31／32 候选的硬件查询均成功，但当前原生 Output UAV 类型没有被观察到，`selectedTyped=0`、`observedCall=0`，语义仍不唯一。前两份有实际 SR 的报告已发生每窗口 45 次前置→后置尝试，后置录制仍为 0；最新手动后置也被相同条件拒绝。因此再次强制后置不能解决当前缺口。

现有类型观察器只记录同线程、原生 Evaluate 内新建的视图，不覆盖之前创建的缓存描述符、复制、复用和完整的实际绑定／使用。下一版先补有界描述符来源与显式 native 使用证据，以及 RTV 目标／范围；新增观察本身不放宽格式准入。未确认的 typeless 资源不猜成 UNORM。

## 路线与报告说明

RR 的自动后置及前置按钮保护已经存在。普通 SR 现有的是逐帧后置尝试，旧提示可在 POST 准入前被置位，不能据此说后置已运行。新的兼容锁须同时具有明确前置失败和同配置、Feature、设备、资源解释范围内的真实后置执行／提交／存储证明，仍逐帧检查 POST 安全条件；变更或失败即撤销，不修改保存的模式偏好，且明确画面待确认。

真实 F8 的 12–16 位十进制 QPC 数字被通用地址脱敏规则替换为 `[address]`，导致整段时长不能按当前脚本可靠重建。修正仅保留精确 timing schema 的合法数字，保留原始日志、路径、凭据与非白名单地址过滤；须在实际生成的 TXT 文件中核对数值并运行汇总器。此次旧报告不据此给出性能改善结论。
