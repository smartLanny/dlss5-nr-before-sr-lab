# RC10 对照后的优化实施方案：干净、低分辨率保细节、低开销、清楚的 UI

日期：2026-09-25。当前方案基线是 #306 / `fe245aed083c23cf246c42a0edbb9877f56e53de`，实际已交付 Inbox1 构建 `4a07bce2`。研究起点 #307 / `939b1e246968dec4512cc41a82d06c2bcc6b6324`。本文是实施建议与验收要求，不是已经接入的新算法或新 DLL。

## 1. 先说清 PR 改了什么

#307 最初只增加研究报告、标量证据索引、真实颜色函数的 CPU 探针，并更新 CURRENT_STATUS，共4个文件。没有修改src、默认参数、着色器、模型、运行库加载、UI或游戏文件；合并它本身不会提高FPS、减少噪点或改变菜单。

#306是另一个PR：已交付的0.5.1 Inbox1运行时修复针对同来源旧模型仍待安全退休时的替代创建准入，防止未完成退休与新分配重叠；不能将它当作本次RC10清晰度/噪点研究已经实现。

本次在同一个#307补充此方案，保留研究和运行时交付的区别，不再为一份规划另开新PR。

## 2. 新反馈如何进入决策

维护者新增报告：对方脸部及身体黑色噪点更少；UI明确、舒适且好看；帧率更高；实际前置使用中低NR分辨率仍有优秀观感；50系专用DLL已由测试者验证约5%帧率收益。缺点为部分人感到NR细节/色彩较弱，以及叠层可能拖影。

这些反馈直接作为产品优化目标，不用“只是降低画质”否定它们。5%记录为维护者转述的测试结果；本轮没有读取其原始帧时、精确受测DLL哈希与画面对照，因而不扩展成所有游戏/显卡或本家已验证的5%。此前“文件名不能证明速度”仅限制静态分析结论，不是否定新提供的实测。

路线边界：固定RC10二进制有Before upscaling控制，帮助同时注明RR仍在重建后运行。因此能确认存在前置设置与RR后置声明，不能证明整个插件只有pre-SR；维护者所测前置效果仍是优先对齐对象。不要据此删除本家的后置、RR或其他兼容路线。

必须区分证据层级：原始插件/字节码和本家源码读取得到结构证据；近黑探针是合成CPU数学证据；用户五项优势/两项缺点是使用反馈；下面算法、参数范围与优先级是建议，尚无新运行时或新游戏验收。

## 3. 总体方向

产品主路径应追求：单层在较低工作分辨率下保留原图细节、稳定采用模型有效编辑，再交给原生SR，而不是靠更多层、高强度锐化或更重滤波补偿彼此副作用。多层仍保留为高级增强，不用删功能伪装优化。

此目标不意味着现有版本默认多层：当前新配置/恢复默认已经是单层；要解决的是低比例的实用性、模型细节与后处理控制边界，以及切换/长期运行的实际成本。

将质量拆成四项验收：原图已有细节是否保住、NR新增结构/颜色是否仍有价值、运动稳定性、达到这个观感的总成本。锐利不等于新增真实结构；平滑也不等于正确去噪。不得为了追平清晰度把可靠的NR颜色一并压没。

## 4. 第一批图像算法：低网格重建、黑斑、彩噪在同一链路处理

### 4.1 黑斑不是一个颜色问题

上轮探针保持亮度基本不变而颜色方向变化，因此只证明近黑候选的彩噪敏感区，不能把脸/衣服上的黑点都归为这个函数。新诊断必须区分：

- 进入模型前已经有噪声或曝光/下采样在跳动：查输入准备与曝光尺度。
- 原始NR输出存在孤立暗化：查模型结构设置及低置信度亮度编辑，不用全图提亮遮盖。
- 原始输出正常，最终恢复后出现色斑/跨边缘暗斑：查恢复、范围/人脸约束及比例边界。
- 单层干净、叠层或外部防闪后出现拖影：查新增层残差及历史选择，不再加一遍全图平滑。

复用既有集中验收/F7的配对输入、NR原始输出和最终结果；捕获必须来自同一次调用/同一层/同一曝光与有效区域，捕获与性能计时分段。不能拿旧进程F8或累计success替代当前最终像素。

### 4.2 低亮度候选的色彩连续置信度

落点：`src/nr_colour_restore.hlsli`，以及源准备/边缘合同。现有函数按source自身的准备比例恢复RGB，再将候选色彩归一到受保护目标亮度。近黑候选可能对绝对很小的色差敏感。

建议：对候选色彩可靠性建立连续权重。低可靠性时逐渐回到原图在目标亮度下的色彩方向；可信时保持现有颜色采用、零通道新增颜色和HDR域。亮度与颜色置信度分开，不用ColorStrength=0或全局降饱和作为修复。

不能只检查候选亮度低就清空色彩：暗色服装、合法强暗化、暗红/暗蓝光也是真实内容。联合考虑有效输入范围、邻域一致性和已有噪声/量化尺度，阈值必须定义在相同曝光/准备域并连续过渡；数值范围来自反例与像素统计，而非抄另一二进制常数。

验收：N=P、0采用、色彩0、可靠新增颜色、正常强暗化、零通道、HDR高光、负值合同、非有限输入与平滑渐变；保留目标亮度且不能突然褪色/跳色。

### 4.3 孤立暗化的保守亮度稳定

对纯黑斑，应限制不可靠的局部“暗化编辑”，而非磨平源图。复用同表面边缘引导与局部编辑分布；仅在编辑孤立、源图缺乏对应结构且邻域有效时降低暗化权重。原图有对应黑色纹理、阴影边界或跨物体时不借邻居亮度。

优先采用向零编辑衰减、有界且保持符号的形式，不从强暗邻域制造本像素原本没有的更强暗化；不要统一削减所有负残差。高置信度模型生成的阴影/结构应保留，避免把用户所说“细节/色彩偏弱”的缺点复制过来。

这不是确定的语义真值判定。肤色阈值无法解决衣物、非人类皮肤和背景同色区域；独立人脸检测#302失效仍要独立修。当前原生mask可作额外置信度，不作为全局黑斑算法的唯一开关。

### 4.4 原图引导的修改量重建

建议建立一个小接口的重建模块，输入同域原图、配对低网格输入/输出或编辑场、实际有效区域和强度/可靠性；内部集中处理坐标、配对、边缘权重、有限值、1:1与零编辑退路，避免前后置各写一套近似数学。

前置路径的示意，C_R为原生SR输入，P_L/N_L为更小的模型网格：

```text
C_R -> 有合同的准备/下采样 -> P_L -> NR -> N_L
                    配对编辑 E_L
C_R + 原图引导重建(E_L) -> 增强后的同尺寸SR输入 -> 原生SR -> 输出
```

保留原生SR输入已有高频，只上采样编辑，不把低分NR整图替代高分原图。原生SR只执行一次。后置则在原生SR/RR输出的对应尺度恢复，不把RR有噪输入强制送进前置NR。

当前本家四点配对双线性与后续边缘保护已存在；RC10固定shader的4x4引导编辑上采样是新增参考，不等于需要复制它的log-RGB域。先独立实现高质量参考，再比较4tap与16tap的质量/带宽；预计算低网格配对编辑，避免每个全分辨率邻域重新读取和解码相同输入。能融入现有最终合成时避免新增全分辨率写回，但不牺牲可验证性或在途所有权。

保留当前RGB/normalized-opponent/亮度编辑的明确定义，不能任意移动log、exp、准备逆尺度或颜色预算的次序。原图guide与低网格guide必须在同一亮度/曝光域，不能把HDR直接截成SDR来让权重“稳定”。

预期与限制：原图引导可减少跨边缘扩散，但NR网格没看到的细小语义结构不能凭插值保证还原；高频源纹理也可能错误地刻进光影修改。测试细线、头发、衣物纹理、同亮度不同物体、透明/粒子、高光和半像素运动，不能只验一张静止脸。

公开机制参考：Microsoft Research的Joint Bilateral Upsampling说明可用原高分辨率图引导低分辨率解重建；它不是本次RC10实现和效果的源码证明。
https://www.microsoft.com/en-us/research/publication/joint-bilateral-upsampling/

### 4.5 分辨率尺度与合成预算

用实际WxH定义成本，不把两个插件“50%”自动视为同一工作量。UI同时显示游戏SR输入、NR实际工作尺寸和最终输出；pre-SR的百分比参考与post的参考明确标注。

示例（不是当前插件固定预设）：输出3840x2160、原生SR输入2560x1440、NR为SR输入边长50%，实际NR是1280x720，不是1920x1080。对相同参考边长，50%为25%像素，但NR时间不会保证严格变成25%，准备/SR/合成等也不会同比下降。

开发扫描优先75%、67%、50%，低于这些比例是否产品可用取决于实际尺寸、运动与SR倍率；不要第一步追求极低NR百分比。只有测得新增恢复成本小于省下的NR成本且质量达标，才判为有效优化。不能用静态shader指令数或理论像素比例替代GPU时间。

## 5. 稳定输入与叠层拖影：修正确性，再减历史拖滞

### 5.1 输入归一化与最终防闪不要相互追逐

保留游戏实际曝光/PreExposure的语义，对缺少可靠曝光的分支才研究同帧估计；不能凭显示器HDR开关或贴图浮点格式猜颜色域。稳定的是本插件额外准备尺度，不是冻结游戏原本的眼睛适应。

已有HDR AMDOF和历史单位换算不用重新接一遍。分别测“原准备+无外部防闪”“稳定准备+无外部防闪”“稳定准备+既有防闪”，查看是否已有足够稳定性；不要默认把两种慢滤波同时开到高强度。按秒而非固定每帧变化率控制额外归一化，切镜/合同变化仍快速重新建立，不靠延迟重置伪装平滑。

### 5.2 多层外部时域只做一次必要处理

独立NR层本来各有模型历史，再给每层附加长历史滤波，可能放大拖尾风险。先核对每层真实Reset、视图/源帧、运动单位、jitter/采样相位和同帧曝光，不能把分辨率降低后的MV简单再乘一个比例。反向运动、错帧和无效遮挡用更大history权重无法修好。

后续实验优先只处理额外层带来的增量。令Z1、Zk为同一源调用、同一完整域/尺寸下第一层与第k层可见合成结果：

```text
D_extra = Zk - Z1
Z_out = Z1 + 稳定后的 D_extra
```

这不是把不同尺寸、不同准备域的原始N1/Nk直接相减。也不需要为了得到Z1重新跑一次NR，应该复用已存在的同帧prefix；若prefix存储/寿命不成立，明确显示此模式不可用或采用已有整链模式，不能假报“只处理后续层”。

静止可信区域较长历史；运动边缘、遮挡/显露、透明粒子、曝光突变与运动不一致处降低历史权重，采用当前可靠编辑或退至Z1。限制历史编辑到当前同表面合理范围，平滑过渡且不把邻域阴影涂到前景。

原生MV是有语义的几何运动输入，不等于完美的NR合成细节运动；光流也是带成本的估计，不自动优于原生MV。当前0.5.1已接入的HDR路线主要用AMDOF；前置原生MV、前置later-scope等仍不能因“理论可用”直接打开。光流尽量取未增强的同域源图，避免把模型随机纹理当运动；现有深度/一致性信息有效时用于拒绝。

重要限制：若第一层NR本身已经产生拖影，Zk-Z1方案无法抹掉Z1里的残留；它先阻止附加层继续恶化，并为进一步降低低置信度额外编辑提供退路。不能宣称外部防闪能完全逆转不透明模型的内部历史。

AMD的公开FSR2文档把MV、jitter及反应性/透明遮罩分开处理，尤其粒子/透明对象可能没有可靠MV或深度。这里只借鉴时域可靠性原则，不声称本家能获得所有游戏的reactive mask，也不照搬FSR接口到Feature18。
https://gpuopen.com/manuals/fidelityfx_sdk/techniques/super-resolution-temporal/

## 6. 性能：不再只追CPU微计数，也不否定已有修复

建立三个独立目标：相同实际路线/像素/层数下更少开销；相同主观质量下允许更低NR预算；正常和退休驻留不抖动、不迫近显存预算。用相同场景的基础渲染FPS、帧时间尾部及相应GPU链路计时衡量，不把FG显示帧直接作NR速度。

按真实消费者审计准备、NR各层、编辑恢复、防闪、复制/转换、CPU关键线程和提交间隙。GPU占用低可来自CPU供给、同步、限帧、错误拒绝或内存压力，不能只看百分比选择一种根因。分段计时的重叠与嵌套要明确，不能相加各段P95。

后继工作集优化重点是：同一源/视图的输出地址轮换可复用scratch；真正视图或创建合同变化必须独立。可分离“模型历史身份”和“这一次输出目标绑定”，但复用仍受设备、格式/有效区域、完整键和fence控制；不得用新的宽松缓存复活退役对象。

关闭时按消费者需求省去昂贵统计、可选采样/读回和无用遍历；必要寿命/状态观察不能直接全部撤掉，否则重新开启时无法正确恢复。已合入的预编译、#303缓存、Perf12退休与#306准入继续保留，不当作新功能再实现。

不首选再造一个绕过保护的“轻量Core”，否则兼容与验收会分叉。可以在一个Core内保留有证据的快路径与原安全路径，实际可用性和退路由状态显示。任何持续安全旁路必须提示F8并反馈，不计作性能成绩。

## 7. 50系优化DLL：独立的高优先级收益

按维护者新增反馈，约5%帧率收益视为测试者已报告的实测，优先验证能否直接在本家获得。没有必要先重写或逆向厂商算法才允许做兼容验证；也不能因.text/大资源相同就否认数据/选择逻辑改变可能影响执行。

第一步核对受测的准确SHA256、GPU、驱动、实际NR尺寸、层数、原/优化DLL和FG状态。目录中候选优化DLL为`24f2d48e...`，必须确认与报告的受测文件一致，不能只对文件名。

在同一50系机器、同一Core/config下分别启动原DLL和优化DLL，先看导出、Create/Evaluate/Reset、HDR和多层兼容；确认成功采用率、NR计时和颜色/细节没有退步。可用时此收益可能与本家重建优化并存，但应分别报告，不能预先承诺普遍+5%或与其他百分比直接相加。

若50系受控验证通过，建议运行库选择/安装层增加该已验证版本的身份说明、架构限制和一键回退；明确保存的手动选择不被覆盖。切换需要完整退出重启，不在活跃Feature18和在途GPU工作期间热卸载。40系及更早架构保留已验证运行库，不为一个5%结果改所有卡默认。

不把未知许可的DLL提交源码仓库；签名/来源/哈希、接口兼容和性能是分别检查的项目。仅记录验证过的身份与兼容结论，包部署策略另走既有安装器流程。

## 8. UI要并行做，而不是等所有算法研究结束

保留维护者指定顺序：顶部先版本和真实运行状态，其后总开关、AI色彩范围等常用项。用统一的普通操作路径，不再把第一层额外调节、光影微调、细节增强藏在多个意义相近的页。

建议常用页分两列：左边效果，右边性能；窄窗口自动单列。高级层参数、兼容修正、诊断单独折叠/页签，保留开发者完整视图。状态可示例为“当前 RR→NR，1层，实际1536×864，GPU时间已测/未测”；不能把请求Before仍显示成已实际前置，也不能从success总数假报实时工作。

效果区保留少数具有唯一含义的控制：整体采用程度、AI颜色、明暗偏好、结果细节、噪点稳定。算法实验初期仍在高级区，验证后再由质量预设管理。模型结构/皮肤参数另列并标注需要重建；后期结果参数明确即时生效，不把“细节”同时用于两种处理。

视觉上采用统一间距、标签/数值对齐、稳定滑条宽度、低对比背景和少量状态强调；复用ReShade字体资源，考虑中文与DPI，不新增花哨图标或大段彩色告警占满主页面。未亲眼看到对方UI截图，不把这些建议写成已经像素级模仿它的美术。

交互合同：逐项/分组恢复；按住/临时选择默认与我的配置对照；预览不写INI，退出/取消恢复完整状态；调整模型参数合并为一次显式应用或松手提交，避免拖动每一像素都重建。加载中同时显示当前实际值与待应用值，不假报即时生效。恢复某组不能偷偷改模型、DLL、路线或其他组。

“画质预设”和“性能预设”分开：自然/细节等只改变画质意图，质量/均衡等改变工作预算，且预览会展示具体改动。单层已是现有新默认，不再宣布“改成默认单层”是本次新增优化。

## 9. 当前可做的诊断调参，不冒充最终默认

| 目的 | 当前可做的一次受控对照 | 边界 |
|---|---|---|
| 分离叠层影响 | 同配置单层 vs 当前层数 | 只用于定位，不能把少一层的FPS称为同工作量优化 |
| 判断人物结构增强是否放大噪点 | native AutoMask保持，SkinStructure +0.4与0比较 | 0为候选诊断值，不保证身体全覆盖或降噪；不照搬负值，避免-1哨兵语义冲突 |
| 区分彩噪与亮度黑斑 | AI颜色0.5与0短暂比较，别同时改曝光/结构 | 0去彩噪但黑斑仍在则不是同一问题；0不是新推荐默认 |
| 判断低工作比例是否为主因 | 相同实际路线单层75/67/50%与原设置对照 | 当前尚无本方案引导重建，不能保证50%已优秀；显示实际WxH |
| 分离外部防闪的收益/拖尾 | 现有支持路径下off vs AMDOF，其他保持 | 看实际submitted/accepted而非复选框；不开新的未支持native MV/后续层范围 |

保留UI correction、已有模型和游戏设置，除非某一项正是本次受控变量；不要同时一键改变五项然后猜效果来自哪项。非重复同条件的玩家反馈先保留，不要求用户为每一条假设做完整矩阵。
