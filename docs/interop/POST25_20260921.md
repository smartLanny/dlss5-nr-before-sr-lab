# 后增强 25% 工作比例

本批将原生 SR/RR 后置及独立 Present 后增强的工作比例扩为 25–100%。
前置仍为 50–100%；游戏渲染比例没有改动。新建或缺省配置仍为 100%，
已保存的合法设置保留。一至五层共用一次工作尺寸，各层不再次缩小。

## 配置与界面

- 原生后置使用 `PostWorkPercent`。RR 和 FG 重定向的兼容路线继续使用这个字段。
  25–100 的整数有效；0 保持已有“关闭 NR、保留精度”的控制语义；其他值拒绝，
  保留上一有效值，不把 24% 当作 25%。采集期间仍由配置锁管理临时值与恢复。
- 独立 Present 使用 `CompatPostPercent`，缺省 100。合法的 25–100 不会再被
  `NormalizeConfig` 提升为 50。范围外的 INI 值沿用既有的端点归一化行为；
  界面提交则先验证所选路线范围，拒绝非有限值及越界输入。
- 前置仍使用 `WorkMode` / `CustomWorkScale` 的既有合同。滑条根据编辑目标采用
  50 或 25 的下限；实际运行的自动回退不改写正在编辑的字段。目标、配置或
  Post revision 改变时仍取消旧手势。
- 颜色优先提示修正为默认 0.7；恢复画质说明修正为保守颜色 1.0。
  本批没有改变颜色算法、保存值或实际默认值。

## 尺寸和输入合同

原生后置从重建输出 O 计算 N，再执行既有模型尺寸对齐。100% 保持原输出
尺寸；非 100% 可能因为对齐而有轻微差异，以实际模型尺寸为准。
Present 从最终来源尺寸一次计算工作尺寸，所有层继承该尺寸。

后置 `LoadPostArea` 和 Present 使用的 `FilterExactAreaV6` 均按实际覆盖面积
求和，没有固定 2×2 限制；25% 需要覆盖约 4×4 来源像素。原生后置保持原生
Depth 的 R 网格，并通过现有 Motion 重采样及位移单位转换绑定 N，不裁掉
高分辨率运动场。Present 保留已有来源证明和导引单位策略；降低工作比例不
给予缺失资源、未知运动相位或不完整生命周期任何额外准入。

## 本批验证和后续门禁

定向 CPU 检查已通过：后置/Present 尺寸及导引单位 8,653 项、实际配置/持久化/
采集 89 项、一至五层尺寸/历史 94 项，以及实际滑条拖动、释放、RR/FG 重定向、
低于下限拒绝与保存后重新显示。原有前置 Win32 INI 67 项通过。
面积滤波的独立有理数积分对照增加四分之一和奇数尺寸。

生产着色器 WARP 用例增加 25%，使用 128×96 → 32×24，以免小尺寸对齐
把 25% 变成 50% 后仍误报通过。保留原有像素、透明度、输出偏移、非零编辑、
SDR/HDR 和格式检查。该用例须在最终完整生成 Core 上执行，不能以 CPU 检查代替。

真实 Present NGX 入口增加 `validate-compat-present-ngx.py --case post25`，
覆盖一至五层 25%，检查归一化没有改写比例以及每层实际绑定/捕获尺寸。
此入口使用最终完整 Core、真实 NVIDIA 和 Feature18；构造颜色输入不等于
游戏、原生 SR/RR、原生 FG 或时域改善的验收。完整生成、WARP、NGX 及游戏
结果由本批最终交付记录分别登记，本说明不提前声称通过。
