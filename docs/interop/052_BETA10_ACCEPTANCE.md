# Beta 10：多层 NR 创建压力保护补全

本地 #313 的窄修复候选。最终源码、完整构建、硬件、包装与部署身份以交付记录为准；未完成的检查不算通过。Esc 进入动画中 NR 短暂消失仍未归因，不列入本候选修复承诺。不启动游戏、不推送、不合 main、不发布在线 OTA、不改 Manager 默认版本或用户保存设置。

## Beta 9 游戏反证

2026-09-29 03:41:28，异环 Beta 9 `86518955` 在一条独立后续层的 Feature18 Create 前仅剩 474,750,976 字节可提交余量，厂商返回 `0xBAD00002`（PlatformError，并非明确 OOM 码）。随后封存尚未提交的依赖闭包并进入进程级 `lifecycle-isolation`。03:44 F8 请求 config 19，但最后成功仍为历史 config 8；反复开关不能解除该安全隔离。

Beta 9 的 1 GiB 保护只覆盖主层前/后置创建，漏掉独立后续层。故障前两个合法原生父实例交替创建多层 NR，共同增加提交占用；不能因此把二者合并成一个身份、按帧龄释放、或认定已经找到全部增长来源。保护漏口已证实，厂商内部具体失败分配仍未知。

重启后的 PID 52316 有完整 SR 与 RR 九组，各 18 张截图，五个普通/私有 SR 组均为 180 个预热源帧和 600 个有效局部 GPU 样本；三组时域仍无有效采用和截图。原生路线标签正确，两次均恢复设置。这个单层窗口不能证明多层压力故障消失。

## 最小修复合同

- 主层与后续层共享可提交余量读取和同一 1 GiB 严重压力下限。后续层在自身生命周期登记、导引 GPU 操作和厂商 Create 前检查。
- 低余量返回非致命延后，保留前层已记录工作，不伪造厂商失败，不设置进程隔离，也不把尚未完整的多层链标成已采用。主层的有效结果继续使用。
- 后续层按父层源调用计数 300 帧或配置变化重试。已创建模型、关闭和冷却路径不增加该查询。操作系统读数无效沿用原有准入，不当成零余量。
- 真实不透明 Create/Evaluate 失败仍保留原隔离及生命周期规则；不清除未知状态、不强行释放在途资源。

另修正一个可由源码和合同回归证明的不必要模型重建：游戏原始颜色纹理在 R11G11B10_FLOAT 与 FP16 之间切换时，NR 实际的 proxy/neural 始终为 FP16，且同一 codec 模式未变。仅对这两种原始浮点格式允许保持模型存储合同；原始格式变化仍触发历史 Reset。其它颜色格式、深度/MV、模型尺寸/flags、owner、slot 格式适配、在途与退休保护保持原规则。这个修正不意味着可以沿用不匹配的 slot，也不能独立证明 Esc 已解决。

1 GiB 是严重压力保护线，不是模型内存预测，也不能保证避免所有内存分配失败。既有 #318 RR 绑定、#319 安全回收/缓存及 Beta 8 的真实计时修复继续保留。

## 验证与证据边界

## Esc 的未解决边界

维护者已明确：UI 浮现在游戏画面上、镜头焦点推进的进入动画中 NR 短暂消失，菜单完全展开后 NR 恢复。这与创建失败后的持续隔离分开处理。重启日志确有相同工作尺寸/flags 下导引存储合同变化、退休重建和暖机的记录，也有短暂命令状态拒绝；没有菜单时刻，不能把某个窗口直接标为 Esc 原因。除上述狭窄浮点存储修正，本包在既有合同变更日志补充深度/运动/颜色格式、运动绑定尺寸及转换选项的旧新值，不新增逐帧日志。下一次只需记下进入动画的时刻，在菜单完全展开恢复后立即按 F8，保留同进程日志；已有 SR/RR 九组不必为此重复录制。不得用解除来源/FG/fence 保护来让状态变成“开启”。

后续由维护者手测，见 [最短检查](052_BETA10_MANUAL_CHECKLIST.md)。普通均衡仍为建议；现有私有 SR/时域选项保留独立实验身份，失败四点候选不进入产品。
