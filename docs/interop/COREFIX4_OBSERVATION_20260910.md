# Corefix.4：原生层观察、独立阶段与 UI 回执

Corefix.3 的实机结论继续有效：死亡搁浅后置没有持续效果，正常／仅状态切换偶尔像 NR 增强短暂出现，暂停后不闪但仍无效果；近期状态跳动仍存在。绝区零因原生 Output 解释未取得，NR 仍为 0。五份反馈已核对为实际交付的 Corefix.3，原始材料保留在私有证据区。

## 共享机制修改

命令列表的代理与原生接口只在当前原生调用内关联：冷入口核对当前 token、附着的生命周期通知、实际设备及存活记录；录制 hook 仅读取有界值记录，不查询 COM。不同编号域分别核对，Reset、退休、记录代次变化和调用退出使关联失效。

描述符从 ReShade 初始化回调明确给出的原生设备层采集。代理的虚拟 CPU 地址保持原样转发，不推算其原生地址，不长期保存代理地址映射；一次复制／创建／清除只收集一次真实原生操作。没有活动观察窗口的清除直接执行原调用，避开命令记录锁。

原有同设备／同资源接口的 CreateView 观察保持。设备接口不同但共享准确生命周期时，可以恢复同一资源指针的真实 CreateView 证据；资源接口不同不会因此新增渲染准入。缓存描述符存在和显式 Clear 使用仍为独立观察，不直接升级为 typed 语义准入。route 生命周期登记不覆盖原生资源地址索引，退休按唯一描述符生命周期身份封口。

暂停／仅状态切换使用独立 CPU 只读票据。新窗口携带当前配置、Feature、设备、Output、子资源和 probe phase；历史读回保持原 frame／phase／trace。仍保留 8 个窗口，F8 最多展开一组 6 条原生和 12 条后续事件。新增只读票据不增加 GPU 命令。

UI 在原来的同一次观察及实际文案选择后记录重置原因、匿名线程身份、间隔、范围、计数与状态变化。F8 仅复制有界记录，不推进窗口。原有一秒统计窗、两秒中断规则、文字及设置保持。

组件开发验证包含真实生产完整翻译单元的合成 COM 复现、实际初始化回调与 hook 发布、原始 API 转发次数、描述符修订和资源／设备退休；它不创建实际 D3D 设备或加载 NGX。最终单项 CPU 91 条包含“不观察时不依赖记录锁”的受控线程检查，删除快速返回的反向对照被准确捕获。

UI 单项 92 条及反向对照通过。两组件合并中间源的完整 F8 七组各 1092 条通过，最大元数据 161729/163840 字节，末尾 96193/98304 字节，无需扩容。最终三组件同源整组也通过这些边界、12 组完整 F8 反向控制及实际原生描述符 WARP 检查。

本地 WARP、调用／提交、格式观察和最终游戏画面是不同证据。本候选没有新的实机视觉通过结论；#205、#2 及相关未完成判断继续开放。后续死亡搁浅只需固定后置、暂停采样、保持反馈页可见约 30 秒后取得一份新 F8；绝区零沿用原加载方式取得实际场景报告。
