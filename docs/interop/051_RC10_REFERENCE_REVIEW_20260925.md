## 1. 问题归属和不可牺牲的目标

本家优先问题是低NR工作分辨率输入下人物脸部/身体的黑色点状或块状噪声，
不等同于之前只改变色彩方向的近黑数学探针。叠层拖影是维护者转述的目标
插件反馈，本轮不把它重新归给本家、不据此给本家每层追加强时域。

保住可信NR色彩、合理的新阴影/明暗、有效新增结构和原图已有纹理，是验收
底线。减色、减弱整体增强或磨平细节可以是对照，不可暗中当成成功修复。

## 3. 必须纠正的三个控制含义

目标帮助函数 `fn_180062400` 区分：

| 控制 | 证据支持的职责 | 不可混同 |
|---|---|---|
| NRDisplayPedestal | 移除模型附加的暗部提亮，Auto/Always；帮助警示可能误压阴影噪声 | 不能再命名为NRTransferMode，也不能据此给本家添游戏硬编码 |
| NRTransferMode | Display编码下修改量如何回到HDR、是否考虑准备曲线增益 | 不是上述黑位移除 |
| NRNeuralFloorGuard | 极暗候选需要较大恢复增益时，降低不可靠色彩方向的采用 | 不等于整份明暗/颜色修改收缩 |

Shader #2虽有标量重建与等量RGB扣减，完整调度/表面/开关联仍待补，不能
直接断定它就是每个游戏最后执行的pedestal步骤。反过来，也不能认定本家
已有某个明暗限制就一定用了目标的同一错误算法。

## 4. 优先学习的两个机制，以及一个有代价的机制

### 4.1 极暗候选 AND 高恢复增益：连续色度可信度

Shader #19的特定归一化域分支有两种安全证据：候选不够暗，或恢复增益
不够大。二者取较大安全权重，只有两项都危险时才显著收缩候选颜色。
目标打印常量是六位小数的近似值，不是本轮从DXBC解出的原始浮点位，也不是
nits或PQ阈值；**不将其直接复制进本家HLSL、UI默认或HDR参数**。

私有材料孤立公式重算：候选峰值0.0001、恢复倍率1/2/4/8时色度权重约
1/1/0.5/0；候选峰值0.02时这些倍率下都为1。这是该局部公式的示例，不是
人脸降噪百分比或已验证模型输出分布。

该分支的回退端使用原图色彩方向，同时按模型这次修改后的目标亮度缩放。
不是恢复旧亮度。完整shader还有色域、色相、混合和存储误差，不能从局部
数学推到所有路径逐比特恒亮度。

本家实现目标：在自己的配对准备/曝光/色彩域内定义置信度，保持目标亮度
和可信色彩不变；正确处理黑源、零通道新增颜色、合法暗化、彩色光照和HDR。
不能仅因候选暗就清掉颜色，也不能宣称该色度机制能单独消除纯亮度黑斑。

### 4.2 4x4原图亮度引导的配对修改量重建

Shader #10手工读取邻域配对输入/候选，提取逐通道log修改，结合空间距离
和亮度差加权并归一，再恢复配对结果。它不是对最终整图强锐化。

联合权重不足会退回纯空间权重；同亮度不同物体不能保证分开。`T2.w`引导
的实际生产者和完整绑定仍需补证。0个sampler不代表无滤波：手工Load后
计算权重仍然是滤波。常量寄存器计数也不能误写成同数量的单个dword。

本家独立实现应保留现有编辑域和同帧配对，检查有效矩形/offset、半像素和
jitter、padding、分辨率边界、alpha、无效足迹与HDR尺度。4点/16点都做
预算对照，复用已有低网格数据和最终合成，不以额外全屏带宽换一个未测的
理论收益。1:1、N=P和零采用必须有准确的无修改路径。

### 4.3 低proxy时整份暗部编辑收缩：单独对照，不默认一起开

另一个Display分支对整份log编辑施加暗部权重，明暗和颜色都会变小。
这可能改善稳定性，也会减弱合法NR效果。它只是“有玩家觉得细节/颜色弱”的
可调查解释，不是没有画面对照就成立的根因。

至少分开A重建、B色度可信度、A+B联合。整体暗部编辑收缩若实现，必须是
额外明确标注效果代价的实验D，不在A+B默认中藏入。输入toe、输出pedestal
撤销也要独立，不混成一个无法归因的“更干净”预设。

## 5. 默认模型差异与参考代码的归属

目标 `fn_18007a770` 中配置读取前的初始化为强度1、tone/structure各1、
AutoMask关、skin=-1、UICorrection关，随后配置和每层覆盖仍可改写；
`fn_1800a76b0`能看到实际Set参数。键被写入或回读都不证明闭源模型消费。

本家已读Inbox1结构初始强度1.5、skin .4、AutoMask/UI true；最终创建
在AutoMask关时传skin=-1。二者是初始化/参数合同差异，不能当作测试者
实际值，更不能把-1称为免费降噪。先留存“好看那次”的有效模型参数，再
区分模型设置与合成A/B。不要直接改变所有用户保存值。

目标有同feature工作集复用分支，也有可选私有look历史和Reset/时间间隔
管理；不能套用另一项目README的“没有历史”。附带参照工程的固定32次
Evaluate后释放策略也不是目标已证实策略；不替换本家的精确GPU寿命证明。

## 6. 数学反例与可运行检查

新 `scripts/probe-edit-reconstruction-contracts.py` 是独立编写的Python
示例，使用明确可配置、非目标精确常量的阈值，只证明建议合同可被表达。
**它不复用或执行生产HLSL，不模拟完整目标shader，不证明游戏噪点会减少。**

`tests/test_edit_reconstruction_contracts.py` 的20项测试在Windows通过：
连续性、范围与单调性（2000组随机参数）、只有暗但低增益不衰减、可信颜色
保留、不同置信度下保持新目标亮度、零/常量编辑、同亮度边界限制、无支持
退回空间、非法输入，以及命令行拒绝覆盖已有回执。

负向对照说明：

1. 仅按“暗”保护会错误拒绝低恢复增益的可信颜色；回退旧亮度会违反新目标。
2. 修改量已有黑点不能定位根因，模型原始输出的黑点也会原样进入差值。
3. 单独参照公式中的“中间加floor比值限幅”不等于最终颜色端已限幅。中性灰
   source=proxy=.0001、model=.01、floor=1/512、MaxRatio=2时，理想代数
   颜色端约34.35294倍，而亮度端2倍。这不是RC10或本家缺陷判定，不是完整
   GPU色相/色域证明；移植前应检查真正最终目标，不只检查中间量。

```text
python -m unittest discover -s tests -p test_edit_reconstruction_contracts.py -v
python scripts/probe-edit-reconstruction-contracts.py --output <new-directory>/math.json
```

另已重跑原私有材料探针，源算术锚点核对及2000组局部权重检查通过；原件
和私有探针输出不引入公共仓库，不能与上面的独立示例混报为生产回归。
