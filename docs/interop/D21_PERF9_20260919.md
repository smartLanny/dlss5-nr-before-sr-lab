## Remaining measured mechanisms

Perf8's old full source-state Rebuild and comparison-sort hotspots are no longer
the leading paths. The shared remaining paths include SnapshotPostBoundaryList
(about 11.40 / 6.75 CPU ms/s in BEFORE/AFTER ON), ProcessCommandListReset
(7.88 / 5.51), and source OnExecute (3.63 / 4.76).

Exact instructions in the matched binary show SnapshotPostBoundaryList's 2048-
record fallback scan. The single hint per address-hash bucket can repeatedly
miss when several lists collide. Actual collision rates cannot be reconstructed
from sampled instruction pointers alone, so no game scan-count reduction is
claimed in advance.

Reset and OnExecute also inline Lineage::AnyPending. The former batch layout
places each 40-byte identity/status header beside 48 event payloads, producing a
6952-byte stride. Thus status queries touch widely spaced metadata, and Reset
clears an entire event array even though the new count is zero. These are
related query/reset/submission costs; this candidate repairs them together.

## Runtime changes and preserved contracts

`src/nr_source_frame.hpp` separates the existing 64 compact batch headers from
their existing 64 x 48 event payloads. The event-slot index is derived from the
current internal Batch pointer, never saved across a call or into another
object. Counts still gate every event read. Arrays are initialized on object
creation; Reset/ForgetList clear the header and pending bit without rewriting
inactive event bytes. Reusing a slot writes its new event prefix before exposing
that count. Copy construction/assignment copies both arrays and the summary.

A 64-bit pending summary is maintained only by successful Add, Submit and batch
clear transitions. Its invariant exactly matches `recording && !submitted &&
count`. Overflow remains pending until submit/reset; failed native submit still
clears the pending bit when the old implementation marks the batch submitted.
Invalid inputs, replay, full tables, tail coalescing, source retirement and
queue/content/taint metadata keep their existing behavior. AnyPending becomes a
constant-time bit test. TracksList/BatchFor/Reset retain their original matching
and first-free order, now over compact headers rather than event-sized strides.

`src/nr_post_boundary_native.inl` replaces one direct-mapped hint with four ways
per each of the same 16 hash sets. Recent-way lookup keeps the single-hot-list
case small. More colliders fall back to the original full scan; only cache hints
are evicted, never real records or state. The original registry shared lock,
epoch, first matching record, fresh ready/reset/device fields, and current
call-bounded alias scope checks remain. Negative hints cannot retain an alias
or survive an epoch change. Additional TLS value storage is about 1.25 KiB per
thread; no heap allocation or COM reference is added.

No shader/model/NR-layer/extent/subrect/format/HDR/exposure/jitter/depth/MV,
SR/RR/FG route, native command order, queue/fence lifetime or restore policy was
changed. Workload is not reduced by dropping hooks, skipping state updates or
silently switching route. Cold initialization is not moved to arbitrary workers
or hidden through OFF-state prewarming. The independent Perf8R/colour branches
are not modified or automatically merged.

## Executed focused gates

`validate-perf9-observation.py` compiles complete frozen Perf8/current Lineage
and extracts each actual snapshot function. Counters and one sizeof accessor
exist only in generated fixture copies, never in the Core.

- Full 64-batch / 48-event overflow, invalid/failed/replayed submission, bit 63,
  12000 mixed transitions, all public label fields, stale-prefix isolation and
  object copies agree with Perf8. AnyPending is compared after every transition.
- 1000 no-pending queries: 64000 batch predicates -> 0, with the compact header
  6952 -> 40 bytes. The event payload has not been deleted or truncated.
- 15000 full reset/set/pending/submit/membership CPU-double transactions:
  approximately 3.24-3.35 ms -> 0.92 ms; semantic checksums agree. Not a FPS claim.
- Four deliberately colliding native list addresses over 4000 hot calls:
  8170000 full-scan predicates -> 0 after warmup. One-list timing is about equal;
  eight colliders exceed the four-way capacity and can still pay the original
  scan plus a small classification cost. Not every access pattern is faster.
- 2000 native-address generations; alias rebind/expiry; fresh readiness/Reset;
  20000 concurrent snapshots across 1998 epoch changes under real Windows SRW.
- Existing source-frame 399 checks, inherited mixed Barrier/identity/alias/SRW
  cases and 36 production compatibility-route checks plus negative controls pass.

Full bilingual Core compilation and whole-Core/WARP results are reported only
when their actual candidate receipts complete. Hosted CI is a separate status;
NVIDIA/game FPS validation is not inferred from CPU doubles or WARP.

## Capture hygiene and next acceptance

`record-perf9-comparison.ps1` checks available storage and active compiler names
before invoking the owner's existing recorder. It does not kill a compiler,
disable security software, modify an INI, install a Core, or press F6. A read-only
PreflightOnly mode is available. Five tests exercise busy/low-space rejection,
read-only status and clean argument forwarding using a dummy recorder, not a
real capture. On the real host the read-only probe correctly reports an active
build and does not start recording.

Retain actual NR work extent and UI correction, not only a folder/route label.
New Perf9 route captures can validate reduced observation costs; clean same-
workload Perf8 is required before claiming an isolated whole-frame FPS benefit.
No D13/original-D21/Reno matrix is required. Record OFF -> ON -> OFF, then F8;
verify growing NR success during ON, and separate initial long frames from steady
windows. Persistent bypass, missing effect, flicker or crash requires rollback
and F8/Core log/hash feedback; bypass-induced FPS is not a pass. #277/#272/#273
remain open until real-world acceptance.
