## Implementation

Runtime changes are limited to `nr_descriptor_provenance.h` and F8 counters in
`nr_feedback_capture.inl`.

Each fixed CPU/GPU slot pool has a direct-mapped discovery cache, at most 2048
relative slot numbers (8 KiB per normal pool). A hit rechecks BOTH heap ID and
slot index. No Receipt, resource validity, epoch, pending flag or incarnation is
cached. Existing Read/Finish/Current validation still executes. Cache conflicts
and misses use the original full-key chain. Allocation publishes the slot number;
erasure removes its cache reference before reuse. Nothing changes hash buckets,
LRU ordering, heap membership, capacity, eviction policy, or in-flight protection.
Zero heap keys are explicitly rejected. There is no TLS/raw borrowed pointer or
new ownership lifetime. All operations use the existing registry mutex.

Cumulative hits, misses and chain steps are recorded per pool. Chain steps are
accumulated locally, with a single update after each miss; there are no per-node
clocks, atomics or log calls. F8 exposes `descriptor.slotQueries`. These are Find
statistics only, not all descriptor work, GPU time or proof of input validity.

NormalizeUnknownRanges reuses its mandatory validity scan to check order, then
skips sort only for already ordered inputs. It retains exact byte-address union,
duplicate handling, types, invalid-input behavior and gaps. Unordered input still
uses the same sorting comparator and union pass. Original D3D12 arrays are never
modified.

## Feedback loop and tests

`validate-perf6-lookup.py` reads frozen Perf5 headers from Git. Test-only
instrumented copies count chain steps/comparator calls; the actual addon uses
only the explicitly documented small cumulative counters.

- Repeated 256-key write/pending-read/Finish/read workload: old chain checks
  60480, new 0 after warmup. Full key and validity checks are NOT eliminated.
- Already sorted 2048-range workload: old comparator calls 4102, new 2047.
- Exact public receipt differential, forced capacity eviction, protected pending
  slot, same-address heap replacement, stale Finish, global invalidation,
  resource replacement and device retirement checks pass.
- 150 sorted/reversed/random/invalid-range sequences produce the same normalized
  arrays as Perf5. Existing descriptor CPU suite: 2225 checks pass.
- Timing also covers one hot key and a 4096-key working set beyond cache size;
  do not assume a universal gain. Counts are not a game FPS multiplier.
- Default registry is 16597576 bytes on the local Windows compiler, still under
  the unchanged 16 MiB cap. No increases to descriptor pool capacities.

Inherited Lock2/Perf3/Perf4/Perf5, threaded differential, complete generated Core
and WARP gates remain in `build-perf6-candidate.ps1`. `build-perf5-candidate.ps1`
is only an alias so new binaries cannot be mislabeled Perf5. The generator pins
the changed production source. Build receipts, not this pre-build checklist, are
the authoritative final compile/WARP state.

## Owner acceptance

Keep INI, model DLLs, shaders, NR working extent/layer count, colour, RR/SR/FG,
ReShade/bridge and companion unchanged. Test one actual Perf6 Core only. Record
same-scene OFF -> ON -> OFF and F8 after the stable windows; preserve the first
initialization frames separately. The specific next checks are cache-hit/miss
rate and residual chain steps, plus plugin CPU and frame times. A large working
set can fall back to the old path; this is allowed and must remain correct.

No first-enable prewarm or NGX background creation is introduced. The captured
~1.55-second cold-start frame is still an independent unresolved issue. A bypass,
missing NR effect, flicker or crash requires rollback and an F8/Core log/hash bug
report, not a performance pass. No game deployment or stable release is implied.
